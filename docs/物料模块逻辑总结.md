# 物料管理模块 - 逻辑总结

> 日期：2026-08-16
> 本模块 = `src/views/material/*`，含 物料基本维护 / 库存管理 / 盘存记录 / 出入库管理（申请+审批+执行+台账）/ 采购入库 / 领料还料申请 / 物料申请。
> 后端走 `/shouhuiApi` 下的 `/stock/*`（物料库存）与 `/project/*`（采购订单/供应商/项目分期）。

---

## 一、菜单结构（正式环境由后端菜单表配置）

| 菜单 | 路径 | 页面 |
| --- | --- | --- |
| 物料基本维护 | `/material/list` | `material/goods/index` |
| 库存管理 | `/material/stock` | `material/stock/index` |
| 盘存记录 | `/material/stocktake` | `material/stocktake/index` |
| 出入库管理 | `/material/record` | `material/record/index`（申请 + 台账） |
| 采购入库 | `/material/purchase` | `material/purchase/index` |
| 物料申请(隐藏) | `/material/apply` | `material/apply/MaterialApply` |
| 领料申请(隐藏) | `/material/pick` | `material/pick/index`（由出入库管理按钮跳入） |
| 还料申请(隐藏) | `/material/return` | `material/return/index`（由出入库管理按钮跳入） |

> 领料/还料页顶部有页面级面包屑「出入库管理 → 领料/还料申请」，点「出入库管理」返回 `/material/record`。

---

## 二、物料基本维护（goods）

- 物料 CRUD + **单位子表**：第一行即基准单位（换算系数固定 1，不可移动/删除），副单位填换算系数；**单位下拉统一走数据字典 `inv_unit`**（`material.util::loadUnitOptions`），同单位禁止重复选择。
- **物料编码后端生成**：新增时隐藏，创建后只读展示（编号显示规则）。
- 新增/编辑：`unitPrice`（基准单价）、`stockQty`（初始库存）**未填默认 0，始终上送**；编辑不传 `version`。
- 行操作含手动出入库（`IOModal` → `/stock/ioRecord/manualIn|manualOut`）。
- 导入/导出走 `JImportModal`（下载模板在弹窗内）。

## 三、库存管理（stock）

- 库存总览（按基准单位显示库存数量/金额）。
- 行操作：**出入库**（手动入库/出库，生成台账）、**盘存**（`POST /stock/ioRecord/takeStock`，按实际盘点数量留痕）。

## 四、盘存记录（stocktake）

- 固定按 `sourceType=stocktake` 过滤 `/stock/ioRecord/list`。
- 差异 = 盘点后 − 盘点前（正=盘盈绿 / 负=盘亏红），物料编码/名称按 `materialId` 富化。

## 五、出入库管理（record）

两条 tab：**出入库申请** + **台账**。

### 5.1 申请创建
- 三种入口：领料申请（`/material/pick`）、还料申请（`/material/return`）、物料申请（`/material/apply`）。
- 选择「分期项目」下拉（服务端模糊搜索 `/project/period/searchByName`，打开即预载第 1 页 10 条），自动带出**主项目名称**（`projectName`）。
- 还料页：**还料人 = 当前登录用户**（自动填充，不手填），提交带 `returnUser`。
- 明细 itemList 提交：`materialId/materialName/materialCategory/brand/model/unitName/unitQty` 等。
- 明细「库存」列展示：接口 `currentStockQty + baseUnitName`（如 `1个`）。

### 5.2 审批（整单审批）
- **只有「待审批(PENDING)」显示「审批」按钮**。
- 审批弹窗：整张申请单所有物料逐行显示，**每行默认「通过」**，驳回手动选「驳回」并**填行级审批备注**（驳回必填）；无「暂不处理」。
- 提交 = **整单所有物料审批结果一起提交**：通过项 `approveApply(AGREE, items)`、驳回项 `rejectApply(REJECT, items)`；**任一条驳回 → 整单状态变「已驳回」**。
- 明细审批状态标签走字典 **`stock_item_status`**。

### 5.3 执行出入库
- 「已通过(APPROVED)」→ 出库(领料) / 入库(还料/采购)；「部分通过(PARTIAL_APPROVED)」可执行已通过明细。
- 执行弹窗/批量出入库调 `POST /stock/apply/execute`（`{applyId, itemIds, items:[{itemId, executeQty}]}`）；**执行人由后端从登录 token 取**，明细记录 `executeUserId/executeUserName`。
- 明细「执行人」列展示执行出入库的经办人（后端 `executeUserName`）。

### 5.4 申请人动作
- **待审批/已撤回/已驳回 → 可「修改」** 跳回申请页（`?applyId=`）改数量后重新提交。
- 待审批可「撤回」（→已撤回）；**已驳回不可删除**；删除仅限 待审批/已撤回。

### 5.5 台账
- 出入库记录（`/stock/ioRecord/list`），行操作「详情」弹窗展示该条记录涉及的全部物料详情（物料主表 + 单位换算 + 本次变动）。
- 台账来源/类型标签走字典 `stock_io_source_type` / `stock_io_type`。

## 六、采购入库（purchase）— 状态机

| 状态 | 行操作 | 目标 |
| --- | --- | --- |
| 1 待采购 | 修改 / **确认采购** / 关闭 | →2 |
| 2 采购中 | **采购完成** / 关闭 | →3 |
| 3 已到货 | **开始入库** / 关闭 | →4 |
| 4 入库中 | **入库**（逐物料实际入库数量）/ **入库完成** | 入库后仍 4；入库完成 →5 |
| 5 已完成 | — | |
| 0 关闭 | — | |

- 状态切换走 **`POST /project/purchaseOrder/status`（`{orderId, status}`）**，不再用 editOrder 改状态。
- **入库**：`StockInModal` 逐物料填 `inboundQty`，调 **`POST /project/purchaseOrder/inbound`**（`{orderId, items:[{itemId, inboundQty}]}`），库存/台账按实际入库数量计算；入库完成由后端校验。
- **关闭**：仅 1/2/3 可关闭（开始入库前），`changeStatus({orderId, status:'0', closeReason})`。
- 状态标签走字典 `purchase_order_status`（1待采购/2采购中/3已到货/4入库中/5已完成/0关闭）。

## 七、跨页面的下拉预加载

- 弹窗/抽屉下拉数据（供应商/项目分期等）在**主页面渲染时预载第 1 页 10 条**并缓存（`material.options.ts` 的 `ensureSupplierOptions`/`ensurePeriodRecords`），打开弹窗直接读缓存，输入模糊查询走服务端。
- 字典类下拉（单位/状态/类别/品牌）统一走 `material.util::loadDictMap`（模块级缓存），改后台字典重新登录生效。

## 八、关键约定（全局）

1. **所有状态/枚举/下拉标签走后端 `sys_dict` 数据字典**，前端不写死（mock 字典已全部移除）。
2. **编号显示规则**：新增时隐藏编号（后端生成），创建后只读展示。
3. **操作人身份**：`getCurrentUser()` 取当前用户；审批提交带 `approvalUserId`；列表/详情按 id 解析姓名（后端姓名优先）。
4. **审批人展示**：直接用接口 `approvalUserName` 字段。
5. **执行人** = 执行出入库的经办人（`executeUserName`）。
6. **单位**统一走 `inv_unit` 字典；**主项目名称** = 项目主项目名（`projectName`），分期名仅作下拉 label。
7. **全局禁用浏览器自动填充**（`autocomplete="off"`，`src/utils/autocompleteOff.ts`）。
