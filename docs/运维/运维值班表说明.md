## 页面与操作流程

- 页面入口：运维管理 → 运维值班表，路由 `/operation/list`，组件 `operation/duty-roster/index`。
- 先选择值班月份及参与人员，默认通过“输入排班逻辑”检查后生成；也保留三人轮值和自定义空表入口。人员来自正式人员选项接口，限定 `operations_staff` 运维人员角色。
- “三人轮值”生成初稿：张三、李四 / 夜班张三 / 休息王五 → 李四、王五 / 夜班李四 / 休息张三 → 王五、张三 / 夜班王五 / 休息李四。仅此生成方式需要3人；查询上月月末夜班后衔接轮值。
- “自定义排班”生成当月空表，可选择其他人数并逐日填写。
- 生成规则仅用于初稿，人工调整是最终依据。白班可以从2人改成1人或清空；夜班、休息均可单选或清空。不强制保存时符合默认人数、白夜班搭配或次日休息规则。
- 休息人员可独立调整；修改白班或夜班不会自动覆盖人工选择的休息人员。更改生成配置也不会删改已有明细，只有明确点击并确认“重新生成排班表”才会覆盖。
- 联系电话直接读取该行夜班人员快照，不再提供独立联系人选择框。无夜班时显示“—”，未维护电话时显示提示。
- 默认每页10天，可切换20/31天；切换月份回第一页，保存提交整张月表，不只提交当前页。
- 点击“保存并锁定”后等待服务器确认，成功才进入只读展示；失败保留编辑内容。可维护用户点击“修改排班”可再次编辑。
- 切换月份、刷新有未保存修改时，确认放弃后再读取；重新生成会确认覆盖。版本过期时提示刷新，不自动覆盖其他用户修改。

## 文字输入规则与检查

默认流程：输入一段文字 → 点击“检查规则” → 查看系统理解及逐日可行性 → 点击生成 → 人工调整 → 保存并锁定。

可输入示例：

```text
平时白班2人，夜班1人；
节假日1人值24小时；
夜班后休息一天；周末按平时排班。
```

也支持“平时白2个夜1个”“节假日白班1人，不排夜班”、中文人数和换行。夜班默认沿用当前业务规则：参加当天白班，次日休息；解析结果会明确展示这一约束。可显式写“夜班后不强制休息”。夜班目前为单人班次，文字规则支持0或1人。

检查分两层：先完整识别文字，再以参与人员和当月每个日期模拟排班，结合上月最后一天的夜班检查休息衔接。若某天所需人数超过可排人数，指出日期、要求、休息人员和可用人数；不输出部分排班。检查本身不覆盖现有表格。

“节假日一天一个人”未交代是否值夜班，会提示改写为“1人值24小时”或“白班1人，不排夜班”。人数冲突、不支持的约束（如固定某个人不能上某天、连续休息多天）会明确报出，不能忽略后显示通过。本功能是本地可解释文字规则解析，并非通用AI理解；指定人员等安排可在生成表格后人工修改。

文字、参与人员或月份变动后，旧检查失效，需重新检查；生成使用已检查的完整快照，不会因后续修改反向改变检查结果。保存时仍只提交实际每日明细，不重新检查文字规则或强制补足人数。原始规则文字仅用于当前前端生成，不新增或虚构后端规则字段，刷新后不保证保留。

法定节假日及调休来自项目既有 `lunar-javascript` 数据；2026年已按[国务院办公厅2026年节假日安排通知（政府网站转载）](https://www.beijing.gov.cn/cs/gncs/zcwj/202603/t20260327_4568275.html)核对。普通周末默认按平日，可写“周末按节假日排班”；法定调休上班日优先按平日。没有内置日历数据的年份遇到差异化节假日规则时阻止生成并提示，不会将未知假日默认为平日。未声明节假日差异时沿用平日人数。

休息列为单人字段，生成时记录上一夜班后需休息的人员；其他未安排班次的人员不会凭空变成后端多休息人字段。

## 正式接口与数据边界

以2026-10-17刷新后的 Apifox 项目8679942为准：

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/operation/dutyRoster/personOptions` | GET | 返回 `canManage`、`persons`（userId/name/phone） |
| `/operation/dutyRoster/queryByMonth` | GET | 按 `month=yyyy-MM` 查询共享月表及版本 |
| `/operation/dutyRoster/save` | POST | 原样提交人工调整后的轮值快照和每日明细 |
| `/operation/dutyRoster/exportXls` | GET | 按月份导出服务器已保存的Excel |

保存请求仅发送契约字段：`month`、`version`、`rotationUsers`、`days`。每日明细为 `date`、`dayUsers`、`nightUser`、`restUser`，人员对象为 `userId/name/phone`；不提交生成规则、界面锁定标记或展示用weekday。保存整月替换，携带最近查询版本，成功后接收新版本。数据层不会重新排班、补足人员或推导休息人员。

姓名、电话为逐日快照，未编辑行保留查询原值。已离开角色的历史人员可回显，不作为新选项。返回明细可为部分日期、重复日期或空班，前端保留记录顺序，不在查询时自动补齐日期或重建人员。

`canManage` 决定维护入口，管理员/运维主管可维护，运维人员只读及导出。只读账号不发起生成、编辑或保存操作，后端仍负责鉴权。业务成功按响应 `success=true` 判断，HTTP200不等于业务成功。

本轮已从浏览器本地保存切换为正式服务器接口，不再回退旧localStorage月表。原浏览器中的旧值班数据不自动提交或覆盖服务器，未删除旧存储内容。

## 导出

只允许导出当前已保存锁定的月份。编辑期间禁用导出，避免误导出旧版本。使用正式导出接口，JSON业务错误不会作为Excel文件下载；服务端按快照导出日期、星期、白班、夜班、休息、夜班联系人及电话。

### 休息人员自动计算

休息人员不再提供选择框。按本月参与人员集合，减去当天白班与夜班人员的并集，去重后按本月参与顺序展示，支持多人或无人休息。调整人员或班次即时更新；保存的 Mock 明细包含完整 `restUsers`，导出也用同一计算方法。旧 `restUser` 仅兼容旧初稿，不作为页面及导出的休息名单依据。此规则替代此前独立编辑休息人员的说明，不改变白夜班人工调整自由度。

### 多人夜班（替代 0/1 人限制）

文字规则不再限定夜班为 0 或 1 人；白夜班人数均支持非负整数（解析上限100）。生成默认优先兼任，按实际参与人数及所有前一日夜班人员次日休息判断可行性，支持纯夜班。明确要求所有夜班人员参加白班时，白班人数应足够容纳夜班人员。页面夜班改为多选，电话显示全体夜班人员电话，休息名单排除所有当日夜班人员。Mock保存和导出以 nightUsers 数组为准，旧 nightUser 读入兼容；跨月文字生成读取上月末全体夜班人员。此变更为前端 Mock，不能推定正式后端已经支持多人字段。

### 自定义规则填写引导

默认选择三人轮值。只有选择“自定义排班逻辑”且处于编辑状态时，才显示文字输入、模板和检查结果。提供常规轮值、节假日单人值班、多人夜班模板，点击填入后可修改，必须重新检查才能生成。结果分为“我理解的安排”和“能否排出来”，即使人数不足也展示已理解的规则及具体失败原因。“手动排班 · 生成空表”不显示文字区域，休息人员自动计算。

### 自然说法与24小时后休息

支持用户原文“工作日 和周末 早班2人 晚班1人；节假日例如国庆 早班1人 晚班1人；一个人 如果当天上了24小时 那转天休息”，包含空格、换行及“第二天”说法。国庆作为节假日例子，适用于全部法定节假日；不是只指定国庆。24小时定义为同一天兼任白班和夜班，仅这部分人员次日强制休息，与所有夜班人员次日休息分开处理；跨月也读取上月末白夜班交集。未识别约束仍报错，不宣称支持任意自然语言。
