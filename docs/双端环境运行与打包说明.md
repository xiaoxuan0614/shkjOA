# 双端环境运行与打包说明

更新时间：2026-10-09 08:35（北京时间，Asia/Shanghai）。正式API已由用户确认。

## 常用命令（推荐入口）

开发分别在PC仓库执行 `npm run dev`、H5仓库执行 `npm run dev:h5`。测试和正式双端统一在PC仓库执行：

```sh
cd /Users/xuan/AI/ClaudeAllData/shkj-OA
npm run package:test
# 或：正式环境双端打包（不上传）
npm run package:production
```

`scripts/package-dual.mjs` 按目标显式传入两端API/上传地址、静态路径并关闭Mock；构建在独立 `release-packages/YYYYMMDD-HHmmss-test或production/` 目录中进行，不覆盖dist或旧包、不改开发/测试环境文件。PC静态路径 `/`，H5沿用 `/h5/`。需要本机有相邻 `SHKKJ-uniapp` 仓库及其依赖、zip/unzip命令；无移动仓库写权限时需批准构建权限。

每次自动生成 `build-record.json`（北京时间开始/结束、各步骤时间与退出码、Git版本/工作区状态、Node/pnpm版本、API、路径、包大小和SHA-256），并保留分步骤log。失败也会留记录；只有status=passed的包才可交付。脚本恢复移动端生成的pages/manifest快照，不能在同一移动仓库并发构建或同时编辑这两个文件；强制终止时需人工核对。

## 2. 本地准备

- 两个项目都使用现有 `pnpm-lock.yaml`；首次安装在各自目录执行 `pnpm install --frozen-lockfile`，不要混用安装器改写锁文件。本文的npm命令仅用于执行脚本。
- PC声明Node `^18 || >=20`；H5声明Node `>=18`、pnpm `>=7.30`。实际打包应记录 `node --version`、`pnpm --version`，不要在打包时顺带升级依赖。
- 先检查各自 `git status --short`，明确产物包含当前工作区未提交修改，不只包含HEAD提交。
- 构建会更新输出目录；先将旧PC `dist`、旧H5 `dist/build/h5-test` 移到独立备份目录或保留既有压缩包。禁止删除仓库、源文件或覆盖旧发布包。
- 环境变量和前端产物都不是秘密存储处，不得放入密码、访问Token、私钥等。

## 5. 正式环境打包

在PC仓库执行 `npm run package:production`。正式API及文件/上传地址统一 `https://oa.shouhuikeji.com/shouhuiApi`，PC `/`，H5 `/h5/`。脚本执行以下流程：

1. 创建独立时间戳目录并立即登记startedAt及running状态。
2. PC设置 `OA_BUILD_OUTPUT_DIR` 到本次pc目录，运行完整 `npm run build`。`build/constant.ts` 支持独立输出；`postBuild` 仅对API、文件域名、API前缀三个公开配置优先读取显式环境变量，因此运行时不会回退测试地址。
3. H5使用production编译模式、正式API/上传地址，关闭代理/源码映射，输出到本次h5目录；结束后恢复pages/manifest原始内容。
4. 读取PC `_app.config.js`、H5 `app.config.js` 验证目标地址；核对H5前缀及代理关闭、HTML入口静态引用、本地敏感文件/源码映射排除。
5. 压缩为 `oa-pc-production.zip`、`oa-h5-production.zip`，执行zip完整性检查，计算SHA-256，记录结束时间。错误退出并保留失败记录，不假报成功。

原始 `build:h5:test` 固定测试地址，不可用于正式包；不需要手动修改任一 `.env.production`。正式包生成后也不会自动上传服务器。

## 6. 运行产物与部署检查

- 本地预览PC已有产物可使用项目内Vite的preview命令；`npm run preview` 会先重新构建，不适合检查一个不能被覆盖的既有发布包。
- 测试/正式服务器应由Nginx等静态Web服务器运行，不运行 `npm run dev`，也不双击HTML文件。
- 测试PC包内容放到站点根目录，H5包内容放到 `/h5/`；不要放到 `/shouhuiApi/h5/`。正式路径以确认值为准。
- PC深层路由回退到PC的index.html，H5深层路由回退到H5的index.html；API路径必须代理到后端，不能回退成前端HTML。
- HTML、运行时配置和Service Worker应及时更新；带hash静态文件可长期缓存。若旧页面仍出现，检查缓存/Service Worker，先保留上一版以便回滚。
- 打包后执行 `unzip -tq <压缩包>`，核对入口引用的本地资源存在；检查不包含 `.env`、私钥及不需发布的source map；记录SHA-256。
- 上传后再检查登录、角色权限、PC业务页面、H5深链接、附件与地图。构建成功不能替代接口/权限/业务验收。历史安全待办见 `docs/测试部署安全检查.md`，其中旧审计数量不是当前安全结论。
