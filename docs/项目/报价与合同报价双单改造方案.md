# 报价与合同报价双单改造方案

日期：2026-09-12  
项目：shkj-OA（移动端相关入口同步纳入后续实施）  
状态：需求与技术改造方案，尚未实施。已确认规则、建议设计、待确认事项分开标识。

## 1. 改造目标与已确认规则

1. 签约前，由采购录入成本报价，提交领导审批。
2. 审批人维护报价系数；物料维护可以设置默认系数，本次报价中可以调整。
3. 指导单价 = 成本单价 × 报价系数。系数 1.2 表示在成本基础上加价 20%，不是毛利率 20%。
4. 领导确认后生成正式指导报价并锁定，交给销售使用。
5. 销售不查看成本与系数；对外导出的文件不含成本价，也不含可反推成本的系数或公式。
6. 上述是合同签订前的报价。合同签订后生成新的合同报价单，两类单据独立且可追溯关联。
7. 不在合同里直接改写签约前已锁定原报价；原报价保留领导确认时的完整依据。

**新规则替代旧设计中的“合同关联后调整同一报价、不复制新单”。** 当前系统仍运行旧流程，不能把本文当成已经上线的行为。历史数据不自动按新规则改写。

## 2. 单据边界与整体流程

```text
物料默认报价系数
       ↓ 选料时形成快照
采购成本报价草稿 → 提交领导 → 驳回 → 采购修改后重提
                         ↓ 审核成本、调整系数、确认
                签约前报价锁定（原始审批依据）
                         ↓ 销售查看、对外导出
                      合同签订
                         ↓ 生成独立新单，保留来源 ID/版本
                  合同报价单（最终成交明细）
                         ↓ 生效规则待确认
                    计划用料 → 物料总账
```

| 对象 | 用途 | 主要内容 | 是否修改来源 |
| --- | --- | --- | --- |
| 签约前报价单 | 内部成本与加价审批、对外指导报价 | 成本、系数、指导价、数量、审批快照 | 锁定后不再直接修改 |
| 合同报价单 | 记录最终签约物料、数量与成交单价 | 来源报价关联、合同关联、成交明细 | 不修改签约前报价 |
| 计划用料 | 实施用料安排 | 物料、计划数量、单位、备注 | 不反向修改合同报价 |

“采购成本报价草稿”和“领导确认的指导报价”建议是同一签约前报价的不同阶段，不再额外引入第三类业务单据。本功能也不等同于实际采购订单或采购付款流程。

## 3. 角色与数据权限

下表为建议配置，实际授权须由管理员确认；不以姓名硬编码审批权限或查找审批人。

| 角色 | 签约前权限 | 合同报价权限 | 成本/系数可见性 |
| --- | --- | --- | --- |
| 采购/报价编制人 | 创建、编辑本人或授权范围内草稿、提交、修改驳回单 | 按业务需要查看 | 内部授权范围可见 |
| 报价审批领导 | 查看待审成本、调整系数、通过或驳回 | 查看与监督，后续审批能力待定 | 可见 |
| 销售 | 查看分配给本人或负责项目的已锁定报价、对外导出 | 建议维护所负责合同报价草稿 | 不可见 |
| 项目经理 | 按项目授权查看执行所需信息 | 只读生效合同报价，带入计划 | 默认不可见 |
| 库管 | 沿用库存和采购确认权限 | 仅业务确需的物料与数量 | 不因库管角色自动开放 |
| 管理员 | 管理配置与授权 | 管理配置与授权 | 按管理员授权，不允许绕过锁定直接改数据 |

- 区分菜单权限、按钮权限、行级数据权限和敏感字段权限。
- 后端查询、导出、修改、审批均校验权限，前端隐藏不是安全边界。
- 审批领导通过角色/审批配置绑定实际账号；离职或换人可配置，不改业务代码。
- 多角色账号的成本可见性需按明确授权执行，禁止通过销售视图意外获取内部完整对象。
- PC 与移动端分别配置终端授权；给 PC 授权不代表移动端自动获得权限。

## 4. 物料维护与价格计算

### 4.1 建议新增字段

以下为设计字段名，不表示现有接口已支持：

| 层级 | 建议字段 | 说明 |
| --- | --- | --- |
| 物料主档 | defaultQuoteFactor | 默认报价系数，建议最多 4 位小数 |
| 报价明细 | costUnitPrice | 本次报价成本单价，不直接替代库存实际成本 |
| 报价明细 | quoteFactor | 选料时带入默认值，领导可调整的本次快照 |
| 报价明细 | guideUnitPrice | 后端计算的指导单价 |
| 报价明细 | quantity / unitId | 数量与计价单位，按现有单位体系对齐 |
| 报价明细 | costAmount / guideAmount | 成本金额和指导金额，后端计算 |
| 合同明细 | dealUnitPrice / dealAmount | 最终成交单价与金额，独立于指导价 |

- 本次修改系数仅影响当前报价，不回写物料默认系数。
- 修改物料默认系数不追溯影响已保存或已锁定报价。
- 成本必须明确是“当前选择单位的单价”；切换单位时明确换算或清空重填，不得把箱价当个价使用。
- 系数不等于利润率：成本 100、系数 1.2，指导价 120，加价率 20%，毛利率约 16.67%。
- 建议数量 > 0、成本单价 ≥ 0、系数 > 0；零成本和低于成本报价是否允许提交须确认，不能默默按 1 填补缺失系数。
- 建议单价/金额保留 2 位，系数最多 4 位；指导单价先四舍五入，再乘数量生成行金额，合计为行金额之和。具体精度须前后端一致并在 Apifox 明确。
- 含税/未税、税率、币种、运费及安装服务费口径待确认。成本与指导价必须使用同一税务和单位口径。
- 后端重新计算金额并返回权威结果，不信任前端提交的指导价或总额。

## 5. 签约前报价流程与锁定

建议业务状态：草稿 → 待审批 → 已通过锁定；待审批可驳回到可修改状态。状态编码由后端确认，不能直接复用合同状态工具处理不同协议。

1. 采购选择项目分期，维护报价名称、销售负责人、物料、数量、单位、成本和备注。
2. 保存草稿后回显后端完整主单和明细；失败时保留输入，不能显示虚假保存成功。
3. 提交时校验至少一条有效物料，生成领导审批待办；待审阶段采购禁止修改。
4. 领导查看成本和数量，填写/调整每行系数，可批量填入系数再逐行调整。
5. 确认通过时，后端同一事务保存系数、重算价格、记录审批人/时间、锁定并关闭待办。不得先改明细成功再审批失败，留下半完成状态。
6. 驳回必须填写原因，关闭待办并允许采购修改后重提。
7. 锁定后销售只能查看和导出，不允许直接修改价格、数量、单位或系数。
8. 需要重新报价时如何修订锁定单、是否使用版本及再次审批，作为独立待确认流程；不得新增任意解锁按钮。

建议加入版本号乐观锁、幂等键及服务端状态校验。重复点击/超时重试不能产生重复审批、重复待办或重复合同报价单。审批前重新查询只是前端辅助，不能替代服务端并发控制。

## 6. 合同报价生成与生命周期

### 6.1 已确认边界

- 签约后生成新的合同报价单，必须有独立主键/单号，关联来源签约前报价及其锁定版本。
- 来源报价不变，合同报价调整不回写原始成本、系数、指导价或数量。
- 外部合同物料附件与结构化合同报价明细是不同对象；上传附件不能代替可计算的明细数据。

### 6.2 建议实现，需业务确认

- 初始复制来源的物料、规格、单位、数量及指导单价，指导单价作为成交单价初始值。
- 内部成本留在受控来源快照，不把成本和系数复制到销售可读字段中。
- 合同报价可调整最终成交数量与价格，建议增加调整原因；是否允许新增/删除物料及低于指导价提交须确认。
- 建议每份合同只有一个当前有效合同报价版本；历史版本保留，不通过删除历史解决唯一性。
- 建议合同报价在合同录入草稿阶段编辑，随合同提交冻结，合同审批通过后生效；驳回/撤回只解冻对应合同报价，不解冻签约前原单。
- 上述“草稿、冻结、生效”方案尚未得到逐项确认。用户明确的“签约后生成”不等于系统“合同审批通过后生成”，不得擅自把二者等同。
- 如果确认必须合同审批通过后才生成，则生成动作移至通过事务，后续合同报价修改应走合同变更流程，而不是已通过合同直接编辑。
- 再次提交合同或重复调用生成接口，应返回既有对应版本，不重复生成。
- 合同报价总额与合同金额是否必须相等需明确：存在服务、税费或折扣时，应有可解释的差额项，不擅自覆盖合同金额。

## 7. 计划用料与物料总账衔接（建议）

1. 下游执行来源由“签约前候选报价”切换为“当前生效合同报价”，避免把未成交数量当成执行依据。
2. 首次创建计划时带入生效合同报价物料及数量；已存在计划不自动覆盖，仍允许按现有权限候补物料或调整计划数量。
3. `candidateQty` 继续由后端维护，前端编辑计划不传该字段。建议其新含义为生效合同报价对应的基准单位数量，具体映射需后端确认。
4. `plannedQty` 与合同报价数量独立，调整计划不反向修改合同报价。
5. 物料总账按分期与物料、基准单位汇总；两份报价不能重复计数，失效版本不能参与当前合同数量。
6. 已领料、已采购、已执行项目变更合同报价时，不自动覆盖计划或倒扣库存；变更差异及后续处理须有单独规则。
7. 成本报价不是实际采购成本；不要直接用报价成本覆盖总账 `actualCost` 或库存计价。

## 8. 接口改造与请求数量治理

### 8.1 当前核对结果（2026-09-12）

已刷新 Apifox 项目 8679942 并核对目标资源：

- `/project/materialCandidate/list` 仍必传 `periodId`，只声明 pageNo/pageSize，没有跨项目查询协议。
- `OaProjectMaterialCandidateSaveRequest` 当前只有 id、periodId、candidateName、status，不代表已支持本方案的成本审批或双单关系。
- `/project/contract/addWithPaymentRecords` 当前在 multipart `data` 顶层接收 `materialCandidateId`，提交后把原候选单改为已采用，且不持久化新的合同关联字段。这与双单方案不等价，必须改后端流程。
- 当前前端 `src/views/plan/Plan.api.ts` 的 `quotationList` 先查询全部分期再逐个查候选单，最后本地分页；翻页/搜索会重复扫描，是已确认的请求过多原因。

### 8.2 后端需要提供的能力

以下是能力清单，不是已发布 API；具体 URL、方法、字段名及状态码须后端更新 Apifox 后实施。

| 能力 | 必要约束 |
| --- | --- |
| 报价服务端分页 | periodId 可选；支持主项目/分期/报价名称、状态筛选，返回名称、总额、角色允许字段及 total/current/size |
| 报价详情 | 按单据 ID 直接查询，不从全部清单反查；返回版本、可执行动作、明细分页信息 |
| 草稿保存 | 保存主表与明细，明确部分失败/事务语义及返回内容；禁止越权修改敏感字段 |
| 提交、撤回、驳回 | 独立动作鉴权和状态机；撤回的适用阶段待确认 |
| 审核确认 | 同事务保存系数、重算价格、锁定及关闭待办 |
| 对外导出 | 后端安全字段白名单，只包含销售可见内容，覆盖全部结果而非当前页 |
| 合同报价生成 | 校验来源已锁定及项目归属，持久化来源/合同关联，幂等生成新单 |
| 合同报价维护及生效 | 独立 ID/版本，按合同阶段控制；不修改原报价 |
| 物料默认系数维护 | 查询/保存字段与权限、默认空值策略明确 |
| 审批待办 | 明确 todoType、业务 ID、审批人范围；详情打开对应单据，办理用来源业务接口 |

- 列表每次翻页/搜索只发一条当前页报价主查询，不再先读项目列表、逐项目查报价或逐行补名称；字典可缓存，不计入重复业务查询。
- 选择项目采用远程搜索分页，不在进入报价列表时预加载全部项目。
- 主表列表不附带全部物料明细，详情按需加载。
- 若仍用 `editBatch` 全量同步明细，必须读齐全部分页并校验加载成功后才能提交；分页只是展示，不能用当前页覆盖整单。更优方案是版本化差量维护或专用整单保存协议。
- 导出完整分页数据由后端负责；不能仅导出 pageSize=1000 的第一页。
- 保留单次操作一条结果提示，加载错误支持重试，不叠加接口和页面重复 Toast。

## 10. 成本保密与导出验收

- 销售接口响应不出现 costUnitPrice、costAmount、quoteFactor、内部毛利等字段，不能仅在 UI 隐藏。
- 指导价和系数同时暴露可反算成本，因此系数也属于敏感字段。
- 不向销售下发内部完整对象再用前端删除字段；导出使用明确白名单 DTO。
- Excel/PDF 不包含成本列、隐藏工作表、批注、隐藏单元格、内部附件或引用成本的公式。
- 对外清单建议仅有序号、物料名称、品牌/规格、单位、数量、指导价或成交价、金额、经审核的对外备注。
- 签约前文件导出指导报价，合同报价文件导出最终成交报价，标题/单号/来源不能混淆。
- 日志、错误信息、移动端缓存和预览文件也遵守同一敏感字段权限；切换账号不能残留前一个账号的成本。

## 11. 历史数据与上线顺序

1. 先确认第 13 节决策项，再定义数据库与 Apifox 契约。
2. 后端先实现跨项目分页、角色字段隔离、双单关联、状态机、并发/事务及幂等。
3. 更新物料与报价前端，然后改合同生成与下游计划；最后同步移动端。
4. 历史候选单缺成本/系数时标识为历史单，禁止推算或伪造审批数据。
5. 已采用老报价保持既有执行结果；是否补建合同报价由审核后的迁移清单决定，保留来源标记及迁移日志。
6. 不批量解锁旧单、不重复累计 candidateQty、不覆盖现有计划/库存/实际成本。
7. 灰度验证后切换入口；回滚保留已经生成的新单和关联，不用删数据恢复旧流程。
