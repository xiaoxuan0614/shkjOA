# 字典配置说明（类型/状态下拉统一走字典）

> 更新：2026-09-09。原则：**所有「类型 / 状态 / 属性」类下拉一律走「系统管理 → 数据字典」**。正式环境以后端字典为准；接口固定枚举允许保留同值展示兜底，避免字典缓存暂时不可用时直接显示英文码。加载：登录返回 `sysAllDictItems` + 实时 `/sys/dict/getDictItems/{code}`。

## 二、创建步骤

1. 登录后台 → **系统管理 → 数据字典** → 新增字典（字典编码/字典名称填上表的编码与含义）。
2. 进入该字典 → 新增字典项（`value` / `text` / 排序；`project_period_status` / `outsourcing_status` 还可配颜色色值）。
3. 重新登录或刷新页面，前端即自动加载。

## 三、字典项 value 一致性（重要，务必看）

前端下拉的 **`value` 会随保存提交到后端**，因此字典项的 `value` **必须与后端已存数据一致**：

- **项目相关字典（`project_type` / `project_business_attr` / `project_products`）真实后端存的是编码**（如 `1`、`2`），多选字段存逗号分隔字符串（如 `"2,1"`）。→ 字典 `value` 用编码（`1/2/3...`），`text` 为展示文案。
  - 前端已做「数组 ⇄ 逗号字符串」自动转换：编辑回显时把 `"2,1"` 拆成 `["2","1"]`，保存时 `["2","1"]` 合回 `"2,1"`（见 `ProjectApply.vue` 的 `loadDetail` / `handleSave`）。
- `project_period_status` 的当前状态值以后端 `period.status` 为准；调试阶段使用 `DEBUGGING=调试中`。前端仅兼容历史 `DEBUG_COMPLETED=调试完成` 数据，不再向统一状态接口提交该旧值。
- `project_process_status` 固定与工序接口枚举一致：`NOT_STARTED=未开始`、`IN_PROGRESS=进行中`、`COMPLETED=已完成`。建议颜色依次配置为灰、蓝、绿；不得把中文文案作为接口值提交。
  - 2026-08-31 已在正式后台创建该字典及三项启用状态，并刷新字典缓存；本次未向 Mock 增加同名字典。
- 工序接口字段 `processName` 保存的是 `work_type` 字典值，抽屉、列表和日志必须按该字典转换显示；字典未命中时才展示接口原值。
- 通用数值审批状态统一使用 `approval_status`：`-1=待提交`、`0=驳回`、`1=审核通过`、`2=待审批`、`3=已撤回`，覆盖计划方案、合同、项目用料申请、项目延期、出入库申请及其明细。`src/utils/approvalStatus.ts` 保留同值判断与缓存失败兜底。2026-09-03 正式后台已创建该字典并删除历史 `contract_status`、`stock_apply_status`、`stock_item_status`；项目生命周期、出入库执行状态及 `approval_result=AGREE/REJECT` 保持各自协议。
- 首页待办类型统一使用 `todo_type`。`value` 必须与 `/sys/todo/page` 返回的 `todoType` 完全一致；前端读取字典文案和颜色，未命中时显示原始编码，字典暂时不可用或未配置颜色时使用下表同值文案/颜色兜底。该字典只负责展示，不改变 `todoType/bizId/bizSubId/actionKey/actionParams` 的办理分派。前 8 项已在正式后台创建；两项验收待办需后端实现后同步新增并刷新字典缓存。

| `value` | `text` |
| --- | --- |
| `PROJECT_MEMBER_INVITATION` | 项目成员邀请 |
| `PROJECT_PLAN_APPROVAL` | 项目计划方案审批 |
| `PROJECT_CONTRACT_APPROVAL` | 项目合同审批 |
| `PROJECT_MATERIAL_APPLY_APPROVAL` | 项目用料申请审批 |
| `PROJECT_DELAY_APPROVAL` | 项目延期审批 |
| `PROJECT_REWORK_APPROVAL` | 项目返工审批 |
| `PROJECT_INTERNAL_ACCEPTANCE` | 项目内部验收 |
| `PROJECT_EXTERNAL_ACCEPTANCE` | 项目外部验收 |
| `STOCK_OUT_APPROVAL` | 出库申请审批 |
| `STOCK_OUT_EXECUTE` | 出库执行待办，等待库管出库 |

- `member_role` 完整字典实时用于参与成员列表回显，避免登录时空缓存遮蔽后台新配置；添加成员弹窗过滤 `0/1/2`，且这三个角色不可删除。人员配置邀请状态固定为 `0=拒绝`、`1=接受`、其他值`=待接受`，不使用 `invite_status` 推断文案。
- `outsourcing_status` 的 `value` 为 `0 / 1`，与后端 `OaOutsourcingUnit.status` 一致。
- `contract_type`：项目合同 / 维保合同 / 无合同（`value` 建议用中文文本与存量一致）。
- `project_material_candidate_status`：状态值必须与候选清单接口一致，配置 `-1=草稿`、`0=驳回`、`1=通过（锁定）`、`2=待处理`、`3=已采用`、`4=已作废`；列表、搜索和编辑页直接按该字典回显。

> 若字典 `value` 与存量不一致，编辑回显会丢失文案（显示原始 value），属字典配置问题，非代码 bug。

## 四、合同签订 / 审批流程（固定状态配置）

- 新增或重新提交合同 → `status=2`（待审批）；销售负责人默认当前登录用户，可修改。
- 合同信息页内选择通过/驳回：**通过 → `status=1`**，选择项目经理并写入合同后将项目流转到「筹备中」；**驳回 → `status=0`** 并填写 `approvalReason`。审批结果为固定选项，不新增字典。
- `status=-1` 表示待提交，`status=3` 表示已撤回；其他异常值按待提交兜底。
- 原提交人可撤回待审批合同；待提交、驳回或已撤回合同可由原提交人修改并重新提交，驳回详情必须展示 `approvalReason`。审核通过合同锁定。
- 项目管理列表「合同状态」列使用固定通用转换；后端项目列表接口需返回 `contractStatus`。
- 权限码：发起合同 `project:contract`；审批 `project:contract:approve`（角色授权里配）。
