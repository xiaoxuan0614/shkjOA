## 2. 技术架构与启动链路

### 2.1 技术栈

- Vue 3 + TypeScript + Vite 8
- Ant Design Vue 4
- Pinia
- JeecgBoot 前端基础设施
- pnpm（Node 18 或 20+）

### 2.2 应用启动

`src/main.ts` 的主要顺序：

`createApp` → `createRouter` → `setupStore` → `setupI18n` → `initAppConfigStore` → 注册外部包/全局组件 → `setupRouter` → `setupRouterGuard` → 指令与错误处理 → 第三方组件 → `router.isReady()` → `mount`

### 2.3 权限与动态路由

项目列表“验收”新增独立入口权限 `project:acceptance:view`，无权限不生成按钮，点击及弹窗加载重复校验；内外验办理权限、待办与详情原有访问规则不变。正式后台于 2026-09-13 在 `/project/list` 下创建 PC 按钮节点“验收”，可见/可访问、有效，编辑页已回读确认；Mock 已同步，本次未修改角色授权。

项目列表“新增”入口通过 `project:add` 控制显示，打开新增类型选择框及确认进入时重复校验；新建主项目/新增分期共用此权限。正式后台已于 2026-09-11 在 `/project/list` 下创建“创建项目（按钮）”（PC、可见/可访问、有效）并回读确认；本次未改角色授权，使用者仍需该按钮及 `/project/apply` 隐藏页权限。Mock 同步权限码，不代表正式授权；新增接口及后端鉴权不变。

当前权限模式是 **BACK**：

1. `src/api/sys/menu.ts` 的 `getBackMenuAndPerms()` 从后端取得菜单和权限码；
2. `src/store/modules/permission.ts` 的 `buildRoutesAction()` 构建运行时路由；
3. `src/router/helper/routeHelper.ts` 将后端菜单对象转换为 Vue Router 配置；
4. `src/utils/dynamicPages.ts` 通过 `import.meta.glob` 将后端 `component` 字符串解析到 `src/views/` 页面；
5. Pinia 权限仓库保存菜单、动态路由和权限码。

### 2.4 API 层

- 请求入口：`src/utils/http/axios/` 导出的 `defHttp`。
- 正常响应：`{ code, result, message, success }`，`code === 200` 表示成功。
- `GET` 查询成功默认不弹 Toast；新增、修改、审批等写操作由接口调用或页面保留一条明确结果提示。全局 Toast 同时最多显示两条，避免并发请求提示堆叠。
- 请求带时间戳和 MD5 签名。
- 各业务模块在对应 `*.api.ts` 中维护接口，页面不应散落硬编码 URL。

### 2.5 表单显示约定

- `src/App.vue` 的 Ant Design Vue `ConfigProvider` 与 `src/settings/componentSetting.ts` 的公共 `BasicForm` 默认配置均关闭 `colon`，所有业务表单标签不显示冒号。
- 公共字典下拉 `JDictSelectTag` 默认只把“请选择…”作为未选择时的占位提示，不将其插入可选项列表；业务下拉仅展示真实字典项，特殊场景可显式开启 `showChooseOption`。
- 合同信息表单使用响应式两列网格，附件字段与普通字段共用同一标签和控件对齐规则；窄屏切换为单列，上传按钮使用普通中性按钮样式。
- 新增用户、重置密码、个人修改密码、注册及忘记密码统一使用 `src/utils/password.ts` 的密码长度规则：新密码至少 6 位，不强制数字、大小写字母或特殊字符组合；确认密码仍必须一致。登录表单只校验必填，兼容历史账号。

## 3. 菜单与路由的三种来源

| 来源         | 文件/位置                                 | 职责                               | 是否是正式菜单事实源 |
| ------------ | ----------------------------------------- | ---------------------------------- | -------------------- |
| 正式后端菜单 | 后端 `sys_permission`，后台“菜单管理”维护 | 登录后返回生产菜单、隐藏页和权限码 | **是**               |
| 前端静态路由 | `src/router/routes/modules/*.ts`          | 开发兜底、静态入口和直接路由注册   | 否                   |
| Mock 菜单    | `mock/sys/menu.ts`                        | `pnpm mock` 时返回菜单和权限码     | 否，仅本地验证       |

## 5. 项目、合同与回款关键流程

### 5.0 文件预览边界

文件统一通过 `src/utils/filePreview.ts` 和 `src/components/FilePreview/FilePreviewContent.vue` 在站内弹窗读取并渲染，不提供外链或下载入口，也不再把内网文件地址交给公网预览服务。已选择或已提交的图片、PDF、DOCX、XLS/XLSX、PPTX 均可预览；旧版 DOC/PPT 无法在浏览器直接解析时展示明确说明，不再出现空白弹窗。

公共 `JUpload`、`BasicUpload` 默认每个上传入口只允许一个文件且不启用多选；项目、合同、方案及独立验收单保持相同规则。验收报告例外：每次一个、累计最多三个，支持图片、Word、PDF、Excel，逐项预览/删除，满三个禁用上传；使用 `acceptanceFiles.ts` 拆分路径，沿用 JUpload 逗号连接约定（验收后端持久化待联调）。其他单文件入口存在文件时隐藏上传按钮。已提交文件的删除入口服从页面编辑权限：项目详情文件仅项目对接人或项目经理可删除，计划、合同及项目表单仅在各自可编辑状态开放删除。

### 5.1 项目生命周期

项目以分期 `periodId` 为主要流程标识，主项目由 `projectId` 标识。当前主要状态顺序为：

`未开始` → `合同签订/审批` → `筹备` → `待审批/计划审批` → `实施中` → `全部工序完成` → `验收中（内部/外部并行）` → `质保中` → `完结`

当前轮任一验收不通过时可发起返工：`验收中` → `返工申请/审批` → `返工中` → `工序完成后自动验收`。一张返工单只配置一个统一返工工序，返工用料只记录本轮额外领料量；首次施工与历次返工通过 `reworkId` 留痕，不覆盖历史。

实际状态值、权限码和可执行动作以 `src/views/project/Project.data.ts`、后端状态接口及 [项目全流程需求](项目/项目全流程需求.md) 为准。

### 5.2 合同隐藏页入口协议

合同编辑表单关联报价仅提供“修改调整”，不另设“查看详情”；调整弹窗物料明细默认 10 条/页，支持 20/50/100 条及跳页。分页只影响展示，完整草稿跨页保留、全量校验并保存；错误自动定位对应页。共享表格其他调用方默认不开分页，合同只读详情入口保持不变。

合同审批统一使用 `project:contract:approve`：合同信息页审批区域、通过/驳回操作与后端 `POST /project/contract/status` 保持一致。旧 `project:contract:audit` 不再作为前端审批权限；正式审批角色需授予新权限并刷新登录权限缓存。

| 模式 | URL 参数 | 首次业务读取 | 页面状态 |
| --- | --- | --- | --- |
| 新增 | `mode=create&periodId=...&projectId=...` | 读取项目基本信息，**不读取**已有合同、回款计划 | 项目信息+空合同表单 |
| 查看 | `mode=view&periodId=...&projectId=...` | 按 `periodId` 读该分期唯一合同，成功后再调用 `paybackList` | 只读 |
| 编辑 | `mode=edit&periodId=...&projectId=...` | 按 `periodId` 读该分期唯一合同，成功后再调用 `paybackList` | 原提交人可修改待提交、驳回或已撤回合同 |

约束：

- 查看/编辑缺少 `periodId` 时明确报错并返回项目列表。
- 页面入口不再调用 `contractList` 猜测“新增还是已有合同”。
- `contractList` 只用于真正的合同列表；不得用于新增页初始化或组合提交后的合同 ID 恢复。
- 从查看点击“修改并重新提交”时将 URL 的 `mode` 改为 `edit`，保留 `periodId/projectId`；驳回状态同时展示驳回原因。
- 所有合同修改均不调用已废弃的 `POST /project/contract/edit`，统一使用 `POST /project/contract/editWithPaymentRecords`：`contract.periodId` 必传，合同字段差量提交，回款计划全量同步，后端将状态转为待审批。合同审批通过前写项目经理也携带当前完整回款计划调用该组合接口；回款管理列表的“编辑”统一跳转正式合同编辑页。
- 通用数值审批状态统一使用后台字典 `approval_status`：`-1=待提交`、`0=驳回`、`1=审核通过`、`2=待审批`、`3=已撤回`，覆盖计划方案、合同、项目用料申请、项目延期、出入库申请及其明细；前端保留同值映射兜底。历史 `contract_status`、`stock_apply_status`、`stock_item_status` 已删除。项目生命周期、出入库执行状态及 `approvalResult=AGREE/REJECT` 等审批动作参数保持各自协议，不得作为审批状态回显。项目列表在合同通过前统一显示“合同信息”，进入只读详情后：审批权限人可通过/驳回，原提交人可撤回待审批合同或修改驳回/撤回合同后重提。合同通过后列表入口隐藏，只从项目详情查看。
- 项目详情移除顶部“合同信息”快捷按钮和原“计划方案”标签，在标签区新增只读“合同信息”：按当前 `periodId` 调用 `GET /project/contract/queryById`，展示合同主信息、合同附件、合同货物清单及回款计划。详情页八个标签依次为基本信息、合同信息、项目成员、实施位置、实施记录、验收记录、项目文件和用料统计；旧 `tab=plan` 查询参数回退到基本信息。
- 项目详情“用料统计”按当前分期调用 `GET /project/materialAccount/page`，支持 `keyword + pageNo + pageSize` 服务端搜索和 20/50/100 分页。主表展示物料、计划数量、实际出库、施工消耗、待处置和实际成本，展开行查看申请占用、归还处置、库存与金额；数量均按 `baseUnitName` 展示。该入口与仍读取 `/project/materialPlan/list` 的补料计划预览分离，避免用总账记录替代补料所需的 `materialPlanId`。
- 项目详情“项目成员”标签内部按数据来源拆为“参与人员”和“外协人员”：参与人员调用 `GET /project/member/list`，同一人员多角色合并显示并按 `member_role` 回显角色名称，列表仅展示序号、成员名称、成员角色和邀请状态；该区支持手动刷新和继续邀请成员，邀请按 `/sys/user/list` 选人、过滤系统角色 `0/1/2`、跳过已有成员角色组合后调用 `POST /project/member/addBatch`，成功即重查参与人员列表。外协人员调用 `GET /project/memberOutsource/list`，按单位展示类型、人数、工时、联系人和联系电话，`unitType` 按 `outsourcing_type` 回显。两组拥有独立数量、加载、空状态和失败重试，不再依赖成员记录中的历史 `outsourcingFlag/outsourcingUnit` 字段。
- 项目详情“项目文件”标签固定提供上传入口：所有能访问当前项目详情的用户均可上传，文件通过 `/sys/common/upload` 携带 `biz=periodId` 获取 `message` 路径，再调用 `/project/file/addBatch` 写入记录并刷新列表；删除入口仍只对项目对接人或项目经理开放。
- 合同待审批只读页将 `contractType/paymentNode` 分别通过 `contract_type/payback_node` 字典转换为名称；项目经理姓名快照为空时按用户 ID 补齐，合同附件及合同货物清单有路径时提供预览入口。
- 仅项目处于筹备中（`PREPARING`）时，“编辑计划方案”显示在项目列表操作栏；计划提交审批后立即隐藏，审批通过进入实施中后也不再显示。
- 项目管理、计划方案管理、实施管理及出入库申请列表均不展示项目编号；出入库申请中原“关联单号”列实际绑定 `projectNo`，同步移除；报价管理列表也不展示分期项目 ID。各列表继续以项目名称作为主要识别信息，项目详情、编辑表单、项目选择器、列表搜索、路由与接口中的 `projectNo/periodId` 字段不受影响。
- 项目列表的“项目对接人”优先展示接口姓名快照；快照为空时按用户 ID 从系统用户列表补齐，仍缺失时按 `periodId` 补查分期详情后回显。
- PC 点击“新增”后先选择“新建主项目”或“已有主项目下新增分期”；分期模式在前置弹窗选定主项目后进入表单并锁定主项目上下文。两种新增模式统一通过 `POST /project/project/addProjectPeriod` 组合提交，使用 `parentProjectId` 区分；编辑通过 `POST /project/project/editProjectPeriod` 提交。两者均使用 `multipart/form-data`，`data` 为业务 JSON 字符串，`attachment` 为单个可选附件。项目基本信息附件不再预调用 `/sys/common/upload`，业务 JSON 不传 `attachmentFileId`；编辑未选择新附件时保留原文件，选择后由后端替换。附件只允许 Word、PPT、Excel、PDF 和图片，新增/编辑表单不显示重复的“基本信息”区块标题。
- 进入“编辑/查看计划方案”后，父页面先并行完成 `GET /project/project/projectPeriodDetail` 与 `GET /project/contract/queryById`，两项均成功后才挂载六个业务页签；任一失败都停留在可重试状态，禁止子页以空上下文继续查询或全量保存。同一路由切换 `periodId` 时重置页签并使旧响应失效。页面标题旁的“详情”抽屉直接复用父页已加载的分期详情，不重复请求同一接口。
- 编辑/查看计划的标签名称统一为“方案文件”，按当前项目分期 ID 调用 `GET /project/plan/list` 加载计划方案记录，不再读取 `/project/file/list`，因此合同附件及合同用料草稿不会混入。前端实际传入 `periodId`，但当前 Apifox 参数表仍未声明该字段，后端需补齐契约并确保服务端按分期过滤。表格序号始终按当前行位置从 1 连续显示，不使用内部行键。方案文件使用顶部“保存本页/修改”：先校验整页，再将新增记录和附件通过 multipart `/project/plan/addBatch` 一次提交，已有修改调用 `/project/plan/edit`，待删除记录最后调用 `/project/plan/deleteBatch`；全部完成并回查后整页只读。文件选择只在本地回显，保存时上传。多种操作不是同一事务，部分失败时保留未完成草稿，已成功记录回查后不重复新增。
- 项目基本信息附件采用项目新增/编辑接口组合提交；合同附件和合同物料文件分别随 `addWithPaymentRecords/editWithPaymentRecords` 的 `attachment/materialAttachment` part 组合提交，不预调用统一上传。方案、详情与验收等仍使用统一上传的页面，必须在响应满足 `success=true`、`code=200` 且 `message` 非空时才读取路径。
- 编辑计划方案不再提供“保存全部”。“提交审批”只调用 `POST /project/period/status`，传当前 `periodId` 与项目生命周期 `PENDING_APPROVAL`，不再隐式保存方案文件、用料、人员、外协、工序或位置；提交前必须逐一打开六个页签，确认业务主数据已加载、必填数据通过校验，且无加载失败、保存中或未保存内容，方案文件至少已有一条已保存记录。审核人点击“通过”也执行同一门禁；状态请求开始后整页禁写。页面编辑权限同时要求当前用户为合同指定项目经理且分期仍为 `PREPARING`；计划审批操作同时要求生命周期为 `PENDING_APPROVAL`、`approvalStatus=2` 和审批权限，后端切换期在审批字段缺失时仅按该生命周期临时推导为 `2`。
- 用料计划与实施计划使用独立的“保存本页/修改”状态：已有记录加载后默认只读，点击“修改”才解锁；空列表直接可编辑；保存成功后刷新服务器数据并恢复只读。全量同步按钮必须等待本页初始查询成功，查询失败时禁止用空数组覆盖服务器数据。用料计划通过 `/project/materialPlan/editBatch` 全量同步，每条明细提交 `id（已有记录时）/materialId/plannedQty/unitId/remark`，单位名称快照由后端写入；物料计划与物料主数据并行加载后再统一回显，物料编码和单位选项按 `materialId` 从包含 `materialCode/unitList` 的 `/stock/material/list` 主数据映射补齐，保存后不再逐条调用 `/stock/material/queryById`。实施计划统一通过 `GET /project/process/detail?periodId=...` 读取整份计划，首次保存调用 `/project/process/addBatch`、已有记录调用 `/project/process/editBatch`，第一层同时传计划验收日期及备注。
- 人员配置首次未保存时顶部显示“保存此页”，可邀请/删除允许操作的成员并增删外协；参与人员、外协配置、外协单位与相关字典在一次初始化流程中并行加载并使用请求序号防止旧响应回写，全部完成前禁止外协全量保存。点击保存仅通过 `/project/memberOutsource/editBatch` 全量同步外协配置，成功后按钮变为“修改”，成员与外协统一只读；点击“修改”后才再次解锁。“是否需要外协”默认选否，选是后才展示列表和添加入口，已保存记录非空时回显为是，保存否时提交空 `records` 清空已有外协。成员邀请和删除仍在操作时立即调用成员接口，不进入该保存动作。位置信息改为顶部“保存本页/修改”：新增、修改和删除先更新页面草稿，保存时校验全部位置并通过 `/project/location/editBatch` 一次提交当前分期完整列表（空数组清空）。初始查询读齐全部分页前禁止写入；保存成功并回查后整页只读。未保存的删除也计入脏状态，阻止直接提交审批。
- 每次切换到“人员配置”或“实施计划”时，按当前 `periodId` 重新调用 `GET /project/member/list`；首次进入由子页初始化加载，再次进入分别只刷新参与人员列表或现场负责人选项，不重新加载外协、工序或验收日期，保留未保存草稿。
- 人员配置列表通过 `GET /project/member/list` 加载，并实时读取 `member_role` 字典回显角色名称；邀请弹窗过滤角色 `0/1/2`，分页汇总系统全部用户，项目角色支持多选。点击“提交邀请”立即调用 `POST /project/member/addBatch`；同一用户只提交一条 `records` 明细，多个角色编码放在同一个 `memberRole` 中并使用英文逗号连接，已有角色不重复提交。删除立即调用 `DELETE /project/member/deleteBatch`。邀请状态为 `0=拒绝`、`1=接受`、`2=待接受`，服务端兼容历史空状态。全局登录邀请弹窗暂不挂载，待处理入口统一放在首页“我的待办”；同一账号、同一项目分期的成员邀请只显示一条。被邀请人点击“查看详情”后，页面按 `periodId` 调用 `GET /project/member/list`，筛选当前登录用户的成员记录，拆分 `memberRole` 并通过 `member_role` 显示“我的项目角色”。成员邀请最终通过 `POST /project/member/respond` 同意或拒绝，办理后刷新首页待办。
- 编辑/查看计划不再在每个标签重复展示 `.plan-project-info` 固定信息条；项目基本信息统一通过页面标题旁“详情”按钮打开抽屉查看，抽屉不展示附件内部路径。
- “报价管理”列表路由为 `/plan/material-draft`，新增、修改和查看统一进入固定隐藏页 `/plan/material-draft/editor`。新增选择项目分期后，报价单名称默认填入“主项目名称+报价单”，允许手动修改；切换分期仅更新空名称或原自动名称。新增 query 传 `mode=create&periodId&candidateName`，修改/查看传 `mode=edit|view&periodId&candidateId`，查看模式始终只读；列表可把候选明细导出为 `.xlsx`。报价新增/编辑的选料抽屉在页码旁提供全选本页及取消本页全选，跨页保留已选；已加入报价的物料仍展示，操作列显示“已选择”并禁止重复添加，本次选择按钮保持“选择 / 取消选择”；物料编码仅在悬停名称时以 Tooltip 展示（含已选标签）。同一分期允许创建多份名称不重复的报价候选清单。主表使用 `/project/materialCandidate/list|add|edit`，明细按主表返回的 `candidateId` 使用 `/project/materialCandidateItem/list|addBatch|editBatch`，不再借用 `/project/plan` 或 `/project/materialPlan`，因此不会覆盖编辑计划方案的用料数据。明细仅提交 `id（修改已有行时）、materialId、quantity、unitId、remark`，编码、名称和单位名称由后端生成快照。页面状态直接读取 `project_material_candidate_status` 字典并使用接口原始值：`-1=草稿、0=驳回、1=通过（锁定）、2=待处理、3=已采用、4=已作废`；删除因后端无删除接口而提交状态 `4` 并从列表隐藏。新增主表只提交 `periodId+candidateName`，返回 ID 缺失时按分期和唯一名称反查；保存失败后再次进入同名草稿时复用已有主表，避免重复新增。新增页必须等主表和明细都保存完成后再由 `mode=create` 切换到 `mode=edit`，避免完整 URL 变化导致页面重建并提前读到空明细；切换时携带本次保存快照，新页面用快照回显并使旧查询失效，候选列表短暂未返回新记录时也不清空或退出。普通修改保存继续优先使用明细批量接口返回记录，未返回数组时按 `candidateId` 重新查询，即时查询暂无数据或失败时回显本次提交快照；Alert 在项目信息上方持续显示实际回显结果。新增、修改/提交、审批、作废分别受 `plan:quotation:add|edit|lock|delete` 权限控制；旧 unlock 按钮不再用于任意解锁，查看和导出沿用报价管理菜单访问权限。
- 编辑计划方案的“回款计划”直接复用父页面 `GET /project/contract/queryById` 返回的合同与 `records` 回款明细，不再重复调用合同详情、`/project/paymentRecord/list` 或分期详情；合同类型与回款节点分别使用 `contract_type/payback_node` 字典回显。销售负责人优先使用合同或项目姓名快照，仅在快照缺失时按需调用系统用户和当前分期项目成员作为兜底。合同详情返回合同文件时提供站内弹窗预览，不显示链接和下载；回款表只保留序号、回款项、比例和金额，不显示计划日期及操作列。
- 计划审批仅保留 `project:plan:audit`（计划审批）；旧 `project:plan:approve` 对应已废弃的 `/project/plan/approve`，后台“计划方案审批”旧按钮节点已于 2026-09-09 删除，不再重复配置。
- 项目列表复用同一个计划方案入口：筹备中显示“编辑计划方案”，提交后处于 `PENDING_APPROVAL` 时切换为“查看计划方案”，并通过 `mode=view&periodId=...` 进入六页签只读详情；不额外增加独立查看按钮，查看不依赖计划审批权限。
- 项目列表“计划审批”弹窗底部提供“查看详情/驳回/通过”，不显示“关闭”。查看详情跳转 `/project/plan?mode=view&audit=1&periodId=...`，复用现有计划方案六个页签并强制只读，不单独创建审批详情抽屉；详情页仅在生命周期仍为 `PENDING_APPROVAL`、审批状态为待审批且账号拥有 `project:plan:audit` 时显示“驳回/通过”，办理后返回项目列表并刷新待办。通过更新分期为 `IMPLEMENTING`，驳回更新为 `PREPARING`；当前 `/project/period/status` 契约没有驳回原因字段，弹窗会明示警告原因暂不能持久化，需后端扩展或提供专用审批接口。
- 计划审批通过后至完成实施之前（`IMPLEMENTING/DEBUGGING`，兼容历史 `DEBUG_COMPLETED`），仅项目列表显示受 `project:implement` 控制的“实施完成”，项目详情不再提供该按钮。列表点击后按 `periodId` 调用 `GET /project/process/detail` 打开“确认工序实施进度”抽屉，未开始/进行中的工序均可单选，完成时二次确认并调用 `POST /project/process/status` 传 `{ processId, status: 'COMPLETED' }`；最后一道工序完成后的项目状态由后端自动推进。接口 `processName` 统一按 `work_type` 回显工序名称，工序状态读取 `project_process_status`；抽屉“详情”进入当前项目分期的实施日志页，并自动展开所选工序。
- 当前轮全部工序完成后，按最新业务要求由后端自动进入 `ACCEPTING` 并生成内部/外部验收。列表和详情不再提供提交或开始验收，保留按权限填写结果的验收入口；前端不额外代发提交请求。两类通过后进入质保，失败可申请返工。工序接口文档仍有旧待验收说明，自动流转需后端实测确认。
- 返工管理内嵌在项目详情“验收记录”标签，不新增菜单或路由。返工草稿只维护一条 `process`（名称、负责人、计划起止日期、预计工时、备注）和可空的 `materials` 额外领料计划；审批通过后后端生成普通工序并将分期推进为 `REWORKING`。返工领料沿用 `/material/pick`，携带 `periodId + reworkId`，候选只读取 `GET /project/rework/materials` 的 `availableApplyQty>0` 数据，不混入首次计划。
- `version` 是返工单乐观锁：编辑、提交、撤回、审批均必须使用 `GET /project/rework/queryById` 刚返回的最新值。前端编辑打开时取详情；列表提交、撤回、审批和“保存并提交”在状态动作前再次读取详情，禁止使用列表缓存 version 覆盖并发变更。
- 独立“实施管理”首页以项目分期为一行，通过 `GET /project/project/projectPeriodList` 展示全部项目，不再把每道工序平铺成重复项目行。点击“详情”后以 `periodId` 读取项目分期详情和 `GET /project/process/detail` 的全部工序，在同页按工序分组、懒加载各工序的分页实施日志；日志详情再按 `logId` 调用 `GET /project/implementLog/queryById`。
- 项目列表读取分期字段 `arrivalStatus` 展示“未到货/已到货”。仅 `PENDING_APPROVAL/IMPLEMENTING/DEBUGGING`（兼容历史 `DEBUG_COMPLETED`）且未到货的项目显示受 `project:arrival:confirm` 控制的“确认到货”，实施完成及后续状态隐藏：弹窗按 `periodId` 调用合同详情，使用“到货款”记录的 `rollbackTime` 计算并展示预计回款日期，同时预览 `materialFile` 合同货物清单；确认只调用 `POST /project/period/arrivalStatus` 并传 `{ periodId, arrivalStatus: 1 }`，实际计划回款日期由后端生成。本次调整 PC 入口；移动端需另行同步待计划审批阶段。
- 计划审批通过后，项目列表在 `IMPLEMENTING/DEBUGGING`（兼容历史 `DEBUG_COMPLETED`）状态的“更多”中只显示一个“补料管理”入口，补料申请与审批不再拆成两个抽屉。统一抽屉按账号能力展示“我的申请 / 待我审批 / 审批记录”：普通账号仅查看 `applyUserId=当前用户` 的申请；拥有 `project:materialApply:approve` 的账号才显示待审批、审批记录及单张/批量通过、驳回按钮。新增申请在同一抽屉内切换办理，仍可弹窗预览当前用料清单，并通过 `POST /project/materialApply/addBatch` 提交 `apply+items` 父子结构；物料编码随新增明细提交，并在列表/详情中优先按 `materialId` 从物料主表解析，补料明细快照仅作兜底。待办打开同一抽屉的待审批标签并定位 `bizId` 对应申请；列表明细缺失时展开行再调用 `GET /project/materialApply/queryById`。审批记录使用已处理的申请主单（状态 `0/1`）展示，审批仍按申请单父 ID 调用 `POST /project/materialApply/approve|approveBatch`，不下沉到物料行。当前 `GET /project/materialApply/list` 仅支持 `periodId`，前端做本人视图过滤不等同于服务端安全隔离，后端仍需按当前用户和审批权限落实数据范围。
- PC 与移动端领料申请选择“项目用料”时，页面进入即调用 `GET /project/member/participatedProjects`，传 `periodStatus=IMPLEMENTING,DEBUGGING,DEBUG_COMPLETED,IMPLEMENT_COMPLETED,PENDING_ACCEPT,INTERNAL_ACCEPTING,ACCEPTING,REWORKING`，仅展示当前用户已接受邀请且处于计划审批完成后至验收完成、尚未进入质保的项目分期（`DEBUG_COMPLETED/IMPLEMENT_COMPLETED/INTERNAL_ACCEPTING` 兼容历史数据）。PC 项目选择合并为“项目名称”，支持主项目/分期名称本地模糊搜索，候选左主项目、右分期，以 `periodId` 去重及选取，清空或切换时清空原物料。普通项目领料选中后以 `periodId` 分页查询 `/project/materialAccount/page`；返工领料则固定项目并按 `reworkId` 查询 `/project/rework/materials`。候选物料只保留 `availableApplyQty>0`，申请数量以该基准单位数量为上限。新增和重提均向 `/stock/apply/add|edit` 传有效分期 `periodId`，返工领料额外传 `reworkId`。领料申请头不传 `deptId/deptName/projectName/projectNo/applyUserName`，明细仅传 `materialId/unitQty/unitName`；相关展示字段由后端派生。
- PC 还料申请固定为项目类型：页面进入调用 `GET /project/member/participatedProjects` 获取当前用户已确认参与的全部项目分期，选中后以 `periodId` 分页读取 `GET /project/materialAccount/page`，仅展示 `remainingReturnQty>0` 的待还物料。系统应还数量和默认还料数量都取 `remainingReturnQty`（物料基准单位）；数量可改但不能超过该值，提交数量大于 0 且与系统应还数量不一致时必须逐行填写原因，写入明细 `remark`。新增/重提统一调用 `/stock/apply/add|edit`，固定传 `IN + RETURN + PROJECT + periodId`；项目编号、项目名称、还料人和单价由后端派生，服务端再结合已冻结还料执行最终数量校验。
- 单张申请的“办理出库/入库”弹窗按 `/stock/apply/items` 分页元数据逐页汇总已审批明细并按 ID 去重，再在本地以 30/50 条分页展示；支持搜索、状态筛选、仅看已选、当前页选择、跨页全选和批量填入可执行上限。出库每种物料固定为两行：信息行展示选择、物料信息、申请量 `applyQty（回退 unitQty）`、实时库存 `currentUnitStockQty`、已出 `executedQty` 和待出；操作行只维护本次出库数量与备注。待出量按 `approvedQty（回退 applyQty/unitQty）- executedQty` 计算，本次出库不得超过待出量或实时库存。提交 `POST /stock/apply/execute` 时只发送 `applyId + items`；明细发送 `itemId/executeQty/remark?`，项目还料再发送 `dispositionType`，报废或遗失必须发送 `dispositionRemark`。
- 计划审批弹窗每次打开按 `periodId` 调用 `/project/project/projectPeriodDetail`，项目名称、分期名称和生命周期状态均从真实详情回显，不再读取待办 title/summary 或假定状态；加载失败提供重试且禁用查看/审批，关闭或切换时旧响应失效。
- `PROJECT_PERIOD_APPROVAL` 待办点击“查看详情”打开现有计划审批弹窗；优先使用 `actionParams.periodId`，缺失时仅该类型按契约以 `bizId` 作为分期 ID。待办接收权限 `project:period:approve` 与现有计划办理权限分别遵循各自契约，不因入口映射修改授权。
- 待办不再配置独立菜单或 `/todo/list` 页面，统一放在首页“我的待办”卡片中。每条一行依次显示待办类型、接口原始 `summary`、申请时间和“查看详情”；不显示 `title`，`summary` 为空时显示“—”，不展示 `ASSIGNED/CLAIMABLE` 范围文案。办理入口由 `todoType/bizId/bizSubId/actionKey/actionParams` 决定：补料、成员邀请、合同、计划沿用现有入口，`PROJECT_INTERNAL_ACCEPTANCE/PROJECT_EXTERNAL_ACCEPTANCE` 打开对应项目“验收记录”标签。类型标签读取 `todo_type`，未知值保留原编码；`/sys/todo/*` 只查询待办，实际办理仍调用来源业务接口。
- 项目详情右侧“项目动态”通过 `GET /project/dynamic/list` 倒序展示，每条同时显示 `actionContent`、`operatorName` 与 `operateTime`；动态区域限制为视口内高度并独立纵向滚动，窄屏下改为固定高度滚动。
- 项目详情的项目类型、业务属性、涉及产品、方案类型、成员角色和用料采购状态均按对应字典显示名称；多选编码逐项映射后用顿号连接，未知字典值才回退显示原始值。
- 人员配置的外协单位下拉调用 `/project/outsourcingUnit/list` 加载启用单位，选择后同步单位类型、联系人和联系电话；同一分期的外协配置按 `unitId` 排除其他行已选单位并在保存前校验，禁止重复选择同一外协单位。选择需要外协后至少维护 1 条配置，每条人数至少为 1 人，工时不得小于 0。外协单位实体与表单统一使用 `unitType`，字典 `outsourcing_type` 为 `0=个人`、`1=企业`。
- “实施计划”的工序名称按 `work_type` 字典值排除其他行已选工序并在保存前拦截重复；现场负责人仅从当前分期已接受邀请（`inviteStatus=1`）的项目成员中选择，按用户 ID 去重。每条工序的名称、现场负责人、计划开始时间和计划完成时间必填，完成时间不得早于开始时间；计划工时根据起止日期自动计算，计划验收日期必填并从 `GET /project/process/detail` 的 `plannedAcceptanceDate` 回显。工序列表统一过滤接口或父组件回填中的空记录，日期汇总、工时计算和保存校验均兼容空数据，避免读取空工序的 `startTime/endTime`。方案文件列垂直居中，位置信息的实施位置列加宽。
- 物料基本维护的列表、新增/编辑表单和搜索统一使用 `material_brand` 字典；列表把接口 `brand` 编码转为品牌名称，字典未命中时才显示原值。
- 可编辑明细表统一使用 `src/components/EditableTable/` 的名称唯一选择和按行校验能力：其他行已经选择的名称不再出现在当前行选项中，当前行原值继续回显，选项耗尽后禁用新增；行内名称选定后校验该业务声明的全部必填项，提交前再次拦截重复和无效值。当前已覆盖合同回款、实施工序、外协配置、物料单位，以及共享选料抽屉及其计划用料、报价、物料申请、领料和采购明细；允许重复的方案类型等字段不套用唯一规则。
- 用料计划的“选择物料”抽屉默认按全部分类分页展示物料库，保留搜索和分类筛选；已加入当前计划（含尚未保存的行）的物料继续显示为“已选择”，禁止重复添加。新选物料可取消，跨页选择继续保留；从计划移除后重新打开抽屉即可再次选择。该显示模式仅用于计划用料，其他业务选料行为保持原有规则。
- 编辑计划方案的用料单位按物料详情 `unitList` 下拉选择并优先基础单位；工序表底部按“最晚计划完成日期 − 最早计划开始日期”× `8h` 显示总工时；实施位置地图弹窗确认后必须同步选点并主动关闭，不能停留在未确认状态。

### 5.3 合同与回款接口

列表验收入口：`src/views/project/components/AcceptanceModal.vue` 在项目列表 `ACCEPTING` 操作栏打开，重新读取分期详情核验状态/权限，复用 `DetailAcceptance.vue` 的权限过滤表单；完成后关闭并刷新列表。`project:internalAccept` 办理内验，`project:accept` 且本项目经理办理外验。提交人姓名通过完成接口 `acceptUnitLeader` 与报告、结果一起保存，不再手动开始验收。

项目详情验收记录：内部/外部卡片办理时可选择验收日期，保存资料通过 `acceptDate` 保留选择，完成验收将所选日期按当天零点传入 `acceptEndDate`，不再固定使用提交时刻；日期必选。已完成卡片及历史表只读显示 `acceptEndDate`（年月日），空值显示“—”。

实施记录详情（`src/views/implement/detail/index.vue`）不显示实施日期，位置读取 `implementLocationName` 并与内容上下分行；工时优先 `hours`，空值时显示注明来源的打卡时长。日志提交人与所属工序现场负责人相同才展示参与人员信息和实际外协记录，名称按分期成员/外协配置补齐，不展示整项目人员作为本次参与者。

合同新增、修改及审批前保存项目经理时，`contract.salesUserId/salesUserName` 始终成对传递，姓名从所选用户解析，不能因未修改而从差量请求省略；其余可编辑合同字段继续差量提交。当前 Apifox 字段为 `salesUserName`，不是 `saleName`。

| 用途               | 方法与路径                                      |
| ------------------ | ----------------------------------------------- |
| 合同列表           | `GET /project/contract/list`                    |
| 合同详情           | `GET /project/contract/queryById`               |
| 新增合同及回款计划 | `POST /project/contract/addWithPaymentRecords`  |
| 修改合同及回款计划 | `POST /project/contract/editWithPaymentRecords` |
| 合同编辑（已废弃） | `POST /project/contract/edit`                   |
| 回款计划列表       | `GET /project/paymentRecord/list`               |
| 回款计划批量新增   | `POST /project/paymentRecord/addBatch`          |
| 回款计划全量同步   | `POST /project/paymentRecord/editBatch`         |
| 回款计划批量删除   | `DELETE /project/paymentRecord/deleteBatch`     |
| 项目分期状态更新   | `POST /project/period/status`                   |

合同信息页将接口字段 `contractAmount` 显示为“项目金额”；`plannedDeliveryDate`（计划交付日期）、项目金额与 `warrantyPeriod`（质保期）均为必填，质保期只允许输入大于等于 0 的整数。历史待审批合同缺少计划交付日期时不能直接审批通过，应驳回补充后重新提交。回款金额使用 `big.js` 按“项目金额 × 比例 ÷ 100”计算并保留两位；提交前要求回款比例合计精确等于 100%。合同信息回款计划的“回款周期”映射接口字段 `rollbackTime`，表示阶段任务完成后回款的周期；新增行默认 7 天，比例和周期均使用数字输入，比例限制为 0～100，周期必须为大于等于 0 的整数，旧记录缺失该字段时也按 7 天回显。合同详情以必填 `periodId` 一次返回合同、两个文件记录和回款计划；新增/修改均使用 multipart 组合接口，修改时 `contract.periodId` 必传，其他合同字段只传变化项，`records` 全量同步。
