# 休息与转派：双端页面与后端配合

2026-10-29：本期为可交互页面预览，全部人员、工单、负载、休息冲突均为标注的示例。无业务写请求、无持久化。不是实际休息登记或已完成转单。

## 入口和操作

- PC：运维值班表列表 → 休息与转派，复用值班表编辑按钮权限控制预览入口。
- 移动端：主管维修列表 → 休息与转派，复用现有 canManage 控制预览入口。普通维修人员不因此获得主管转派权限。
- 选择指定日期、人员、开始结束时间；上午/下午/全天快捷选择，也可自定义。
- 查看受影响维修单，逐单指定接收人，或勾选多单后统一指定；可分批指定不同人员。
- 执行中的单独提示，不参加批量转派；存在执行中记录时不允许确认休息预览。
- 原人员和示例休息人员不出现在接收人候选。修改日期/人员/时段清空旧查询与指定结果，需重新查询。
- 预览确认结果列出安排与每单接收人，明确未保存。当前时段为同一天，按开始包含、结束不包含筛选示例工单。

## 已核对的正式接口

已刷新 Apifox 项目8679942：GET /operation/dutyRoster/queryByDate 支持 date=yyyy-MM-dd，返回 dayUsers/nightUsers/restUsers，可用于正式版本展示当天排班，但不返回临时休息记录或受影响维修单。

POST /repair/transfer/submit 仅当前负责人提交 targetUserId/reason，运维主管审批后生效，不能作为主管直接批量转派接口。当前没有调用此接口代办，更没有绕过审批。

## 后端需要补充（接口名称待定）

1. **主管权限与人员选项**：后端返回可管理人员范围、可设置休息/可转派能力；双端统一正式权限码，不以PC值班表编辑权限直接授权真实转派。
2. **日期与人员安排查询**：白班、夜班、已有临时休息起止和备注。休息记录具有ID、状态、创建更新信息；后续支持查看记录/取消，避免只建不查。
3. **受影响单预览**：传 userId、startAt、endAt；服务端筛选自动派单、当前有效负责人、预计执行时间冲突的工单，返回待转/执行中/不可转原因、版本或预览标识。缺少预计执行时间必须返回待处理原因，不能默默漏掉。
4. **接收人候选**：按每张工单及执行时间查询可接人员，返回休息冲突、排班、待处理量；不同工单可有不同候选，不使用客户端示例的统一名单作正式校验。
5. **确认休息并转派**：传休息范围、备注及 assignments[{orderId,targetUserId}]，支持单单或多单。建议原子事务、幂等requestId和版本校验；发现新增受影响单、工单已执行或候选失效时明确返回冲突，整体失败且保留前端选择，不允许静默部分成功。
6. **自动派单避让**：休息时段生效后，新派单也要排除对应人员；与确认接口协调并发，避免查询后新增工单被遗漏。休息与派单时间均按北京时间解释。
7. **审计与通知**：记录原负责人、新负责人、主管、原因和时间；新负责人待办与旧负责人权限同事务变更，完成通知与业务历史可追溯。

主管确认直接生效还是走审批需要确认正式业务契约。现有负责人发起的转单审批保持原样，本预览不改变它。

专项覆盖时段边界、非法接收人排除、执行中拦截、双端模型一致与SFC编译；PC定向ESLint通过。未提交真实休息/转派，未进行移动真机验收。
