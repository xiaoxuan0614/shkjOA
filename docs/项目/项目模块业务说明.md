# 项目模块业务说明

> 更新：2026-08-25（附件单文件替换规则与站内内容预览）
>
> 接口文档：https://s.apifox.cn/ffb89e1a-f7ea-4dd5-99ae-e8365679dc0c

## 一、模块定位

项目模块覆盖：**项目管理**（主项目+分期）、**计划方案**、**实施管理**（工序/实施记录/参与人员/施工打卡/工期延期）、**项目成员/实施位置/项目文件/项目动态/用料计划**、**验收管理**（内部验收 + 客户验收并行）、**合同管理/回款**。

后端以「**项目(project) — 分期(period)**」两级结构组织：主项目下挂多个分期，**所有子表（计划/成员/位置/实施/验收/文件/用料/动态）都挂在分期(periodId)上**。

## 二、角色 × 页面

| 角色       | 页面                                 | 职责                                   |
| ---------- | ------------------------------------ | -------------------------------------- |
| 项目对接人 | 项目管理/项目详情                    | 创建项目；创建后从详情修改项目基本信息 |
| 合同审批人 | 项目管理                             | 审批合同；通过时指定项目经理           |
| 项目经理   | 编辑计划方案                         | 编写、保存并提交后续项目计划           |
| 实施人员   | 项目详情-实施记录/实施位置/成员/文件 | 查看/维护实施维度数据                  |
| 项目经理   | 项目详情-验收记录                    | 录入内部验收、客户验收（上传验收报告） |
| 财务       | 回款管理(合同)                       | 合同信息、已回款金额                   |

## 三、项目生命周期（状态流转）

```
未开始 ──合同提交──> 合同待审核（2） ──审批通过（1）+指定项目经理──> 筹备中 ──计划提交审批──> 待立项
待立项 ──审批通过──> 实施中 ──实施完成──> 验收阶段
验收阶段：内部验收与客户验收并行；客户验收通过后可进入质保
质保中 ──质保结束──> 完结
任意允许关闭的状态 ──关闭审批──> 关闭（例外终态）
```

- 合同提交后，项目列表的同一“合同信息”入口进入只读详情：审批权限人可通过/驳回，原提交人可撤回；驳回详情展示原因，驳回或撤回后由原提交人修改并重新提交；通过时指定项目经理，项目进入筹备中，列表入口随即隐藏，后续从项目详情查看。
- 合同待审核只读详情将合同类型和回款项编码转换为字典名称；项目经理姓名支持按用户 ID 补齐，已上传的合同附件与合同物料清单可在站内弹窗查看文件内容。
- 已有合同修改并重新提交时调用 `editWithPaymentRecords`，项目分期 ID 必传；合同字段仅提交变化项，回款计划全量同步，修改成功后转为待审核。合同审批通过前写入项目经理也使用该组合接口并携带当前完整回款计划，再调用合同状态接口审批通过；前端不再调用已停用的 `/project/contract/edit`。回款管理列表的“编辑”统一进入正式合同编辑页。
- 合同回款计划增加“回款周期”，表头提示其含义为“阶段任务完成后回款的周期”；新增款项默认 7 天，可修改为大于等于 0 的整数，使用每条回款记录的 `rollbackTime` 随合同组合新增/修改接口保存。旧记录没有该字段时按 7 天显示。
- 合同审批通过或项目处于筹备中时，项目列表直接显示“编辑计划方案”操作，不收进“更多”。
- 项目列表的对接人姓名优先使用列表姓名快照或用户 ID 反查；仍缺失时按当前分期补查项目详情，避免列表留空。
- 新增项目、已有主项目新增分期及编辑项目的附件改为随项目保存接口组合提交：multipart 的 `data` 为业务 JSON 字符串，`attachment` 为单个可选文件，不预调用公共上传接口，也不在 JSON 中传 `attachmentFileId`。编辑不选新附件时保留旧文件，选择后由后端替换；允许 Word、PPT、Excel、PDF 和图片，页面移除表单上方重复的“基本信息”标题。
- “编辑/查看计划方案”页面标题旁显示“详情”，在当前计划页打开项目基本信息抽屉；抽屉展示主项目、分期与对接、实施信息。
- 计划页标签由“方案文件管理”改为“方案文件”，按项目分期 ID 读取 `/project/plan/list`，仅展示计划方案记录，不显示合同附件或 `CONTRACT_MATERIAL_DRAFT` 合同用料草稿。新增行点击“保存”时调用 multipart `/project/plan/add`，将该行数据放入 `data`、本地文件放入 `attachment`；已有行保存使用 `/project/plan/edit`。保存成功后名称、类型、文件和备注统一锁定，操作栏切换为“修改”，点击后才恢复编辑；文件选择只显示普通文件完成图标，实际上传发生在保存时。
- 项目基本信息附件使用 `addProjectPeriod/editProjectPeriod` 的 `attachment` part 组合提交；合同附件和合同物料文件分别随合同新增/修改组合接口的 `attachment/materialAttachment` part 提交。合同页选择时仅本地回显，不再预调用统一上传；未选择新文件时保留原文件。
- 每个附件上传入口默认只保留一个文件且不允许多选；文件存在时隐藏上传按钮，必须先删除当前文件再选择替换文件。已选择和已提交的图片、PDF、DOCX、XLS/XLSX、PPTX 都在站内弹窗预览；项目详情文件的已提交删除仅向项目对接人或项目经理开放，计划、合同、项目和验收附件按所在页面编辑权限开放删除。
- 人员配置列表调用 `/project/member/list`，实时读取 `member_role` 字典并将 `memberRole` 回显为名称。邀请弹窗过滤角色 `0/1/2`，成员通过 `/sys/user/list` 汇总全部分页并在打开弹窗时刷新；项目角色支持多选，点击“提交邀请”立即通过 `/project/member/addBatch` 按同一用户的多个角色发出邀请，已存在的用户角色组合不重复提交。成员删除立即调用 `/project/member/deleteBatch`，不等待外协配置保存。
- 计划页六个标签不再重复显示固定项目基本信息条；项目基本信息统一从页面标题旁“详情”按钮打开抽屉查看，抽屉不展示附件内部路径。项目分期详情与合同详情仍独立加载，单个接口失败不阻断整个页面。
- 编辑计划方案不提供“保存全部”；“提交审批”只通过 `/project/period/status` 把当前分期更新为 `PENDING_APPROVAL`，不会代替用户保存任何页签数据。
- 用料计划和实施计划顶部按钮在“保存本页/修改”之间切换：已有记录默认只读，空列表直接编辑；保存成功后刷新并锁定。用料计划支持导入 `.xlsx`（按物料编码匹配物料库）或选择当前分期状态为 `1` 的已锁定报价，导入只修改页面草稿，点击保存本页后才提交。人员配置顶部“修改/保存本页”只编辑和批量提交外协配置，与成员邀请、删除无关。位置信息仍由列表每行单独“保存/修改”；保存成功后该行锁定只读，修改前必须先解锁。由于位置接口为分期全量同步，行保存以已落库快照为基线，仅替换当前行，其他未保存行仍保留在前端；单条保存仅提示当前行保存成功，不展示接口默认的“批量修改成功”。
- 报价管理使用项目用料候选清单主子表独立维护报价物料，不再与计划方案“用料计划”共用数据。列表展示主项目、分期、报价单名称、分期 ID、最后更新人和报价状态；同一分期可创建多份名称不重复的报价。新增通过 `/plan/material-draft/editor?mode=create&periodId=...&candidateName=...`，首次保存主表只提交 `periodId+candidateName`，取得 `candidateId` 后批量新增物料；修改通过 `mode=edit&periodId=...&candidateId=...` 精确回显；查看详情使用 `mode=view` 并强制只读。列表导出读取候选明细并由前端生成 `.xlsx`。状态直接按 `project_material_candidate_status` 回显：`0` 草稿可修改和删除，`1` 已提交、`2` 已采用只读，`1` 可由专用解锁权限恢复为草稿；草稿删除使用状态 `3`。新增响应未直接返回 ID 时按分期和唯一名称反查，已有同名草稿则作为未完成保存继续维护。
- 项目邀请接收端调用 `GET /project/member/myInvitations` 获取当前用户的待处理邀请，调用 `POST /project/member/respond` 并传 `memberId/inviteStatus` 办理（`1=同意`、`0=拒绝`）。登录弹窗、首页“我的待办”和站内待办列表共用前端邀请状态；点击“办理”打开项目基本信息抽屉并支持同意、拒绝，成功后三处同步移除。接口只返回成员邀请实体，项目/分期名称和项目经理姓名按唯一 `periodId` 补查项目与合同详情。
- 编辑计划方案的“回款计划”只读展示当前分期合同：按 `periodId` 查询唯一合同，合同类型匹配 `contract_type` 字典名称；销售负责人优先读取合同姓名快照，并兼容字段别名和嵌套用户对象，仍缺失时依次按负责人 ID、项目分期详情、合同创建账号 `createBy` 和当前分期 `memberRole=1` 的项目成员补齐。合同文件提供站内弹窗预览，不显示链接或下载；回款明细不显示计划日期和操作列。
- 待立项项目的“计划审批”弹窗底部为“查看详情/驳回/通过”，不显示关闭按钮。查看详情跳转现有计划方案页面，以 `mode=view` 强制只读查看方案文件、用料计划、人员配置、实施计划、位置信息和回款计划；审批通过和驳回仍在计划审批弹窗办理。
- 项目详情右栏按时间倒序展示项目动态，每条显示动态内容、操作人 `operatorName` 和操作时间；列表在桌面端按视口高度、窄屏按固定高度独立滚动，避免动态过多拉长整个详情页。
- “实施计划”根据全部工序的最早计划开始日期和最晚计划完成日期计算跨度总工时：自然日差 × `8h`；每条工序的计划工时也按本行起止日期自动计算。现场负责人仅可选已接受邀请的项目成员并按用户 ID 去重，计划验收日期必填。“实施位置”地图确认后回填位置名称、经纬度和描述，并关闭选点弹窗；位置列加宽展示完整地址。
- 当前页面统一通过项目分期状态接口推进，前端按钮按当前状态和权限码显示，后端负责校验不可跳步。
- **验收阶段 = 内部验收 + 客户验收并行**：谁先谁后无所谓；两者分别记录和上传报告，客户验收通过后可进入质保。
- 状态码以 `project_period_status` 字典和后端接口为准。

## 五、验收阶段（核心概念）

内部验收与客户验收**同时进行、不分先后**，均为验收阶段的一部分，分别记录、分别上传验收报告：

| 维度      | 内部验收 `project_internal_acceptance` | 客户验收 `project_acceptance`                                            |
| --------- | -------------------------------------- | ------------------------------------------------------------------------ |
| 负责人    | `acceptLeaderId/acceptLeaderName`      | `acceptLeaderId/acceptLeaderName`、`acceptUnitLeader/acceptUnitPhone`    |
| 日期      | `acceptDate`、`implementCompleteDate`  | `acceptDate`、`implementCompleteDate`                                    |
| 验收报告  | `reportFileId`（必传）                 | `completionReportFileId`(竣工报告，必传)、`acceptanceFormFileId`(验收单) |
| 结果/备注 | `result`、`remark`                     | `result`、`remark`                                                       |

详见 [验收阶段设计.md](验收阶段设计.md)。
