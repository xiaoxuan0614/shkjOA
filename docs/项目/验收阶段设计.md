# 验收阶段设计（内部验收 + 客户验收 并行）

> 2026-08-16。目标：把「验收」从线性流程改为**一个验收阶段内的两条并行子流程**。

## 一、背景（为什么改）

旧设计（mock 阶段）：`实施完成 → 内部验收 → 客户验收 → 质保中`，严格线性、跳步报错、内部验收只传照片、客户验收只读。

新需求：
1. **内部验收 与 客户验收 同步进行** —— 都属于「验收阶段」；
2. **谁先谁后无所谓** —— 没有强制顺序；
3. **都需要上传验收报告**；
4. **客户验收通过 → 进入质保期**。

## 二、模型

```
实施完成 ──进入内部验收(internalAccept)──> 内部验收中
实施完成 ──进入客户验收(accept)────────> 客户验收中
内部验收中 ──内部验收完成(internalAcceptComplete)──> 待客户验收
客户验收中 ──客户验收完成(acceptComplete)─────────> 待内部验收/待进入质保
   两个验收记录都有结果 ──进入质保(warranty)──> 质保中 ──项目完结(complete)──> 完结
```

- 验收阶段内，**内部验收和客户验收可任意切换进入**（前端两个按钮都提供）。
- 客户验收记录保存后（`result` 非空），详情页头部额外显示「进入质保」按钮（`customerAcceptDone` 判定）。
- 后端负责校验顺序合法性（进入质保前要求验收记录齐全等）。

## 三、页面实现（项目详情 → 验收记录 tab）

[DetailAcceptance.vue](../src/views/project/detail/components/DetailAcceptance.vue)：

- **左右两个卡片**：内部验收、客户验收，各自独立表单 + 保存按钮；
- 打开时分别拉取 `GET /project/internalAcceptance/list`、`GET /project/acceptance/list`（periodId，取最近一条）——有记录则编辑回显，无记录则新增；
- 保存：有 `id` 走 `POST /edit`，无 `id` 走 `POST /add`；
- **验收报告必传**：内部验收 `reportFileId`、客户验收 `completionReportFileId` 未上传时拦截保存；
- 报告上传：`JUploadButton` + `/sys/common/upload`，返回路径存入 fileId 字段（`fileId` 语义待与后端确认）。

## 四、状态流转按钮

[Project.data.ts](../src/views/project/Project.data.ts) `statusFlow` 定义各状态可用动作；[detail/index.vue](../src/views/project/detail/index.vue) 在验收阶段内且客户验收已完成时，动态追加「进入质保」。

| 当前状态 | 可用动作 | 说明 |
| --- | --- | --- |
| `NOT_STARTED` 未开始 | 开始实施 | |
| `IMPLEMENTING` 实施中 | 调试完成 / 完成实施 | |
| `DEBUG_COMPLETED` 调试完成 | 完成实施 | |
| `IMPLEMENT_COMPLETED` 实施完成 | 进入内部验收 / 进入客户验收 | **并行入口** |
| `INTERNAL_ACCEPTING` 内部验收中 | 内部验收完成 / 进入客户验收 | 可切客户验收 |
| `ACCEPTING` 客户验收中 | 客户验收完成 / 进入内部验收 | 可切内部验收 |
| 验收阶段内 + 客户验收完成 | 进入质保 | 动态追加 |
| `WARRANTY` 质保中 | 项目完结 | |
| `COMPLETED`/`CLOSED` | 无 | 终态 |

## 五、待后端确认

2. 验收报告 `reportFileId`/`completionReportFileId` 字段：存文件ID还是URL？
3. `acceptComplete`(客户验收完成) 后 status 实际值（决定「进入质保」按钮在前端的触发条件是否需要更精确）。
