# 物料管理模块 - 逻辑总结

## 出入库用途分流与前端权限（2026-09-10）

项目领料 OUT+PROJECT 新增及重提由后端免审批放行，主单/明细 status=1、executeStatus=PENDING；前端显示“免审批·待出库/部分出库/已出库”，不提供库管确认或驳回。维修/劳保领料由申请部门的有效负责人审批；前端要求 `mtl:apply:approve`、身份为上级、负责部门包含申请 deptId。单张及批量执行要求 `mtl:goods:io`、status=1、执行状态为 PENDING/PARTIAL_EXECUTED。实际出库身份与部门审批范围由后端最终校验，提交和审批都不扣库存。入库保持原审批流程。

单张审批、批量审批、执行弹窗和 STOCK_OUT_APPROVAL/STOCK_OUT_EXECUTE 待办使用共同门禁；待办按 actionParams.applyId 取最新详情。统一审批请求只传 applyId、approvalResult、approvalComment，不传已不在当前契约内的 approvalUserId。

契约边界：当前后端禁止已通过申请撤回/编辑/删除；旧 status=2 项目申请不自动迁移，当前前端按新要求不提供项目审批按钮，需后端确认历史数据处置，不能直接前端改状态。本次未执行库存变更、历史数据迁移或正式角色授权，部门领导角色尚待明确。


## 2026-09-09 领料类型范围

- 项目用料：仅项目可申请清单，沿用 `availableApplyQty` 上限。
- 维修：手填必填维修单号，可选全物料，前端字段暂按 `repairOrderNo`。

## 二、物料基本维护（goods）

- 物料 CRUD + **单位子表**：第一行即基准单位（换算系数固定 1，不可移动/删除），副单位填换算系数；**单位下拉统一走数据字典 `inv_unit`**（`material.util::loadUnitOptions`），其他行已选单位不再显示，所有单位用完后禁用添加，提交前再次校验单位唯一和换算系数必填。
- 列表“品牌”使用 `material_brand` 字典将接口 `brand` 编码转为名称，字典未命中时才回退显示原值；新增、编辑和搜索使用同一字典。
- **物料编码后端生成**：新增时隐藏，创建后只读展示（编号显示规则）。其它业务记录统一按 `materialId` 从物料主表解析 `materialCode`，业务快照仅作兜底；物料变更后清理映射缓存，避免继续显示旧编码。
- 新增/编辑：`unitPrice`（基准单价）、`stockQty`（初始库存）**未填默认 0，始终上送**；编辑不传 `version`。
- 行操作含手动出入库（`IOModal` → `/stock/ioRecord/manualIn|manualOut`）。
- 导入/导出走 `JImportModal`（下载模板在弹窗内）。

## 三、库存管理（stock）

- 库存总览（按基准单位显示库存数量/金额）。
- 行操作：**出入库**（手动入库/出库，生成台账）、**盘存**（`POST /stock/ioRecord/takeStock`，按实际盘点数量留痕）。

## 四、盘存记录（stocktake）

- 固定按 `sourceType=stocktake` 过滤 `/stock/ioRecord/list`。
- 差异 = 盘点后 − 盘点前（正=盘盈绿 / 负=盘亏红），物料编码/名称按 `materialId` 从刷新后的物料主表映射富化。

## 五、出入库管理（record）

两条 tab：**出入库申请** + **台账**。

- 出入库申请列表不展示 `projectNo` 对应的“关联单号”列，仅保留项目名称；搜索表单仍可按关联单号筛选，申请详情和提交字段也保持不变。

### 5.1 申请创建

- 三种入口：领料申请（`/material/pick`）、还料申请（`/material/return`）、物料申请（`/material/apply`）。
- 领料申请必选领料类型：项目用料（`PROJECT`）、维修用料（`MAINTENANCE`）、劳保用品领取（`LABOR_PROTECTION`）。三类均提交 `applyType=OUT`、`bizType=PICK` 和对应 `usageType`。
- 项目用料通过“项目名称”选择分期：页面进入读取 `/project/member/participatedProjects`，传 `periodStatus=IMPLEMENTING,DEBUGGING,DEBUG_COMPLETED,IMPLEMENT_COMPLETED,PENDING_ACCEPT,INTERNAL_ACCEPTING,ACCEPTING,REWORKING`，只展示当前用户已接受邀请且处于计划审批完成后至验收完成、尚未进入质保的参与项目（`DEBUG_COMPLETED` 兼容历史数据），候选只按主项目名称或分期名称在接口返回结果中模糊搜索，下拉左侧显示主项目、右侧显示分期，不显示编号或 ID；选择值及去重键统一为 `periodId`。切换或清空项目时清空原物料明细。编辑时回填主项目/分期名称，不在可领料范围的原项目仅用于回显，需重新选择后才能提交；返工项目保持锁定。选中后按 `periodId` 分页读取 `/project/materialAccount/page`，抽屉以 `keyword` 搜索编码、名称、品牌或型号，不读取 `/project/materialPlan/list`，也不为项目候选加载 `/stock/material/list`。候选和明细显示 `availableApplyQty` 当前可申请数量，数量为 0 时不进入候选列表，申请数量不得超过该值，单位使用 `baseUnitName`；全选只处理当前页可申请且未加入明细的物料。物料名称与编码同行展示，明细可逐条删除。新增和重提均提交有效分期 `periodId`；`projectNo/projectName` 由后端派生且不进入提交体。
- 维修用料和劳保用品领取不显示、不提交项目字段，选料范围为 `/stock/material/list` 全部物料。切换类型或分期会清空当前明细，避免来源混用。
- 还料页固定为项目类型：进入页面调用 `/project/member/participatedProjects`，仅展示当前登录用户已确认参与的项目分期；选择后按 `periodId` 分页调用 `/project/materialAccount/page`，过滤 `remainingReturnQty>0` 的待还物料。该值按基准单位显示为系统应还数量并默认回填本次还料数量，允许在 `0～系统应还数量` 内修改；提交数量大于 0 且与系统应还不一致时，逐行差异原因必填并提交到明细 `remark`。
- 项目还料新增/重提统一调用 `/stock/apply/add|edit`，固定提交 `applyType=IN`、`bizType=RETURN`、`usageType=PROJECT`、`periodId` 和数量大于 0 的 `itemList`；`projectNo/projectName/returnUser/unitPrice` 由后端按分期和当前用户派生。前端不再调用未在当前 Apifox 声明的 `/stock/apply/returnList`，也不再使用本地还料示例兜底。
- 领料申请头不传 `deptId/deptName/projectName/projectNo/applyUserName`；领料 `itemList` 每项只传 `materialId/unitQty/unitName`。页面显示所需的名称、编码、类别、品牌和型号不回传给领料接口。
- 旧“物料申请”兼容入口同样用显式白名单组装 `/stock/apply/add` 请求，不回传申请人、部门或项目展示字段，`itemList` 仅含 `materialId/unitQty/unitName`；还料按独立契约保留差异原因等专用明细。
- 非项目领料明细的“库存”列展示 `currentStockQty + baseUnitName`（如 `1个`）；项目领料用“当前可申请数量”替代库存列。
- 共用选料抽屉和领料明细的“品牌”都按 `material_brand` 字典回显名称，筛选使用名称、提交保留原始品牌值，未命中字典时显示原值。
- 物料申请、领料和采购共用的选料抽屉接收当前明细物料 ID；项目领料再次打开时保留该记录并标记“已添加”，其他来源继续排除已加入物料。提交时仍逐行校验物料唯一，以及数量、单位等业务必填项。

### 5.2 审批（整单审批）

- 申请主表与明细 `status` 统一为 `-1=待提交`、`0=驳回`、`1=审核通过`、`2=待审批`、`3=已撤回`；列表与详情均使用公共五态转换，不读取状态字典。
- **只有「待审批(2)」显示「审批」按钮**。
- 审批弹窗：申请明细**只读展示**（整单审批，无逐条概念）；审批结果单选 **整单通过 / 整单驳回**，**驳回必填审批备注**（驳回原因）。
- 提交：整单通过 `approveApply({applyId, approvalUserId, approvalResult:'AGREE', approvalComment})`、整单驳回 `rejectApply({...REJECT, approvalComment})`，**不带明细 items**。这里的 `AGREE/REJECT` 是 Apifox 明确规定的审批动作参数，不是申请状态码。

### 5.3 执行出入库

- 「审核通过(1)」→ 出库(领料) / 入库(还料/采购)，明细也仅执行 `status=1` 的记录；统一五态不再包含“部分通过”。
- **出库/入库按钮展示条件一致**，均按执行状态区分：仅「待执行(PENDING)/部分执行(PARTIAL_EXECUTED)」(`executeStatus`) 显示对应按钮，执行完不再显示。
- 单张申请执行弹窗按 `GET /stock/apply/items` 返回的 `pages/current/total` 逐页加载全部明细并按 `id` 去重，只保留 `status=1` 的已审批项；界面以 30/50 条本地分页展示，支持搜索、待执行/已完成筛选、仅看已选、当前页选择、跨页全选筛选结果及批量填入可执行上限。出库明细每种物料使用两行：第一行展示选择、物料、申请量、库存、已出和待出，第二行集中填写本次出库数量与备注；申请量取 `applyQty`，为空回退 `unitQty`。跨页操作保留同一行对象，换页或筛选不清空已选数量和备注。
- 每行剩余可执行量取 `approvedQty（回退 applyQty/unitQty）- executedQty`。出库展示所选单位实时库存 `currentUnitStockQty`，本次出库数不得超过剩余量或实时库存；没有库存字段时仍由后端做最终库存校验。
- 执行弹窗调用 `POST /stock/apply/execute`，请求为 `{applyId, items:[{itemId, executeQty, remark?, dispositionType?, dispositionRemark?}]}`，不重复传 `itemIds`；只有 `IN + RETURN + PROJECT` 的项目还料逐项提交 `RESTOCK/SCRAP/LOST`，报废和遗失原因必填。**执行人由后端从登录 token 取**，明细记录 `executeUserId/executeUserName`。
- 明细「执行人」列展示执行出入库的经办人（后端 `executeUserName`）。

### 5.4 申请人动作

- **待提交/已撤回/已驳回 → 可「修改」** 跳回申请页（`?applyId=`）改数量后重新提交，重新提交固定传 `status=2`。
- 待审批可「撤回」（`2→3`）；**已驳回不可删除**；删除仅限待提交或已撤回。

### 5.5 台账

- 出入库记录（`/stock/ioRecord/list`），行操作「详情」弹窗展示该条记录涉及的全部物料详情（物料主表 + 单位换算 + 本次变动）。
- 台账来源/类型标签走字典 `stock_io_source_type` / `stock_io_type`。
- 项目详情“用料统计”不读取计划表，按分期 `periodId` 调用 `/project/materialAccount/page`，以服务端搜索和 20/50/100 分页展示计划、申请占用、出库、施工消耗、归还处置、库存和成本的聚合结果；数量统一使用总账返回的 `baseUnitName`。

## 六、采购入库（purchase）— 状态机

| 状态     | 行操作                                       | 目标                    |
| -------- | -------------------------------------------- | ----------------------- |
| 1 待采购 | 修改 / **确认采购** / 关闭                   | →2                      |
| 2 采购中 | **采购完成** / 关闭                          | →3                      |
| 3 已到货 | **开始入库** / 关闭                          | →4                      |
| 4 入库中 | **入库**（逐物料实际入库数量）/ **入库完成** | 入库后仍 4；入库完成 →5 |
| 5 已完成 | —                                            |                         |
| 0 关闭   | —                                            |                         |

- 状态切换走 **`POST /project/purchaseOrder/status`（`{orderId, status}`）**，不再用 editOrder 改状态。
- **列表筛选**：搜索表单含 采购单号(orderNo 输入)/供应商(supplierName)/分期项目(periodName)/状态(status 字典)。供应商与分期下拉同弹窗一致——主页面渲染预载第 1 页、输入后服务端模糊查询（`/project/supplier/list`、`/project/period/searchByName`），查询参数按实体字段名上送。
- **入库**：`StockInModal` 逐物料填 `inboundQty`，调 **`POST /project/purchaseOrder/inbound`**（`{orderId, items:[{itemId, inboundQty}]}`），库存/台账按实际入库数量计算；入库完成由后端校验。
- **关闭**：仅 1/2/3 可关闭（开始入库前），`changeStatus({orderId, status:'0', closeReason})`。
- 状态标签走字典 `purchase_order_status`（1待采购/2采购中/3已到货/4入库中/5已完成/0关闭）。

## 七、跨页面的下拉预加载

- 弹窗/抽屉下拉数据（供应商/项目分期等）在**主页面渲染时预载第 1 页 10 条**并缓存（`material.options.ts` 的 `ensureSupplierOptions`/`ensurePeriodRecords`），打开弹窗直接读缓存，输入模糊查询走服务端。
- 字典类下拉（单位/状态/类别/品牌）统一走 `material.util::loadDictMap`（模块级缓存），改后台字典重新登录生效。

## 八、关键约定（全局）

1. **所有状态/枚举/下拉标签走后端 `sys_dict` 数据字典**，前端不写死（mock 字典已全部移除）。
2. **编号显示规则**：新增时隐藏编号（后端生成），创建后只读展示。
3. **操作人身份**：`getCurrentUser()` 取当前用户；审批提交带 `approvalUserId`；列表/详情按 id 解析姓名（后端姓名优先）。
4. **审批人展示**：直接用接口 `approvalUserName` 字段。
5. **执行人** = 执行出入库的经办人（`executeUserName`）。
6. **单位**统一走 `inv_unit` 字典；**主项目名称** = 项目主项目名（`projectName`），分期名仅作下拉 label。
7. **全局禁用浏览器自动填充**（`autocomplete="off"`，`src/utils/autocompleteOff.ts`）。
