| 新增保存 | `POST materialCandidate/add`（periodId、candidateName）→ 返回 id/version → 有明细时 `materialCandidateItem/addBatch`（candidateId、version、records）→ 回查主单及明细。主单成功即保留 id，明细失败不重新新增主单。 |
| 修改保存 | `POST materialCandidate/revise`：candidateId、candidateName、version、完整 records、可选 changeReason。空数组表示清空；有实际变化时后端复制修改前内容为独立草稿 B 单。 |
| 提交 | 编辑器先保存 → 回查版本 → `POST materialCandidate/submit`（candidateId、version）；列表提交直接提交当前行版本。后端校验非空明细及每行底价。 |
| 审批 | `POST materialCandidate/approve`：candidateId、version、result字符串1/0、驳回必填reason。不再先修改明细或用 edit 改状态。 |
| 撤回/作废 | 专用 `POST materialCandidate/withdraw|void`，传 candidateId、version。待审批或已采用单不能作废。 |
| 定价 | `POST materialCandidate/price`：candidateId、version、全部明细 records（id、markupRate、finalPrice）。审批通过且有修改价格权限才允许。 |
| 授权 | `GET grants?periodId` 获取用户授权与独立版本；`POST grant` 传 periodId、userId、version、三项布尔权限。新用户版本0，已有用户按原版本提交，三项全false撤销。保存前核对最新授权版本，不覆盖他人更改。 |
| 导出 | `GET exportCheck?candidateId&version` → allowed=true 后 `GET exportData?candidateId&version` → 仅据受控JSON生成Excel。后端再次验证导出资格。 |
| 操作记录 | `GET history?periodId&candidateId?&pageNo&pageSize=20`，返回数组；不足20条禁用下一页。可切换本分期全部记录查看授权审计。当前仅展示动作、操作人、时间、结果、原因，不渲染价格快照。 |

表内未写完整前缀的路径均为 `/project/`。状态为 -1草稿、0驳回、1通过、2待审批、4作废；采用使用 adopted=0/1，定价使用 priced=0/1。

所有报价写入使用整单 version。读取缺失版本不允许操作；页面打开版本与最新版本不一致时要求刷新核对，不自动获取新版本重放旧表单。主单/明细成功后回查版本，再执行后续提交。版本冲突不得通过改状态或换接口绕过。

价格按输入原值提交：底价/终价两位小数，比例四位小数，不自动计算或互相换算。输入采用保守上限9999999999，避免JSON数字精度丢失。底价不是物料成本价。导出Excel仅有编码、类别、名称、品牌、型号、数量、单位、终价，不含成本、底价、比例和内部备注。

修改已通过未采用单的计价基础会由后端退回草稿并取消定价；更改比例或终价取消原定价确认。合同调整入口同步使用报价授权、原版本及 revise，调整后回查状态，不能提示直接提交已退回草稿的报价。

合同 addWithPaymentRecords/editWithPaymentRecords 当前契约仍只提供 materialCandidateId，无候选版本参数；不擅自新增未定义字段。合同事务内采用资格与并发校验由后端负责，前端独立解除采用使用候选 edit/version。
