### 终端范围与移动端路径配置

- 每个菜单节点先选择 `适用终端（clientScope）`：`PC` 仅 PC 端、`APP` 仅移动端、`ALL` 两端共用；历史数据未返回该字段时前端按 `PC` 处理。
- 一级菜单和子菜单均可按需填写 `移动端路径（miniAppPath）`，用于 SHKJ App/小程序授权工作台跳转；按钮权限节点不填写。
- 路径必须以 `/pages/` 开头，并与移动端 `src/pages.json` 已注册页面完全一致；不要填写域名、query 或 hash。
- 一级菜单路径用于模块主入口；领料、还料、车辆等需要独立移动端入口的子菜单可填写各自路径。移动端递归读取授权菜单并按路径去重，所以父子节点路径相同时只生成一个入口。
- 留空表示该节点不生成移动端入口；操作能力继续通过 `perms` 授权标识控制。
- `APP` 节点不要求填写 PC 访问路径和组件；`PC` 节点不显示移动端路径；`ALL` 节点同时维护两端字段。子节点只能选择终端范围能够覆盖它的父菜单。
- 修改现有菜单的移动端路径不会改变菜单 ID，但 PC 与移动端角色权限必须在“角色管理 → 授权”的对应页签分别勾选。
- 保存后应分别验证：PC 当前用户权限沿用原接口；移动端当前用户权限使用 `/sys/permission/getUserAppPermissionByToken`。返回旧值时检查后端菜单/Redis 权限缓存。`/getSystemMenuList` 仅用于系统菜单管理，不作为移动端当前用户授权依据。

## 一、配置前必读：component 路径规则

后端菜单里的 `组件路径(component)` 会映射到前端 `src/views/` 目录下的文件（`src/utils/dynamicPages.ts` 的 `import.meta.glob` 注册，支持 `.vue` / `.tsx`）。

| 菜单里的 component 写法      | 对应的前端文件                             |
| ---------------------------- | ------------------------------------------ |
| `project/index`              | `src/views/project/index.vue`              |
| `project/apply/ProjectApply` | `src/views/project/apply/ProjectApply.vue` |
| `project/contract/index`     | `src/views/project/contract/index.vue`     |
| `project/plan/ProjectPlan`   | `src/views/project/plan/ProjectPlan.vue`   |
| `resource/outsourcing/index` | `src/views/resource/outsourcing/index.vue` |

**规则**：不带 `.vue` 后缀；目录层级用 `/` 分隔；`xxx/index` 命中 `src/views/xxx/index.vue`。 **约定**：路径统一**不带前导斜杠**（`resource/outsourcing/index` 而非 `/resource/outsourcing/index`）。

## 四、配置步骤（后台操作）

1. 登录系统，进入 **系统管理 → 菜单管理**。
2. 点「新增」创建**一级菜单**：先选适用终端；PC/两端共用菜单填写路由地址=`/xxx`、组件路径=`LAYOUT`，移动端/两端共用菜单按需填写 `miniAppPath`，保存。
3. 选中该一级菜单，点「新增」创建**子菜单**：终端范围不得超出父菜单；PC/两端共用菜单的路由地址填**完整绝对路径**（如 `/project/list`），组件路径=`project/index`（不带前导斜杠、不带 .vue），移动端入口填写已注册的 `/pages/...`，保存。
4. 隐藏路由同样配置，勾选「是否隐藏」。
5. 按钮权限：选中子菜单 → 新增「按钮」类型 → 权限标识填上表编码。
6. 角色管理 → 授权 → 分别切换“PC端权限”和“移动端权限”，给角色勾选对应页面及按钮权限；修改哪一端只保存哪一端。某个节点在菜单管理中已定义数据规则时，其右侧会显示“配置数据规则”按钮，点击后为当前角色、当前端勾选规则；点击菜单名称本身不再打开规则配置。
7. **重新登录**（或清权限缓存）生效；若后端菜单有缓存，需后端清 Redis / 重启。

> 若「菜单管理」里 `菜单类型` 支持 `按钮`，为操作按钮加权限标识配合前端 `v-auth` 使用。
