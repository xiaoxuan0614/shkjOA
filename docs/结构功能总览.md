当前权限模式是 **BACK**：

1. `src/api/sys/menu.ts` 的 `getBackMenuAndPerms()` 从后端取得菜单和权限码；
2. `src/store/modules/permission.ts` 的 `buildRoutesAction()` 构建运行时路由；
3. `src/router/helper/routeHelper.ts` 将后端菜单对象转换为 Vue Router 配置；
4. `src/utils/dynamicPages.ts` 通过 `import.meta.glob` 将后端 `component` 字符串解析到 `src/views/` 页面；
5. Pinia 权限仓库保存菜单、动态路由和权限码。

### 2.4 API 层

- 请求入口：`src/utils/http/axios/` 导出的 `defHttp`。
- PC 与移动端接口默认超时统一为 20 秒；单独指定超时的上传、导出等请求保留各自设置。
- 正常响应：`{ code, result, message, success }`，`code === 200` 表示成功。
- `GET` 查询成功默认不弹 Toast；新增、修改、审批等写操作由接口调用或页面保留一条明确结果提示。全局 Toast 同时最多显示两条，避免并发请求提示堆叠。
- 请求带时间戳和 MD5 签名。
- 各业务模块在对应 `*.api.ts` 中维护接口，页面不应散落硬编码 URL。

### 2.5 表单显示约定

- `src/App.vue` 的 Ant Design Vue `ConfigProvider` 与 `src/settings/componentSetting.ts` 的公共 `BasicForm` 默认配置均关闭 `colon`，所有业务表单标签不显示冒号。
- 公共字典下拉 `JDictSelectTag` 默认只把“请选择…”作为未选择时的占位提示，不将其插入可选项列表；业务下拉仅展示真实字典项，特殊场景可显式开启 `showChooseOption`。
- 合同信息表单使用响应式两列网格，附件字段与普通字段共用同一标签和控件对齐规则；窄屏切换为单列，上传按钮使用普通中性按钮样式。
- 新增用户、重置密码、个人修改密码、注册及忘记密码统一使用 `src/utils/password.ts` 的密码长度规则：新密码至少 6 位，不强制数字、大小写字母或特殊字符组合；确认密码仍必须一致。登录表单只校验必填，兼容历史账号。

## 3. 菜单与路由的三种来源

| 来源         | 文件/位置                                 | 职责                               | 是否是正式菜单事实源 |
| ------------ | ----------------------------------------- | ---------------------------------- | -------------------- |
| 正式后端菜单 | 后端 `sys_permission`，后台“菜单管理”维护 | 登录后返回生产菜单、隐藏页和权限码 | **是**               |
| 前端静态路由 | `src/router/routes/modules/*.ts`          | 开发兜底、静态入口和直接路由注册   | 否                   |
| Mock 菜单    | `mock/sys/menu.ts`                        | `pnpm mock` 时返回菜单和权限码     | 否，仅本地验证       |

同步原则：同一业务隐藏页若同时存在于静态路由、Mock 菜单和正式后台菜单，必须保持 **path、name、component、隐藏状态、激活菜单** 一致；生产运行仍以后端菜单为准。

## 5. 项目、合同与回款关键流程

### 5.0 文件预览边界

文件统一通过 `src/utils/filePreview.ts` 和 `src/components/FilePreview/FilePreviewContent.vue` 在站内弹窗读取并渲染，不提供外链或下载入口，也不再把内网文件地址交给公网预览服务。已选择或已提交的图片、PDF、DOCX、XLS/XLSX、PPTX 均可预览；旧版 DOC/PPT 无法在浏览器直接解析时展示明确说明，不再出现空白弹窗。

公共 `JUpload`、`BasicUpload` 默认每个上传入口只允许一个文件且不启用多选；项目、合同、方案及独立验收单保持相同规则。验收报告例外：每次一个、累计最多三个，支持图片、Word、PDF、Excel，逐项预览/删除，满三个禁用上传；使用 `acceptanceFiles.ts` 拆分路径，沿用 JUpload 逗号连接约定（验收后端持久化待联调）。其他单文件入口存在文件时隐藏上传按钮。已提交文件的删除入口服从页面编辑权限：项目详情文件仅项目对接人或项目经理可删除，计划、合同及项目表单仅在各自可编辑状态开放删除。

### 5.1 项目生命周期

项目以分期 `periodId` 为主要流程标识，主项目由 `projectId` 标识。当前主要状态顺序为：

`未开始` → `合同签订/审批` → `筹备` → `待审批/计划审批` → `实施中` → `全部工序完成` → `验收中（内部/外部并行）` → `质保中` → `完结`

当前轮任一验收不通过时可发起返工：`验收中` → `返工申请/审批` → `返工中` → `工序完成后自动验收`。一张返工单只配置一个统一返工工序，返工用料只记录本轮额外领料量；首次施工与历次返工通过 `reworkId` 留痕，不覆盖历史。

实际状态值、权限码和可执行动作以 `src/views/project/Project.data.ts`、后端状态接口及 [项目全流程需求](项目/项目全流程需求.md) 为准。

### 5.2 合同隐藏页入口协议

合同编辑表单关联报价仅提供“修改调整”，不另设“查看详情”；调整弹窗物料明细默认 10 条/页，支持 20/50/100 条及跳页。分页只影响展示，完整草稿跨页保留、全量校验并保存；错误自动定位对应页。共享表格其他调用方默认不开分页，合同只读详情入口保持不变。

合同审批统一使用 `project:contract:approve`：合同信息页审批区域、通过/驳回操作与后端 `POST /project/contract/status` 保持一致。旧 `project:contract:audit` 不再作为前端审批权限；正式审批角色需授予新权限并刷新登录权限缓存。

统一页面：`/project/contract` 组件：`project/contract/index` 激活菜单：`/project/list`

### 5.3 合同与回款接口

列表验收入口：`src/views/project/components/AcceptanceModal.vue` 在项目列表 `ACCEPTING` 操作栏打开，重新读取分期详情核验状态/权限，复用 `DetailAcceptance.vue` 的权限过滤表单；完成后关闭并刷新列表。`project:internalAccept` 办理内验，`project:accept` 且本项目经理办理外验。提交人姓名通过完成接口 `acceptUnitLeader` 与报告、结果一起保存，不再手动开始验收。

项目详情验收记录：内部/外部卡片办理时可选择验收日期，保存资料通过 `acceptDate` 保留选择，完成验收将所选日期按当天零点传入 `acceptEndDate`，不再固定使用提交时刻；日期必选。已完成卡片及历史表只读显示 `acceptEndDate`（年月日），空值显示“—”。

实施记录详情（`src/views/implement/detail/index.vue`）不显示实施日期，位置读取 `implementLocationName` 并与内容上下分行；工时优先 `hours`，空值时显示注明来源的打卡时长。日志提交人与所属工序现场负责人相同才展示参与人员信息和实际外协记录，名称按分期成员/外协配置补齐，不展示整项目人员作为本次参与者。

合同新增、修改及审批前保存项目经理时，`contract.salesUserId/salesUserName` 始终成对传递，姓名从所选用户解析，不能因未修改而从差量请求省略；其余可编辑合同字段继续差量提交。当前 Apifox 字段为 `salesUserName`，不是 `saleName`。

| 用途               | 方法与路径                                      |
| ------------------ | ----------------------------------------------- |
| 合同列表           | `GET /project/contract/list`                    |
| 合同详情           | `GET /project/contract/queryById`               |
| 新增合同及回款计划 | `POST /project/contract/addWithPaymentRecords`  |
| 修改合同及回款计划 | `POST /project/contract/editWithPaymentRecords` |
| 合同编辑（已废弃） | `POST /project/contract/edit`                   |
| 回款计划列表       | `GET /project/paymentRecord/list`               |
| 回款计划批量新增   | `POST /project/paymentRecord/addBatch`          |
| 回款计划全量同步   | `POST /project/paymentRecord/editBatch`         |
| 回款计划批量删除   | `DELETE /project/paymentRecord/deleteBatch`     |
| 项目分期状态更新   | `POST /project/period/status`                   |

合同信息页将接口字段 `contractAmount` 显示为“项目金额”；`plannedDeliveryDate`（计划交付日期）、项目金额与 `warrantyPeriod`（质保期）均为必填，质保期只允许输入大于等于 0 的整数。历史待审批合同缺少计划交付日期时不能直接审批通过，应驳回补充后重新提交。回款金额使用 `big.js` 按“项目金额 × 比例 ÷ 100”计算并保留两位；提交前要求回款比例合计精确等于 100%。合同信息回款计划的“回款周期”映射接口字段 `rollbackTime`，表示阶段任务完成后回款的周期；新增行默认 7 天，比例和周期均使用数字输入，比例限制为 0～100，周期必须为大于等于 0 的整数，旧记录缺失该字段时也按 7 天回显。合同详情以必填 `periodId` 返回合同和回款计划，统一附件另从项目文件列表读取；新增/修改仍使用 multipart 组合接口的 `data` 部分，修改时 `contract.periodId` 必传，其他合同字段只传变化项，`records` 全量同步。
