# PC 统一上传检查（2026-09-17）

范围：shkj-OA 的 src/views、src/api、src/utils、src/components 和 src/hooks。已刷新 Apifox，核对公共上传及项目/合同/方案的最新请求契约；本次为源码与模拟请求检查，未证明真实上传、保存后重开及预览成功。移动端不在本次检查范围。

## 通用封装

`src/utils/documentUpload.ts` 的 `uploadDocument(file, biz?)` 统一调用 `/sys/common/upload`，校验 success、code（0/200及字符串形式）和非空 message，返回 `{path,response}`。调用方负责类型/大小限制、业务保存、回显和失败重试。`uploadProjectDocument(file, periodId)` 保留分期必填检查，再委托通用方法；新增项目使用 `uploadDocument(file, 'project')`。

## 不能声称全仓所有文件请求均已统一

- Excel 导入需要业务接口解析表格，保留 importExcel 等专用接口；计划用料 Excel 在前端解析后传记录。
- 评论附件组件仍有 `/sys/comment/addFile`、`addFile2` 专用上传，涉及评论关联，不擅自改为只返回路径的公共上传。本轮 Apifox 未提供可替换的关联保存契约。
- Word 模板使用 `/wordtpl/template/parse/file` 解析文件；图片仍使用公共上传。
- 富文本远程图片导入使用 `/sys/common/uploadImgByHttp`，属于远程地址导入，不是本地文件上传。
- 可配置上传组件支持覆盖接口地址，不能仅凭默认地址证明所有运行时配置。
