## 一、字典编码清单（系统管理 → 数据字典 配置）

| 字典编码                            | 含义         | 单选/多选 | 使用位置                                                                   |
| ----------------------------------- | ------------ | --------- | -------------------------------------------------------------------------- |
| `project_type`                      | 项目类型     | 单选      | 新增/编辑项目表单、项目管理/计划方案管理搜索、项目详情回显                 |
| `project_business_attr`             | 业务属性     | 多选      | 新增/编辑项目表单、项目详情回显                                            |
| `project_products`                  | 涉及产品清单 | 多选      | 新增/编辑项目表单、项目详情回显                                            |
| `project_period_status`             | 项目分期状态 | 单选      | 项目管理/计划方案管理 列表「项目状态」标签、详情头部状态徽标、搜索「状态」 |
| `approval_status`                   | 通用审批状态 | 单选      | 计划方案、合同、项目用料申请、项目延期及出入库申请/明细的审批状态          |
| `todo_type`                         | 系统待办类型 | 单选      | 首页「我的待办」类型标签；10 项完整值见全模块字典说明                      |
| `contract_type`                     | 合同类型     | 单选      | 合同信息页面（项目合同/维保合同/无合同）                                   |
| `payback_node`                      | 回款节点     | 单选      | 合同信息页回款计划（预付款/到货款/验收款/质保金等）                        |
| `plan_type`                         | 方案类型     | 单选      | 编辑计划方案“方案文件”列表                                                  |
| `member_role`                       | 参与人员角色 | 单选      | 计划页及项目详情列表完整回显；邀请下拉过滤 `0/1/2`                         |
| `outsourcing_type`                  | 外协单位类型 | 单选      | 外协单位维护及项目详情“外协人员”单位类型（`0=个人`、`1=企业`）             |
| `purchase_order_status`             | 采购状态     | 单选      | 补料计划用料清单预览中的采购状态（缺失时按项目用料接口枚举兜底）           |

前端逻辑：编辑表单的上述下拉通过 `ApiSelect` + `initDictOptions(code)` 从字典加载；项目详情只读字段同样按字典值转换，未知值回退原始编码。用料采购状态因接口已明确枚举，在字典整体缺失时按接口枚举兜底。

## 二、字典项 value 一致性（重要）

- **项目类型 / 业务属性 / 涉及产品：真实后端存的是编码**（如 `1`、`2`），业务属性/涉及产品为**逗号分隔字符串**（如 `"2,1"`）。
- 因此字典 `value` 用编码（`1/2/3...`），`text` 为展示文案；多选字段前端自动做「数组 ⇄ 逗号字符串」转换：
  - 编辑回显（`ProjectApply.vue loadDetail`）：`"2,1"` → `["2","1"]`
  - 保存提交（`handleSave`）：`["2","1"]` → `"2,1"`
- `project_period_status` 的 `value` 与后端 `period.status` 一致；调试阶段配置 `DEBUGGING=调试中`。历史 `DEBUG_COMPLETED` 只用于旧数据兼容，不再作为新流转目标值。
- `contract_type` 建议 value 与后端存储一致。
- **通用数值审批状态使用 `approval_status`**：`-1=待提交`、`0=驳回`、`1=审核通过`、`2=待审批`、`3=已撤回`，覆盖计划方案、合同、项目用料申请、项目延期、出入库申请及明细；`src/utils/approvalStatus.ts` 保留同值判断和兜底。历史 `contract_status`、`stock_apply_status`、`stock_item_status` 已删除；项目生命周期、执行状态及审批动作参数保持原协议。
- 首页待办类型使用 `todo_type`，字典值必须与 `/sys/todo/page` 返回的 `todoType` 完全一致；项目邀请、计划、合同、用料、延期、返工、内部/外部验收及出库两类共 10 项固定值见 [全模块字典说明](../字典配置说明.md)。该字典仅控制标签文案和颜色，不参与办理入口判断。
- `member_role` 的完整字典实时用于参与成员列表回显，避免登录时空缓存遮蔽后台新配置；添加成员弹窗必须过滤 `0/1/2`，这三个角色也不可删除。人员配置邀请状态固定为 `0=拒绝`、`1=接受`、其他值`=待接受`，不从 `invite_status` 推断文案。
- `project_material_candidate_status` 固定配置 `0=草稿`、`1=已提交`、`2=已采用`、`3=已作废`，前端直接使用接口状态值查字典名称；只有草稿可修改和删除，已提交状态可由具有 `plan:quotation:unlock` 权限的人员恢复为草稿。
- 项目详情对业务属性、涉及产品和成员多角色的逗号分隔编码逐项查字典，再用顿号连接；字典不存在某个值时仅该项回退显示原始编码。

## 三、多选提交格式

业务属性 / 涉及产品清单前端收集为数组，保存时 `join(',')` 提交为逗号分隔字符串（对齐后端存储）。

## 四、项目地址（按需打开地图选点）

- 项目地址（新增/编辑项目表单）默认只显示已确认地址和「选择位置」提示，点击输入框或按回车才打开地图，进入表单不预先加载地图瓦片。
- 在弹窗中搜索或拖动选点，「确定」回写地址和经纬度；「取消」保留原值。弹窗关闭即卸载地图，重新打开按已保存坐标回显。
- 实施位置（项目详情「实施位置」弹窗、编辑计划方案「位置信息」标签、计划方案行内）直接拖动选点。
- **高德配置**：`.env` 的 `VITE_AMAP_KEY` + `VITE_AMAP_SECURITY_CODE`（v2.0 必填安全密钥），且需在高德开放平台配置**域名白名单**（开发加 `localhost`）。配置缺失时地图提示错误码、可手动输入，不影响其它字段。
- 选中的经纬度随保存提交（period 实体 `longitude` / `latitude`）。

## 五、项目状态流转（合同审批 → 计划审批）

- 未开始（`NOT_STARTED`）→ 列表「合同签订」→ `/project/contract?mode=create...` 填写合同和回款计划。
- 合同提交时传 `2` 并进入待审批；统一合同信息页内选择通过/驳回，驳回填原因，通过时必须指定项目经理，通过后项目才进入 `PREPARING`。
- 原提交人可撤回待审批合同；待提交、驳回或已撤回合同可由原提交人修改并重新提交，驳回详情展示 `approvalReason`，审核通过状态锁定。
- 只有合同审批指定的项目经理可保存/提交计划；计划审批驳回后仍由该项目经理修改。
- 合同新增模式读取并展示项目基本信息，不读取已有合同/回款计划；查看/编辑必须携带 `periodId` 查询该分期唯一合同。

## 六、合同按钮权限配置

前端通过权限码控制合同发起与审批；撤回和重提按合同原提交人身份控制：

| 权限码                    | 作用                         | 给谁             |
| ------------------------- | ---------------------------- | ---------------- |
| `project:contract`        | 显示项目列表「合同签订」入口 | 销售/项目发起人  |
| `project:contract:approve`  | 显示合同信息页审批区域       | 合同审批人       |
| `project:plan:audit`      | 计划提交后的通过/驳回        | 指定计划审批角色 |
| `project:arrival:confirm` | 计划审批通过后确认项目到货   | 指定到货确认角色 |

**正式后端配置步骤**：

1. 系统管理 → **菜单管理** → 找到「项目管理」列表菜单，新增“合同签订”按钮权限 `project:contract`。
2. 在“项目管理”列表菜单下新增“合同审批”按钮权限 `project:contract:approve`；该权限控制合同信息页内审批区域，不再生成单独列表按钮。
3. 在对应计划审批入口配置 `project:plan:audit`，并在角色管理中分别授权。
4. 用户重新登录或清理权限缓存后生效。

审批区域除权限码外还受合同状态控制：仅 `contractStatus=2` 显示。合同通过前列表统一显示“合同信息”，通过后列表入口隐藏，只从项目详情查看。审批状态统一使用 `approval_status`，前端保留固定映射兜底。

**前端 Mock**：`mock/sys/menu.ts` 的 `codeList` 包含以上权限码；Mock 仅提供菜单/权限和共享字典，不再提供项目、合同、回款业务数据。
