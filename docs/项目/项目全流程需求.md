## 一、角色与职责

| 角色                  | 主要职责                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------- |
| 销售/项目对接人       | 创建项目基本信息；项目对接人负责后续从项目详情修改基本信息；销售负责人填写、修改和重新提交合同 |
| 合同审批人            | 审批合同；先选择通过/驳回，驳回时填写原因，通过时必须指定项目经理                              |
| 项目经理              | 创建计划（邀约参与人员、确认计划用料清单、填写实施计划与位置）；保存并提交计划审批             |
| 参与人员              | 接收/接受/拒绝项目邀约；执行实施；填报实施记录                                                 |
| 审批人（部门/总经理） | 计划审批（待审批→立项）、关闭项目审批                                                          |
| 库管                  | 依据计划用料清单执行出库                                                                       |
| 采购                  | 采购管理（与项目合同物料分属两个模块）                                                         |
| 总经理                | 关闭项目审批终审                                                                               |

## 二、项目创建（销售）

1. **销售人员创建项目基本信息**（项目名称、类型、业务属性、涉及产品、甲方、项目对接人、地址等）→ 项目「未开始」。项目对接人默认当前操作人，可修改；创建后只有该对接人可从项目详情修改基本信息。
2. 销售进入**合同信息页面**（独立隐藏页面 `/project/contract`，非弹窗）：
   - 新增入口：`mode=create&periodId=...&projectId=...`，页面读取并展示项目基本信息，不读取已有合同/回款计划，初始化空合同表单；
   - 查看入口：`mode=view&periodId=...&projectId=...`；编辑入口将 mode 改为 `edit`；
   - 查看/编辑进入后按 `periodId` 调合同详情 `/project/contract/queryById`，成功后再读取 `/project/paymentRecord/list`；
   - 填写合同信息：合同类型 / 合同编号 / 合同名称 / 合同签订日期 / 计划交付日期 / 项目金额 / 质保期 / 销售负责人（默认当前销售）等；计划交付日期、项目金额、质保期必填，质保期只允许填写大于等于 0 的整数；接口字段仍分别为 `plannedDeliveryDate`、`contractAmount`、`warrantyPeriod`；历史待审批合同缺少计划交付日期时不得直接审批通过，应驳回补充后重新提交；
   - **上传合同附件**；
   - **合同货物清单：只挂文件并上传**，不解析为明细；
   - 回款计划逐行选择回款项并填写比例、回款周期：其他行已选回款项不再出现在当前下拉中；回款项、比例和周期均必填，新行周期默认 7 天，比例和周期只接受数字，比例合计必须为 100%，回款周期为大于等于 0 的整数；
   - 两类文件支持 PDF、Word、Excel、PPT，并以绿色按钮选择；选择后只在本地标准文件列表回显，不立即上传。点击“提交”后先调用 `/sys/common/upload`，multipart 表单传 `file` 与 `biz=当前项目分期 ID`，仅取响应 `message` 作为路径；全部待处理附件上传成功后，保存接口才携带已上传路径提交合同与回款数据，任一上传失败必须中止保存。已有合同附件重新加载后保持相同列表样式并可移除重选。
   - 新增提交调用 `/project/contract/addWithPaymentRecords`，请求体为 `{ contract, contractFile?, records }`，合同、合同文件元数据和回款计划由后端在同一事务保存；提交时合同状态传 `2`（待审批）。
   - 已有合同修改并重新提交时，不再调用已废弃的 `/project/contract/edit`；仅通过 `/project/paymentRecord/editBatch` 全量同步回款计划，再将合同状态转为 `2`（待审批）。
   - 合同提交后，项目列表在通过前显示“合同信息”统一入口，默认只读；审批权限人可通过/驳回，原提交人可撤回待审批合同。通过后列表入口隐藏，从“项目详情 → 合同信息”查看。
3. **提交后合同进入待审批**，项目仍保持未开始：
   - 驳回：`status=0`，详情明确展示驳回原因，由原提交人修改后重新提审；
   - 通过：`status=1`，选择“通过”后必须选择项目经理，完成后项目进入「筹备中」；
   - 待审批：`status=2`，审批权限人可通过/驳回，原提交人可撤回；
   - 已撤回：`status=3`，可由原提交人修改后重新提审；`status=-1` 为待提交，其他异常值按待提交兜底并允许原提交人修改提交。

## 三、计划创建（合同审批指定的项目经理，项目筹备中）

项目列表仅在项目处于筹备中（`PREPARING`）时显示“编辑计划方案”；计划提交审批后隐藏，审批通过进入实施中后显示受 `project:implement` 权限控制的“实施完成”操作。

进入编辑或审批详情后，页面先并行读取当前项目分期详情和合同组合详情；两项都成功后才挂载方案文件、用料、人员、实施、位置和回款六个页签，任一失败均禁止子页继续查询或写入并提供重试。

1. **确认计划用料清单**：
   - 依据合同货物清单**文件**（选择/导入该文件，或手动创建物料，沿用现有物料维护页面）；
   - 在计划内可补充辅料。
2. **选择参与人员 → 发送邀约**：点击“添加成员”打开弹窗，实时读取 `member_role` 字典并过滤 `0/1/2`，成员通过 `/sys/user/list` 汇总全部分页；提交调用 `/project/member/addBatch`，第一层传 `periodId`。同一用户在 `records` 中只放一条 `{ userId, memberRole }`，多角色编码在 `memberRole` 内使用英文逗号连接；参与成员列表以成员为一行，通过 `/project/member/list` 返回合并角色并按实时完整字典回显。邀请状态为 `0=拒绝`、`1=接受`、`2=待接受`，并兼容历史空状态。全局登录邀请弹窗暂不挂载，被邀请人在首页“我的待办”中每个项目分期只看到一条成员邀请；点击“查看详情”后再次调用 `/project/member/list` 查询本人在该分期的全部角色，再通过 `/project/member/respond` 同意或拒绝。项目经理只能删除已接受且角色不是 `0/1/2` 的成员，删除调用 `/project/member/deleteBatch`。
3. **快速查看项目基本信息**：进入“编辑/查看计划方案”后，页面标题旁显示“详情”按钮；抽屉直接复用父页已读取的分期详情，查看主项目、分期、联系人、业务与实施信息，不离开当前计划页也不重复请求详情。
4. 填写**实施计划、实施位置信息**；实施计划维护必填的**计划验收日期 `plannedAcceptanceDate`**。
   - 首次进入“方案文件”页签时，使用当前项目分期 ID 调用 `GET /project/plan/list` 查看计划方案，不展示合同附件或合同用料草稿；序号按当前表格行位置从 1 连续显示。列表未加载成功前禁止新增、修改、删除和保存，切换请求时旧响应不得覆盖新分期数据。
   - 选择文件只在本地回显，点击该行“保存”时才调用 multipart `POST /project/plan/add`，`data` 传该行方案 JSON、`attachment` 传方案文件；已有行修改使用 `POST /project/plan/edit`。方案名称、方案类型和文件均必填，提交整份计划前至少存在一条已保存的方案文件。
5. **提交审批** → 项目状态「**待审批**」。
   - 提交前必须逐一打开六个页签并确认业务主数据查询成功；任何页签仍在加载、加载失败、保存中或存在未保存内容时都不得流转状态。前端校验通过后只调用 `/project/period/status` 传 `{ periodId, status: 'PENDING_APPROVAL' }`，后端仍应在状态接口中执行同等的原子完整性、合法前置状态、权限与并发防重校验。`GET /project/plan/list` 的 Apifox 参数表尚未声明必需的 `periodId`，后端必须补齐并按分期过滤。
   - **驳回** → 项目经理可修改计划后重新提交；当前 `/project/period/status` 只接收 `periodId/status`，无法持久化驳回原因，需后端扩展字段或提供专用审批接口。
   - **审批通过** → 项目可**开始实施**（进入实施中）。
6. 计划审批通过后，生成**计划用料清单**，库管可执行**出库**。

> 说明：当前流程为「合同提交→合同审批+指定项目经理→筹备中→计划审批（待审批）→实施中」。

## 四、实施过程（用料管控）

1. 实施过程中申请的用料**必须在计划用料清单内**（计划内）。
2. **计划外物料**需**提报申请 → 审批**；审批通过后**计入计划内**，方可领用。

---

## 五、采购

1. **采购与项目合同物料分为两个模块**（采购管理 与 项目合同物料 独立维护）。
2. 若需一起采购，由**采购人员线下自行沟通**，系统不做关联。
3. 采购需增加字段：**含税金额、未税金额**（二期细化）。

---

## 六、实施完成与验收

1. 实施中按工序逐条完成；当前轮全部工序完成后，后端将分期自动推进为 **PENDING_ACCEPT（待验收）**。
2. 有权限人员点击“提交验收”，首次传 `periodId`，返工复验同时传当前 `reworkId`，一次创建内部和客户两条验收记录。
3. 验收分**内部验收、外部验收**两条线并行执行：内部由运维部门经理上传文件确认，外部由本项目经理上传文件确认；提交验收进入 `ACCEPTING` 时分别生成待办，两项都通过才由后端自动进入质保期。
4. 任一验收不通过时必须填写原因，可发起返工申请。每张返工单统一配置**一个返工工序**和本轮额外领料计划；审批通过后进入返工，完成后重新提交验收。
5. 返工编辑、提交、撤回、审批均使用返工详情最新 `version` 做并发校验，旧版本不得覆盖新数据。

---

## 七、回款

1. **回款项**：预付款、到货款、验收款、质保金、尾款、全款。
2. **手动录入节点**：维护**节点类型 + 比例**，系统**根据项目金额自动计算**该节点金额。
3. 按项目进行情况触发**催款提醒**给销售负责人。
4. 销售负责人**填写回款记录**，并**填写开票状态**。

---

## 八、外协单位

- 外协单位分为**个人、单位**两种类型（新增 `type` 字段；个人可不填单位开票信息）。

## 九、关闭项目审批流程

| 发起人   | 审批链                   |
| -------- | ------------------------ |
| 销售     | 销售 → 总经理            |
| 项目经理 | 项目经理 → 销售 → 总经理 |

> 属例外终态（区别于正常项目完结）。

## 十、通知机制

- **首页“我的待办”单行列表**（参与人员邀约、审批提醒、催款提醒），不再单独配置待办菜单；后续支持**移动端通知**。

## 十一、与现有实现对照（开发参考）

| 需求 | 现有代码/模块 | 缺口 |
| --- | --- | --- |
| 项目创建/合同信息 | `project/apply`、`project/contract/index.vue` | 项目对接人默认当前人；合同 create/view/edit 三模式；合同页内审批、撤回、重提并指定项目经理 |
| 计划创建/审批 | `project/plan`（六标签） | 邀约机制、计划验收日期 `plannedAcceptanceDate`、计划提交审批、待审批 |
| 计划用料/出库 | `material/*` | 计划用料清单生成、库管出库 |
| 用料管控 | `material/pick`/`return` | 计划外物料审批 |
| 采购 | `material/purchase` | 拆模块、含税/未税 |
| 验收/返工 | `project/detail` 验收记录、返工管理、`material/pick` | 已接入提交验收、并行验收、单工序返工、额外领料和复验链路；待真实账号联调 |
| 回款 | `payment`、`paymentRecord` | 节点+比例自动算、催款提醒、开票状态 |
| 外协 | `resource/outsourcing` | 个人/单位类型字段 |
| 关闭项目 | 状态 `CLOSED` | 关闭审批流程 |
| 通知 | 首页“我的待办” | 单行显示类型、标题、申请时间和查看详情；后续支持移动端通知 |
