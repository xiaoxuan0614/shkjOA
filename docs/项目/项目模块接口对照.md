| 方法 | 路径 | 说明 |

返工单 `version` 是乐观锁。前端编辑打开时读取详情；提交、撤回、审批，以及保存后紧接提交审批时，均在状态动作前再次调用详情接口，不能直接使用列表或旧弹窗缓存值。过期 version 由后端拒绝，防止覆盖他人刚完成的编辑或审批。

返工保存主体：

```json
{
  "id": "编辑时传",
  "version": 3,
  "periodId": "分期ID",
  "sourceAcceptanceId": "失败验收ID",
  "reason": "返工原因",
  "description": "返工说明",
  "process": {
    "processName": "返工工序",
    "siteLeaderId": "负责人ID",
    "plannedStartTime": "2026-09-08",
    "plannedEndTime": "2026-09-09",
    "plannedHours": 8,
    "remark": ""
  },
  "materials": [
    { "materialId": "物料ID", "unitId": "单位ID", "plannedQty": 2, "remark": "本轮额外领料" }
  ]
}
```

当前 Apifox `OaProjectAcceptance` 已声明 `reworkId/acceptStatus`，但 `OaProjectInternalAcceptance` 尚未声明这两个字段。前端保留旧数据兼容，后端需按既定返工轮次契约补齐后再完成真实账号联调。

**合同信息页调用约定**：

- 页面将后端 `contractAmount` 字段显示为“项目金额”，并将 `contractAmount`、`warrantyPeriod` 设为必填；`warrantyPeriod` 只接受大于等于 0 的整数，提交字段名不变。
- 新增 `mode=create`：按 `periodId` 调用项目详情用于顶部基本信息回显；不调用合同列表、合同详情或合同明细列表。
- 查看/编辑：合同详情接口仅接受必填 `periodId`，返回 `contract/contractFile/materialFile/records`；同时调用 `/project/file/list` 读取 `CONTRACT_ATTACHMENT` 统一附件，原两个文件位仅作历史兼容。合同信息页不再额外调用回款计划列表，也不得传合同 `id`。
- 合同只读详情使用 `contract_type` 映射 `contractType`、使用 `payback_node` 映射回款计划的 `paymentNode`；`projectManagerUserName` 为空时按 `projectManagerUserId` 从 `/sys/user/list` 补齐。附件字段存在路径时通过静态文件访问地址提供预览。
- 合同附件每次只选一个并立即调用 `/sys/common/upload`，以 `biz=periodId` 上传；成功响应的 `message` 原始路径用于预览和后续关联，数量必须为 1～3 个。合同组合请求只提交合同与回款 `data`，不再传 `attachment/materialAttachment`；组合保存成功后调用 `/project/file/addBatch` 写入 `CONTRACT_ATTACHMENT`，编辑删除调用 `/project/file/deleteBatch`。
- 组合新增的 `records` 元素使用 `paymentNode/ratio/plannedAmount`，不带 `periodId/id/contractId`，至少提交一条；后端任一步骤失败时整体回滚。
- 已有合同重提调用 `/project/contract/editWithPaymentRecords`：`data.contract.periodId` 必传，其他合同字段与详情原值比较后只传变化项；`records` 为全量列表，带 `id` 更新、不带 `id` 新增，未提交的旧记录逻辑删除。接口成功后合同状态固定为 `2`。
- 新增合同在组合请求的 `contract.status` 中直接传 `2`（待审批）。统一合同信息页内审批：驳回传 `{ periodId, status: '0', approvalReason }`；通过时当前仍需调用合同编辑接口保存项目经理，再传 `{ periodId, status: '1' }` 并推进分期到 `PREPARING`；原提交人撤回传 `{ periodId, status: '3' }`。
- 项目列表通过 `contractStatus` 控制统一入口：合同已存在且未通过时显示“合同信息”，通过后隐藏；合同信息页仅在状态 `2` 且拥有 `project:contract:approve` 时显示审批区域。
- 项目列表对接人列优先读取 `projectLiaisonUserName`；姓名快照为空时使用 `projectLiaisonUserId` 从 `/sys/user/list` 补齐，仍无法识别的行按 `periodId` 调 `GET /project/project/projectPeriodDetail` 补查对接人字段。
- 新增项目与已有主项目新增分期统一调用 `POST /project/project/addProjectPeriod`，编辑调用 `POST /project/project/editProjectPeriod`；均传 `multipart/form-data`，其中 `data` 是合法 JSON 字符串，`attachment` 是单个可选文件。前端不预调用 `/sys/common/upload`，不在 `data` 中传 `attachmentFileId`；编辑未传新附件时保留旧文件。
- 当前 `defHttp` 对非 GET 请求会将 `params` 移入 body，项目 multipart 请求需从 `params` 传入完整 FormData；若直接设置 `data=FormData`，其 `Object.keys(data)` 判断会误判为空并丢失 multipart parts。
- 前端通用数值审批规则为 `-1=待提交`、`0=驳回`、`1=审核通过`、`2=待审批`、`3=已撤回`，其他异常值按待提交兜底；Apifox 中仍使用旧说明的模型字段需要后端同步契约。
- 原提交人可撤回待审批合同，并可修改待提交、驳回或已撤回合同；驳回只读页与编辑页展示 `approvalReason`，重新提交后状态改为 `2` 并清空旧驳回原因。
- `mock/demo/project.ts` 与 `mock/demo/contract.ts` 已删除，这些接口均需真实后端。

## 四、对接要点 / 待确认

1. **状态码**：`project_period_status` 仅表示项目生命周期；计划审批结果另读 `approvalStatus` 五态，统一字典编码为 `approval_status`（`-1/0/1/2/3`）。当前前端通过 `POST /project/period/status` 传 `{ periodId, status }`，计划提交、审批通过和驳回分别传生命周期 `PENDING_APPROVAL`、`IMPLEMENTING`、`PREPARING`。2026-09-03 的 Apifox `ProjectPeriodDetailResult` 尚未声明 `approvalStatus`，需后端和文档补齐该返回字段。
2. **项目文件路径**：项目基本信息附件由 `addProjectPeriod/editProjectPeriod` 组合提交；合同双文件由 `addWithPaymentRecords/editWithPaymentRecords` 组合提交；方案、详情和验收等仍使用统一上传的页面，仅在成功响应有效时读取路径。公共上传要求 `success=true`、`code` 为 `0` 或 `200`（兼容对应字符串），从非空 `message` 读取文件路径。2026-09-13 浏览器实际响应为 `code=0`，不可只接受 `200`；相对路径通过 `/sys/common/static/` 读取预览，业务字段仍保存上传返回路径。
3. **删除主项目**：后端仅提供删除分期，主项目删除/批量删除未接入。
4. **回款计划**：合同信息页从合同组合详情的 `records` 读取；新增/修改均随合同组合请求提交全量列表，页面节点、金额、回款周期分别映射为 `paymentNode/plannedAmount/rollbackTime`。
5. **standalone 计划/实施/回款模块**：列表已对齐后端，详情页(方案详情/日志详情/合同回款)为设计稿结构，后续按后端实体重构。
