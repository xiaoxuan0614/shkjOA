# 值班表规则配置：后端配合清单

日期：2026-10-29。以下新增字段为建议契约，尚未实现或接入，需后端确认并更新 Apifox 项目 8679942。

## 本次页面已完成

选择月份和参与人员（可调顺序）→ 输入规则/套用模板 → 查看逐条理解和整月检查结果 → 确认理解 → 生成 → 逐日人工调整 → 保存锁定。

本期采用前端确定性句式解析，不调用AI。支持的顺序轮值示例：

> 工作日白班4人，夜班1人；周末白班1人，夜班1人；夜班后次日上午休息，下午上班，不补人；按选人顺序轮值，周末白班也占轮次，跨月接上月。

工作日白班为全部参与者，不消耗轮次；周末先取白班再取夜班。规则含糊、相互冲突、人数不足或无法识别时不生成。此模式使用自然周末；节假日调休不是隐含条件。原有节假日文字模板保留，但不意味着所有规则可以任意混合。

检查用于生成初稿；人工修改后的实际安排才是保存内容，不能在保存时重新按规则排班或限制人数。

## 已有接口情况

| 接口 | 当前契约与差距 |
| --- | --- |
| POST /operation/dutyRoster/save | 按 month 保存/覆盖，body 为 month、days；忽略 rotationUsers |
| PUT /operation/dutyRoster/edit | 按 id 修改，body 为 id、month、days；不存在的 id 不新增 |
| GET /operation/dutyRoster/queryById | 按 id 查询排班，尚无规则配置与半天休息快照 |
| GET /operation/dutyRoster/queryByMonth | 按月份查询，当前用于跨月夜班衔接 |
| GET /operation/dutyRoster/exportXls | 导出保存结果，现有列没有上午休息 |

days 当前支持 date、dayUsers、nightUsers、restUsers，均为人员数组。人员入参使用 userId，姓名和电话由后端取快照；tel 是独立原始字段，不作为电话兜底。继续保留现有契约。

前端当前保存封装仍统一调用 save；后续接入需将有 id 的修改切到 edit。这是已有接口的前端调整，不要求后端再新增一个修改接口。

## 本期必须配合

| 项目 | 建议新增字段 | 要求 |
| --- | --- | --- |
| 保存生成配置 | generationMode、ruleText、ruleConfig | 规则原文、结构化规则及版本一起保存，查询原样返回；再次编辑能恢复原规则，不用默认模板冒充历史配置 |
| 保存选人顺序 | rotationUsers | 有序人员数组，独立于每日安排；不得排序或从班次反推；保存/修改/查询都返回 |
| 保存半天休息 | days[].morningRestUsers | 人员快照数组，表示上午休息下午上班；restUsers 继续表示全天休息；不自动减少白班人数或补人 |
| 导出同步 | 上午休息·下午上班列 | 使用已保存的半天休息快照；不临时读取其他月份重算历史文件 |
| 老数据兼容 | 缺失字段可为 null/空 | 保留旧班次，页面显示未记录规则，不伪造规则配置；旧客户端未传新增字段时不要意外清空已存配置 |

建议 ruleConfig 包含 schemaVersion、工作日/周末/节假日白夜班人数、calendarMode、restMode、rotationPolicy，以及工作日白班/周末白班是否占轮次。枚举和最终命名由双方统一；前端不会在文档确认前直接传这些字段。

必须区分 calendarMode=NATURAL_WEEK（自然星期）与 HOLIDAY_CALENDAR（含法定节假日及调休）；后者需要明确年份、日期来源和覆盖日期，不能只看周六日。

保存只做必要的数据格式、日期归属和访问权限校验。不得限制夜班只能1人，也不能因人工调整违背生成规则而拒绝。半天休息以当前提交明细保存，不在后端强制重新生成。

## 跨月衔接建议

当前前端从上月末最后一名夜班人员之后继续，查不到记录从首人开始。上月查询失败应明确提示，不能当作“没有记录”。

建议另外存 generationContext：起始轮值人员和生成结束后的 nextRotationUserId，并保留生成时的上月末夜班快照。这样月底人工清空夜班或多人夜班时，不必猜轮次。

采用该方案时建议明确：人工修改当天班次不会隐式移动轮值游标；下一月优先读取已保存游标；没有游标的旧记录才按月末最后一名夜班兜底。此项是待确认建议，当前代码仍采用原月末夜班衔接，没有接入新游标。

已保存的本月半天休息应是本月快照；修改上月不能静默修改本月记录，需用户明确重新生成或编辑保存。

## 可以后续做，不阻塞本期

- 共享规则模板：模板名称、规则原文、结构化规则、适用范围、启停及版本。
- 任意自然语言：后端解析服务返回结构化规则、逐条解释、未识别内容和待确认问题；确定性排班检查返回冲突日期、原因及可改建议。AI只负责解释输入，不替代最终可排校验，不自动保存。
- 乐观锁 version：防止多人覆盖，属于并发完善，不是规则功能前提。

本期无需后端承担排班计算；补齐配置、顺序、半天快照的存取与导出即可。若以后多端都能生成，再考虑统一解析/检查/生成服务，具体新接口路径另行设计。

## 联调验收

1. 保存后刷新，规则原文、人员顺序、实际班次及半天休息一致。
2. 四人顺序 A/B/C/D，工作日全员白班、夜班顺次；周末白班和夜班连续取人。
3. 工作日昨日夜班仍在今日四人白班中，只标上午休息，不补第五人。
4. 手动改为一人白班、多人夜班或空班后可保存；重新进入不被规则覆盖。
5. 月末/月初衔接、月底手动修改、旧数据无规则配置均有明确行为。
6. 导出与保存后页面一致，包含半天休息；新增走 save，已有记录修改走 edit。

当前已验证前端脚本及浏览器草稿生成；没有保存真实排班，没有验证上述新增字段持久化或导出。
