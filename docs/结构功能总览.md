# 首汇科技管理平台 — 当前结构与功能总览

> **最后更新：2026-08-26** 本文档是仓库当前结构、菜单、路由、API 与业务文档的唯一总入口。开始修改代码前必须先阅读本文，并按“模块索引”定位代码与对应文档；历史变更以 [更新记录](更新记录.md) 为准。

## 1. 文档驱动开发规则

1. **编码前**：先阅读本文，确认受影响的模块、页面、路由、API 和模块文档。
2. **编码中**：正式菜单、静态路由、Mock 菜单职责必须分开判断，不以某一份 Mock 配置代替正式后端配置。
3. **编码后**：每次代码更新都必须在 [更新记录](更新记录.md) 追加记录，并检查以下文档是否需要同步：
   - 本文档（结构、入口、边界发生变化时）；
   - [菜单配置指南](菜单配置指南.md) 与 [菜单配置傻瓜指南](菜单配置傻瓜指南.md)（路径、组件、隐藏菜单或参数发生变化时）；
   - 对应模块的业务、接口、字典或验收文档。
4. **按实际影响更新**：不相关文档不机械改写，但完成说明必须注明已经检查过哪些相关文档。
5. 项目级 `.claude/settings.json` 会在写工具执行前后注入上述提醒；`CLAUDE.md` 保留相同的仓库级规则。

## 2. 技术架构与启动链路

### 2.1 技术栈

- Vue 3 + TypeScript + Vite 8
- Ant Design Vue 4
- Pinia
- JeecgBoot 前端基础设施
- pnpm（Node 18 或 20+）

### 2.2 应用启动

`src/main.ts` 的主要顺序：

`createApp` → `createRouter` → `setupStore` → `setupI18n` → `initAppConfigStore` → 注册外部包/全局组件 → `setupRouter` → `setupRouterGuard` → 指令与错误处理 → 第三方组件 → `router.isReady()` → `mount`

### 2.3 权限与动态路由

当前权限模式是 **BACK**：

1. `src/api/sys/menu.ts` 的 `getBackMenuAndPerms()` 从后端取得菜单和权限码；
2. `src/store/modules/permission.ts` 的 `buildRoutesAction()` 构建运行时路由；
3. `src/router/helper/routeHelper.ts` 将后端菜单对象转换为 Vue Router 配置；
4. `src/utils/dynamicPages.ts` 通过 `import.meta.glob` 将后端 `component` 字符串解析到 `src/views/` 页面；
5. Pinia 权限仓库保存菜单、动态路由和权限码。

### 2.4 API 层

- 请求入口：`src/utils/http/axios/` 导出的 `defHttp`。
- 正常响应：`{ code, result, message, success }`，`code === 200` 表示成功。
- 请求带时间戳和 MD5 签名。
- 各业务模块在对应 `*.api.ts` 中维护接口，页面不应散落硬编码 URL。

### 2.5 表单显示约定

- `src/App.vue` 的 Ant Design Vue `ConfigProvider` 与 `src/settings/componentSetting.ts` 的公共 `BasicForm` 默认配置均关闭 `colon`，所有业务表单标签不显示冒号。
- 合同信息表单使用响应式两列网格，附件字段与普通字段共用同一标签和控件对齐规则；窄屏切换为单列，上传按钮使用普通中性按钮样式。

## 3. 菜单与路由的三种来源

| 来源         | 文件/位置                                 | 职责                               | 是否是正式菜单事实源 |
| ------------ | ----------------------------------------- | ---------------------------------- | -------------------- |
| 正式后端菜单 | 后端 `sys_permission`，后台“菜单管理”维护 | 登录后返回生产菜单、隐藏页和权限码 | **是**               |
| 前端静态路由 | `src/router/routes/modules/*.ts`          | 开发兜底、静态入口和直接路由注册   | 否                   |
| Mock 菜单    | `mock/sys/menu.ts`                        | `pnpm mock` 时返回菜单和权限码     | 否，仅本地验证       |

同步原则：同一业务隐藏页若同时存在于静态路由、Mock 菜单和正式后台菜单，必须保持 **path、name、component、隐藏状态、激活菜单** 一致；生产运行仍以后端菜单为准。

## 5. 项目、合同与回款关键流程

### 5.0 文件预览边界

文件统一通过 `src/utils/filePreview.ts` 和 `src/components/FilePreview/FilePreviewContent.vue` 在站内弹窗读取并渲染，不提供外链或下载入口，也不再把内网文件地址交给公网预览服务。已选择或已提交的图片、PDF、DOCX、XLS/XLSX、PPTX 均可预览；旧版 DOC/PPT 无法在浏览器直接解析时展示明确说明，不再出现空白弹窗。

公共 `JUpload`、`BasicUpload` 默认每个上传入口只允许一个文件且不启用多选；项目、合同、方案、验收等自定义附件入口保持相同规则。当前文件存在时隐藏上传按钮，用户删除当前文件后才重新显示。已提交文件的删除入口服从页面编辑权限：项目详情文件仅项目对接人或项目经理可删除，计划、合同及项目表单仅在各自可编辑状态开放删除。

### 5.1 项目生命周期

项目以分期 `periodId` 为主要流程标识，主项目由 `projectId` 标识。当前主要状态顺序为：

`未开始` → `合同签订/审批` → `筹备` → `待立项/计划审批` → `实施中` → `实施完成` → `内部验收` → `客户验收` → `质保中` → `完结`

实际状态值、权限码和可执行动作以 `src/views/project/Project.data.ts`、后端状态接口及 [项目全流程需求](项目/项目全流程需求.md) 为准。

### 5.2 合同隐藏页入口协议

统一页面：`/project/contract` 组件：`project/contract/index` 激活菜单：`/project/list`

| 模式 | URL 参数 | 首次业务读取 | 页面状态 |
| --- | --- | --- | --- |
| 新增 | `mode=create&periodId=...&projectId=...` | 读取项目基本信息，**不读取**已有合同、回款计划 | 项目信息+空合同表单 |
| 查看 | `mode=view&periodId=...&projectId=...` | 按 `periodId` 读该分期唯一合同，成功后再调用 `paybackList` | 只读 |
| 编辑 | `mode=edit&periodId=...&projectId=...` | 按 `periodId` 读该分期唯一合同，成功后再调用 `paybackList` | 原提交人可修改待提交、驳回或已撤回合同 |

约束：

- 查看/编辑缺少 `periodId` 时明确报错并返回项目列表。
- 页面入口不再调用 `contractList` 猜测“新增还是已有合同”。
- `contractList` 只用于真正的合同列表；不得用于新增页初始化或组合提交后的合同 ID 恢复。
- 从查看点击“修改并重新提交”时将 URL 的 `mode` 改为 `edit`，保留 `periodId/projectId`；驳回状态同时展示驳回原因。
- 所有合同修改均不调用已废弃的 `POST /project/contract/edit`，统一使用 `POST /project/contract/editWithPaymentRecords`：`contract.periodId` 必传，合同字段差量提交，回款计划全量同步，后端将状态转为待审核。合同审批通过前写项目经理也携带当前完整回款计划调用该组合接口；回款管理列表的“编辑”统一跳转正式合同编辑页。
- 合同审批状态固定为 `0=驳回`、`1=通过`、`2=待审核`、`3=已撤回`、其他`=待提交`。项目列表在合同通过前统一显示“合同信息”，进入只读详情后：审批权限人可通过/驳回，原提交人可撤回待审核合同或修改驳回/撤回合同后重提。合同通过后列表入口隐藏，只从项目详情查看。
- 合同待审核只读页将 `contractType/paymentNode` 分别通过 `contract_type/payback_node` 字典转换为名称；项目经理姓名快照为空时按用户 ID 补齐，合同附件及合同物料清单有路径时提供预览入口。
- 合同审批通过或项目进入筹备中后，“编辑计划方案”直接显示在项目列表操作栏，不放入“更多”。
- 项目列表的“项目对接人”优先展示接口姓名快照；快照为空时按用户 ID 从系统用户列表补齐，仍缺失时按 `periodId` 补查分期详情后回显。
- 新增项目与已有主项目新增分期统一通过 `POST /project/project/addProjectPeriod` 组合提交，编辑通过 `POST /project/project/editProjectPeriod` 提交；两者均使用 `multipart/form-data`，`data` 为业务 JSON 字符串，`attachment` 为单个可选附件。项目基本信息附件不再预调用 `/sys/common/upload`，业务 JSON 不传 `attachmentFileId`；编辑未选择新附件时保留原文件，选择后由后端替换。附件只允许 Word、PPT、Excel、PDF 和图片，新增/编辑表单不显示重复的“基本信息”区块标题。
- 进入“编辑/查看计划方案”后，页面标题旁提供“详情”按钮，调用 `GET /project/project/projectPeriodDetail` 在当前计划页打开项目基本信息抽屉。
- 编辑/查看计划的标签名称统一为“方案文件”，按当前项目分期 ID 调用 `GET /project/plan/list` 加载计划方案记录，不再读取 `/project/file/list`，因此合同附件及合同用料草稿不会混入。每行“保存”独立提交：新增调用 multipart `POST /project/plan/add`，已有记录修改调用 multipart `POST /project/plan/edit`，文件作为 `attachment` 与 `data` JSON 同请求提交。保存成功后该行锁定并显示“修改”，点击“修改”才解锁；选择文件阶段只做本地完成态回显，不显示持续上传转圈。
- 项目基本信息附件采用项目新增/编辑接口组合提交；合同附件和合同物料文件分别随 `addWithPaymentRecords/editWithPaymentRecords` 的 `attachment/materialAttachment` part 组合提交，不预调用统一上传。方案、详情与验收等仍使用统一上传的页面，必须在响应满足 `success=true`、`code=200` 且 `message` 非空时才读取路径。
- 编辑计划方案不再提供“保存全部”。“提交审批”只调用 `POST /project/period/status`，传当前 `periodId` 与 `PENDING_APPROVAL`，不再隐式保存方案文件、用料、人员、外协、工序或位置。
- 用料计划与实施计划使用独立的“保存本页/修改”状态：已有记录加载后默认只读，点击“修改”才解锁；空列表直接可编辑；保存成功后刷新服务器数据并恢复只读。用料计划通过 `/project/materialPlan/editBatch` 全量同步，实施计划首次保存调用 `/project/process/addBatch`、已有记录调用 `/project/process/editBatch`，第一层同时传计划验收日期及备注。
- 人员配置顶部“修改/保存本页”只控制外协配置，通过 `/project/memberOutsource/editBatch` 全量同步，成功后恢复只读；参与人员邀请和删除不进入该保存动作。位置信息继续使用列表逐行“保存/修改”：保存成功后该行只读，点击“修改”后才可再次编辑；行保存基于已落库快照调用位置全量同步接口，只提交当前行的业务变更，不带入其他未保存草稿，并关闭接口层“批量修改成功”提示，只显示当前行保存成功。
- 人员配置列表通过 `GET /project/member/list` 加载，并实时读取 `member_role` 字典回显角色名称；邀请弹窗过滤角色 `0/1/2`，分页汇总系统全部用户，项目角色支持多选。点击“提交邀请”立即调用 `POST /project/member/addBatch`，同一用户按多个 `memberRole` 批量邀请，已有角色不重复提交；删除立即调用 `DELETE /project/member/deleteBatch`。邀请状态为 `0=拒绝`、`1=接受`、`2=待接受`，服务端兼容历史空状态。接收人通过 `GET /project/member/myInvitations` 获取本人待处理邀请，通过 `POST /project/member/respond` 同意或拒绝；登录弹窗、首页“我的待办”和站内待办共用同一份邀请状态，办理后同步更新。
- 编辑/查看计划不再在每个标签重复展示 `.plan-project-info` 固定信息条；项目基本信息统一通过页面标题旁“详情”按钮打开抽屉查看，抽屉不展示附件内部路径。
- “报价管理”列表路由为 `/plan/material-draft`，新增、修改和查看统一进入固定隐藏页 `/plan/material-draft/editor`。新增 query 传 `mode=create&periodId&candidateName`，修改/查看传 `mode=edit|view&periodId&candidateId`，查看模式始终只读；列表可把候选明细导出为 `.xlsx`。同一分期允许创建多份名称不重复的报价候选清单。主表使用 `/project/materialCandidate/list|add|edit`，明细按主表返回的 `candidateId` 使用 `/project/materialCandidateItem/list|addBatch|editBatch`，不再借用 `/project/plan` 或 `/project/materialPlan`，因此不会覆盖编辑计划方案的用料数据。明细仅提交 `id（修改已有行时）、materialId、quantity、unitId、remark`，编码、名称和单位名称由后端生成快照。页面状态直接读取 `project_material_candidate_status` 字典并使用接口原始值：`0=草稿、1=已提交、2=已采用、3=已作废`；删除因后端无删除接口而提交状态 `3` 并从列表隐藏。新增主表只提交 `periodId+candidateName`，返回 ID 缺失时按分期和唯一名称反查；保存失败后再次进入同名草稿时复用已有主表，避免重复新增。新增、修改、锁定、解锁、删除继续受 `plan:quotation:add|edit|lock|unlock|delete` 权限控制，查看和导出沿用报价管理菜单访问权限。
- 编辑计划方案的“回款计划”按当前 `periodId` 调用合同详情接口，不从合同分页列表猜测记录；合同类型使用 `contract_type` 字典回显。销售负责人兼容合同姓名快照、嵌套用户对象与字段别名，仍缺失时按负责人 ID 查系统用户、项目分期详情、合同创建账号 `createBy` 及当前分期项目成员中的销售负责人（`memberRole=1`）补齐。合同详情返回合同文件时提供站内弹窗预览，不显示链接和下载；回款表只保留序号、回款项、比例和金额，不显示计划日期及操作列。
- 项目列表“计划审批”弹窗底部提供“查看详情/驳回/通过”，不显示“关闭”。查看详情跳转 `/project/plan?mode=view&periodId=...`，复用现有计划方案六个页签并强制只读，不单独创建审批详情抽屉；通过更新分期为 `IMPLEMENTING`，驳回填写原因后更新为 `PREPARING`。
- 项目详情右侧“项目动态”通过 `GET /project/dynamic/list` 倒序展示，每条同时显示 `actionContent`、`operatorName` 与 `operateTime`；动态区域限制为视口内高度并独立纵向滚动，窄屏下改为固定高度滚动。
- 人员配置的外协单位下拉调用 `/project/outsourcingUnit/list` 加载启用单位，选择后同步单位类型、联系人和联系电话；外协单位实体与表单统一使用 `unitType`，字典 `outsourcing_type` 为 `0=个人`、`1=企业`。
- “实施计划”的现场负责人仅从当前分期已接受邀请（`inviteStatus=1`）的项目成员中选择，按用户 ID 去重；每条工序的计划工时根据起止日期自动计算，计划验收日期必填并从项目分期详情回显。方案文件列垂直居中，位置信息的实施位置列加宽。
- 编辑计划方案的用料单位按物料详情 `unitList` 下拉选择并优先基础单位；工序表底部按“最晚计划完成日期 − 最早计划开始日期”× `8h` 显示总工时；实施位置地图弹窗确认后必须同步选点并主动关闭，不能停留在未确认状态。

### 5.3 合同与回款接口

| 用途               | 方法与路径                                      |
| ------------------ | ----------------------------------------------- |
| 合同列表           | `GET /project/contract/list`                    |
| 合同详情           | `GET /project/contract/queryById`               |
| 新增合同及回款计划 | `POST /project/contract/addWithPaymentRecords`  |
| 修改合同及回款计划 | `POST /project/contract/editWithPaymentRecords` |
| 合同编辑（已废弃） | `POST /project/contract/edit`                   |
| 回款计划列表       | `GET /project/paymentRecord/list`               |
| 回款计划批量新增   | `POST /project/paymentRecord/addBatch`          |
| 回款计划全量同步   | `POST /project/paymentRecord/editBatch`         |
| 回款计划批量删除   | `DELETE /project/paymentRecord/deleteBatch`     |
| 项目分期状态更新   | `POST /project/period/status`                   |

回款金额使用 `big.js` 按“合同金额 × 比例 ÷ 100”计算并保留两位；提交前要求回款比例合计精确等于 100%。合同信息回款计划的“回款周期”映射接口字段 `rollbackTime`，表示阶段任务完成后回款的周期，默认 7 天并允许修改为大于等于 0 的整数。合同详情以必填 `periodId` 一次返回合同、两个文件记录和回款计划；新增/修改均使用 multipart 组合接口，修改时 `contract.periodId` 必传，其他合同字段只传变化项，`records` 全量同步。
