## 2026-08-27 · 合同回款周期与计划销售负责人旧数据兜底

- 合同信息回款计划增加“回款周期”列，表头提示“阶段任务完成后回款的周期”；对应 Apifox 字段为 `rollbackTime`，新增款项默认 7 天，可修改为大于等于 0 的整数，只读详情显示“天”。新增和修改合同均随组合接口的每条 `records` 保存该字段，旧记录未返回时按 7 回显。
- 系统用户选项保留用户登录账号 `username`。计划方案“回款计划”在合同姓名快照和 `salesUserId` 均缺失或无法匹配时，继续按合同 `createBy` 匹配系统用户姓名，再回退当前分期销售角色成员和创建账号文本，兼容未保存销售负责人字段的历史合同。
- 本次未改变路由、菜单、权限码或字典；两份菜单配置文档已检查，无需修改。

## 2026-08-27 · 人员多角色邀请、回款合同预览与计划审批详情

- 编辑计划方案“人员配置”的项目角色改为多选；点击邀请弹窗“提交邀请”立即调用 `POST /project/member/addBatch`，按同一用户的多个角色生成邀请，不再等待“保存本页”。同一用户已存在的角色会跳过，避免重复邀请。
- 人员配置顶部“修改/保存本页”现在只控制并全量保存外协配置，调用 `POST /project/memberOutsource/editBatch`；参与人员邀请和删除均在对应操作时立即调用成员接口，与外协保存互不影响。
- “回款计划”继续按合同姓名快照和负责人 ID 回显销售负责人，并增加项目分期详情兜底；合同详情返回 `contractFile` 或合同文件 ID 时显示“预览”按钮，使用站内文件预览弹窗，不提供链接或下载。
- 项目列表“计划审批”弹窗底部移除“关闭”，改为“查看详情”；点击后关闭审批弹窗并跳转 `/project/plan?mode=view&periodId=...`，复用现有计划方案页面查看六个只读页签，不再单独创建审批详情抽屉。通过、驳回仍在审批弹窗内办理。
- 计划方案页识别 `mode=view` 并强制只读，避免审批查看入口被项目经理身份误判为可编辑。本次未新增路由或权限码；两份菜单配置文档已检查，`project:plan:audit` 的授权方式不变。

## 2026-08-27 · 合同修改彻底切换组合接口

- 前端删除 `/project/contract/edit` 的接口常量与修改调用；该接口已由 Apifox 标记停用并会返回失败，所有合同修改统一使用 multipart `POST /project/contract/editWithPaymentRecords`。
- 合同审批通过前写入项目经理时，改为提交 `contract.periodId + projectManagerUserId/projectManagerUserName`，并携带当前完整回款计划，避免组合修改接口全量同步时误删回款记录；不上传文件时由后端保留原合同文件和物料清单。
- 回款管理列表的“编辑”不再打开旧合同弹窗，统一进入 `/project/contract?mode=edit&periodId=...` 正式合同编辑页。菜单、路由层级和权限码未变化，两份菜单配置文档已检查无需修改。

## 2026-08-27 · 回款计划负责人回显与项目动态滚动展示

- 编辑计划方案“回款计划”的合同主信息增强销售负责人回显：优先读取 `salesUserName`，兼容历史字段别名及嵌套用户对象，姓名仍为空时依次按负责人 ID 从系统用户、当前分期项目成员中补齐；老数据未保存负责人 ID 时回退 `memberRole=1` 的销售负责人。
- 项目详情右侧动态增加操作人 `operatorName`，与动态内容、操作时间一起展示；动态列表限制高度并支持键盘聚焦后的独立纵向滚动，窄屏下使用 360px 最大高度。
- 接口仍使用 `GET /project/contract/queryById?periodId=...`、`GET /sys/user/list`、`GET /project/member/list?periodId=...` 和 `GET /project/dynamic/list?periodId=...`，未新增后端接口或菜单权限。

## 2026-08-27 · 菜单管理增加移动端路径配置

- “系统管理 → 菜单管理”列表和一级菜单新增/编辑表单增加 `miniAppPath`，用于维护 App/小程序授权一级菜单跳转路径。
- 移动端路径可留空；非空时必须为 `/pages/...` 格式，禁止域名、query 和 hash。按钮权限节点继续只维护 `perms`。
- 菜单新增、编辑接口沿用通用表单提交，不改变 PC 动态路由、组件路径和既有角色授权关系。
- 已同步结构总览、菜单配置指南和菜单配置傻瓜指南；正式菜单数据仍需管理员按角色实际范围填写并以真实账号回读验证。

## 2026-08-26 · 计划分组保存锁定与审批接口解耦

- 编辑计划方案移除“保存全部”；提交审批不再预保存整套计划，只调用 `POST /project/period/status`，传 `periodId` 和 `PENDING_APPROVAL`。
- 用料计划、实施计划已有记录默认只读，顶部按钮保存成功后变为“修改”，点击修改才重新解锁；空列表保持直接可编辑。用料继续调用 `/project/materialPlan/editBatch`，实施首次保存调用 `/project/process/addBatch`、已有记录调用 `/project/process/editBatch`。
- 人员配置顶部“保存本页”只处理参与人员；外协配置列表下新增独立“保存外协配置/修改”按钮，通过 `/project/memberOutsource/editBatch` 全量提交，成功后有记录的列表锁定只读。
- “保存全部”移除后，位置信息的已落库行删除改为确认后立即调用 `/project/location/editBatch` 全量同步；未保存的新行仍只在本地移除。

## 2026-08-26 · 报价详情、Excel 导出与用料清单导入

- 报价管理操作列新增“查看详情”和“导出”：查看详情复用 `/plan/material-draft/editor?mode=view&periodId&candidateId`，强制隐藏保存、锁定、解锁并以只读方式展示；导出读取候选明细并生成 `.xlsx` 物料清单。
- 编辑计划方案“用料计划”新增“导入清单”，支持上传 `.xlsx`，以及选择当前 `periodId` 下状态为 `1` 的已锁定报价单。Excel 按物料编码匹配库内物料；报价按候选明细的 `materialId` 转换，候选明细 `id` 不会带入计划用料。
- 导入只更新当前页面草稿：已有同物料覆盖数量、单位和备注，其他物料追加；点击“保存本页”后仍通过 `/project/materialPlan/editBatch` 提交。Apifox 当前没有报价导出、计划用料导入或报价转计划专用接口，因此未增加接口分支。

## 2026-08-26 · 修正候选清单状态字典与新增草稿恢复

- 报价管理状态字典由旧的 `quotation_status(DRAFT/LOCKED)` 改为候选清单专用 `project_material_candidate_status`，列表、搜索和编辑页直接使用接口状态 `0/1/2/3` 回显草稿、已提交、已采用、已作废。
- 新增草稿主表严格只提交 `periodId+candidateName`；兼容接口返回主表对象、直接返回 ID，以及响应未带 ID 后按分期和唯一名称反查三种结果，避免主表已保存却因前端未取到 `candidateId` 而误报失败。
- 新增前先检查同分期同名清单：已有草稿时复用该主表并通过明细全量同步继续保存，非草稿同名记录则要求更换名称，避免上一次部分成功后重试产生重复名称错误。
- 已同步 Mock 字典、结构总览、字典说明、项目业务说明和接口对照；本次未改变路由、菜单层级及权限码，两份菜单配置文档已检查无需修改。

## 2026-08-26 · 报价管理切换项目用料候选清单接口

- 报价管理不再使用 `/project/plan` 的 `CONTRACT_MATERIAL_DRAFT` 记录和 `/project/materialPlan` 分期用料，改为候选清单主表 `/project/materialCandidate/list|add|edit` 与明细 `/project/materialCandidateItem/list|addBatch|editBatch`，避免报价保存覆盖计划方案用料。
- 新增报价增加报价单名称，同一分期允许多份名称不重复的报价；首次保存先创建主表取得 `candidateId` 再新增明细，修改页通过 `periodId+candidateId` 精确回显。明细按接口提交 `materialId/quantity/unitId/remark`，单位下拉值改为物料单位 ID。
- 页面状态后来已按候选清单专用字典修正，详见上方“修正候选清单状态字典与新增草稿恢复”记录；草稿删除因后端未提供删除接口而置为作废状态 `3` 并从列表隐藏。
- 已同步结构总览、项目业务说明、接口对照和两份菜单配置文档；路由、菜单层级与权限码未改变，只补充隐藏页新增/修改 query 参数说明。

## 2026-08-26 · 报价管理新增跳转与隐藏菜单修复

- 报价新增/修改页由动态路径 `/plan/material-draft/:id` 改为固定隐藏路由 `/plan/material-draft/editor`，新增和修改分别通过 query 传 `mode=create|edit` 与必填 `periodId`，避免后台动态菜单无法正确匹配带参数子路由。
- 新增按钮选择项目分期后跳转到 `/plan/material-draft/editor?mode=create&periodId=...`；修改按钮使用同一路径并传 `mode=edit`。编辑页保留读取旧 `params.id` 的兼容逻辑，但正式菜单不再配置旧动态路径。
- 静态路由、Mock 菜单、结构总览和两份菜单配置文档已同步；正式后台需把“新增/修改报价”隐藏菜单路径改为 `/plan/material-draft/editor`，组件保持 `plan/material-draft/editor`。后台菜单表单没有“当前激活菜单”字段，前端动态路由转换会按组件自动补充 `/plan/material-draft`。

- 实施计划首次保存改调 `POST /project/process/addBatch`，已有工序或删除既有工序后调用 `POST /project/process/editBatch`；两者第一层均提交 `periodId`、`plannedAcceptanceDate`、`plannedAcceptanceRemark` 和 `records`。列表回显继续使用可用的 `GET /project/process/list`，未调用 Apifox 明确标注“未开发”的 `/project/process/detail`。
- 计划验收日期与备注从项目分期详情回显。已检查两份菜单配置文档，本次未改变路由、菜单和权限码，菜单文档无需修改。

## 2026-08-26 · 合同用料清单升级为报价管理

- “合同用料清单”模块更名为“报价管理”，保留原路由 `/plan/material-draft`；列表改为主项目名称、分期项目名称、分期项目 ID、最后更新人、状态，并只展示已建立的报价记录。
- 新增报价时先选择尚未建立报价的项目分期，再进入编辑页从库内选择物料并填写数量、单位；原“维护清单”操作改名为“修改”。
- 报价状态统一读取 `quotation_status` 字典：`DRAFT=草稿`、`LOCKED=已锁定`。草稿可修改、锁定、删除；锁定后不可修改或删除，只有具备 `plan:quotation:unlock` 权限的指定人员可解锁。
- 新增、修改、锁定、解锁、删除分别受 `plan:quotation:add|edit|lock|unlock|delete` 权限码控制，页面按钮和方法入口双重校验；Mock 菜单权限同步补齐。
- 当前后端没有独立报价聚合列表，前端通过 `/project/plan/list` 的 `planType=CONTRACT_MATERIAL_DRAFT` 记录与 `/project/project/projectPeriodList` 分期数据合并展示；报价物料继续按 `periodId` 调用 `/project/materialPlan/list|editBatch`。
- 已同步结构总览、菜单配置、字典配置、项目业务与接口对照文档。

## 2026-08-26 · 位置信息逐行保存与编辑锁定

- 位置后端只提供 `/project/location/editBatch` 全量同步接口。行保存以最近一次已落库数据为快照，仅替换当前行后提交，避免把其他未保存草稿或本地待删除行一并落库。
- 单条位置保存关闭请求层自动展示的“批量修改成功”，只保留页面的“该条位置信息已保存”提示；整套“保存全部”仍保留接口成功反馈。
- 已检查结构总览、项目模块业务说明、项目模块接口对照及两份菜单配置文档；本次不改变路由、菜单、权限码和接口路径，菜单文档无需修改。

## 2026-08-25 · 编辑计划方案展示与实施计划调整

## 2026-08-25 · 计划页方案文件独立保存

- 编辑/查看计划页签“方案文件管理”改名为“方案文件”；数据源由 `/project/file/list` 改为 `/project/plan/list` 并排除 `CONTRACT_MATERIAL_DRAFT`，不再混入合同附件及合同用料草稿。
