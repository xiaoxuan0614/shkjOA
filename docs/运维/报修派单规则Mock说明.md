# 报修派单规则（Mock）

## 分配规则

1. 先按报修客户查有效客户制规则：客户及其全部现有、新增项目固定分配给指定人员，不受休息或值班表影响。
2. 其他所有客户的全部项目进入值班制，不需要逐个选择客户；由值班表与自动派单规则决定接收人，休息人员跳过。
3. 值班制缺预计执行时间或无可接人员进入待调度，不随意指定客户制人员兜底。
4. 客户制工单不因负责人休息自动转派；需要更换时由主管主动转单。规则变化只影响后续派单，不回改已分配工单。
5. 同一客户只能有一个有效负责人。启用与保存都检查客户重复、人员同类型规则重复；停用客户制后，该客户后续报修回到值班范围。
6. 本Mock暂允许一人分别配置客户制和值班制，两条规则独立管理；是否限制为一种方式，正式接入前再确认。

## 页面

入口：PC维修记录 → 报修派单规则（Mock）。筛选人员、方式、客户制客户、状态；支持新增、编辑、启用/停用及按客户预览归属。客户制显示客户多选，值班制自动覆盖其余客户。当前可见维修列表用户可预览，未新增正式权限或后台菜单。

数据为明确标记的示例，保留于当前页面会话，关闭抽屉再打开保留，刷新清空；不调用业务接口，不影响已接入的休息、轮值池或真实派单。

## 后续正式接入需要确认

- 规则增改查及启停权限；有效客户唯一性必须由后端并发校验。
- 人员/客户候选及数据权限；人员停用时不能继续派单。
- 后端统一实现客户优先和值班兜底，工单保留命中规则、派单方式与负责人快照。
- 休息预览排除客户制工单；原固定四人池如何迁移为值班配置范围需明确，不能由此Mock静默更换。
- 规则修改只对后续派单生效；已待调度工单如何重试需明确。

本次只交付PC配置Mock，移动端真实业务、后端接口及角色授权未修改。
