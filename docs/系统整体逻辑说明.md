# 首汇科技管理平台（OA）— 系统整体逻辑说明（小程序对接版）

> 版本：2026-08-16
> 用途：本人开发小程序前端时的业务逻辑参考。**小程序与 PC 端共用同一套后端接口（一套后端）**，小程序只做前端展示与录入。
> PC 端已实现：项目 / 计划方案 / 实施 / 回款 / 物料 / 库存 / 出入库 / 采购 / 客户 / 供应商。PC 端代码（`src/views/<模块>/*.api.ts`）就是接口调用范本，小程序端按本说明对齐业务语义、复用同一契约。

---

## 一、系统定位

面向**首汇科技（工程公司）**的项目全生命周期管理 OA 平台，覆盖从**立项 → 计划 → 实施 → 验收 → 质保 → 完结**的完整项目周期，并配套**物料库存、出入库审批、采购、合同回款、人员车辆**等支撑业务。

后端为 JeecgBoot 框架，PC 前端为 Vue3 + Ant Design Vue。小程序是同一后端的**第二个前端客户端**，核心使用场景：**项目进度查看、实施打卡与日志提交（拍照）、领料/还料申请、出入库审批、盘点、回款登记**。

## 二、核心数据模型（关键关系）

### 2.1 项目 — 两级结构（最重要）

```
主项目 project（parentId=0）
  └─ 分期 period（parentId=主项目 id）
        ├─ 计划方案  plan
        ├─ 项目成员  member
        ├─ 实施位置  location
        ├─ 项目工序  process（挂在分期下）
        ├─ 实施记录  implementLog（挂在工序下）
        ├─ 参与人员  implementLogPerson（挂在实施记录下）
        ├─ 施工打卡  attendance（签到/签退/位置/照片）
        ├─ 工期延期  delay + delayApproval（延期申请 + 审批）
        ├─ 内部验收  internalAcceptance
        ├─ 客户验收  acceptance
        ├─ 项目文件  file
        ├─ 用料计划  materialPlan
        ├─ 项目动态  dynamic（时间线）
        └─ 合同      contract + contractItem（回款）
```

**关键约定**：
- 主项目名称冗余存于分期（`projectName`）；`periodNo` 为分期编号。
- **所有子表（计划/成员/位置/实施/验收/文件/用料/动态）都挂在 `periodId` 上**，小程序端查子表一律以 `periodId` 为入参。
- 主项目可包含多个分期；后端只允许删除「期」，不允许删主项目。

### 2.2 物料库存

```
物料 stock_material（含单位子表：基准单位 + 副单位）
  ├─ 出入库台账 stock_io_record（每次出入库留痕）
  ├─ 出入库申请 stock_apply → 申请明细 stock_apply_item → 审批记录
  ├─ 采购订单 purchase_order → 采购明细 purchase_order_item
  └─ 供应商 supplier / 客户 customer
```

- 物料**数量以基准单位为准**；副单位按换算系数折算。
- 库存总额 = 所有批次剩余之和（批次功能规划中，见 §5.6）。

## 四、项目生命周期状态机（核心主线）

### 4.1 主流程

```
未开始 ──开始实施──> 实施中 ──调试完成──> 调试完成 ──完成实施──> 实施完成
实施完成 ──进入内部验收──> 内部验收中  ──内部验收完成──> 待客户验收
实施完成 ──进入客户验收──> 客户验收中  ──客户验收完成──> 待内部验收/待进入质保
   内部验收完成 + 客户验收完成 ──进入质保──> 质保中 ──项目完结──> 完结
任意状态 ──项目关闭──> 关闭（例外终态）
```

**规则**：
1. 状态流转由**独立接口**驱动（`/project/period/{start|debugComplete|implementComplete|internalAccept|internalAcceptComplete|accept|acceptComplete|warranty|complete|close}`），**不能跳步、不能回退**，由后端校验。
2. **验收阶段 = 内部验收 + 客户验收并行**：谁先谁后无所谓，分别记录、分别上传验收报告；**客户验收完成后即可「进入质保」**。
3. 每步「推进」按钮在当前状态才显示。

### 4.2 验收（核心概念）

| 维度 | 内部验收 `internalAcceptance` | 客户验收 `acceptance` |
| --- | --- | --- |
| 负责人 | `acceptLeaderId/acceptLeaderName` | 同左 + `acceptUnitLeader/acceptUnitPhone`（甲方联系人） |
| 验收报告 | `reportFileId`（必传） | `completionReportFileId`（竣工报告，必传）、`acceptanceFormFileId`（验收单） |
| 结果/备注 | `result`、`remark` | `result`、`remark` |

## 五、模块业务逻辑

### 5.1 项目管理

- **列表**：主项目 + 分期平铺展示；搜索：项目名称/分期名称/客户/类型/状态；状态推进按钮按当前状态显示下一步操作。
- **新增**：选择已有主项目 → 新增分期；不选主项目 → 本次新建主项目（含首期）。创建后主项目名/项目名**不可改**。
- **项目详情（8 tab）**：基本信息 / 计划方案 / 项目成员 / 实施位置 / 实施记录 / 验收记录 / 项目文件 / 用料清单，右侧项目动态时间线，头部状态推进按钮。

### 5.2 计划方案

- 项目下计划方案（`plan`）：方案名称/类型/起止时间/总工时/文档/备注。
- PC 端 5 tab 结构（项目信息 / 实施计划 / 用料计划 / 位置信息 / 回款计划）。用料计划 = 申请清单（物料类别/名称/品牌/型号/库存/申请数量/单位/快递单号），可添加申请。

### 5.3 实施管理

- **工序 `process`**：工序名称/负责人/计划起止/计划工时/实际起止/状态（未开始·进行中·已延期·已完成）/排序。
- **实施记录 `implementLog`**：实施日期/提交人/工时/位置/内容/照片/车辆/里程/签到签退时间/**外协**（外协单位/人数/工时）。
- **参与人员 `implementLogPerson`**：实施记录下的人员签到表（签到/签退时间/工作内容/评分）。
- **工期延期 `delay`**：工序延期申请（原因/原截止/预计截止/延期天数）→ 审批（通过/驳回），通过后工序展示延期原因 + 预计延期完成时间。
- **施工打卡 `attendance`**：按工序打卡，签到/签退/工时/工作内容/位置（经纬度 + 名称）/照片。

> 小程序重点：实施人员在外拍照打卡、提交实施日志、申请工期延期，是高价值移动场景。

### 5.4 回款管理（合同）

- **合同 `contract`**：合同类型（贸易/维保/项目/维修）/甲方/签订日期/关联项目/合同金额/**已回款 `receivedAmount`**/未回款（= 合同金额 − 已回款，前端计算）。
- **合同明细 `contractItem`**：明细项（名称/规格/数量/单位/单价/金额）——PC 端当前兼任「回款计划」。
- 「添加回款」：在合同下登记一笔回款（回款类型/金额/日期/详情）。

> ⚠️ 回款计划后端暂无独立实体，回款流水表结构待后端补充；小程序端如做回款录入需与后端确认。

### 5.5 物料与库存

#### 5.5.1 物料基本维护
- 物料 CRUD + **单位子表**：第一行=基准单位（换算系数 1，固定不可删），副单位填换算系数；单位下拉走数据字典 `inv_unit`。
- **物料编码后端生成**（新增时隐藏，保存后自动带出）。
- 基准单价 / 初始库存未填默认 0；支持导入（下载模板在导入弹窗内）+ 导出。

#### 5.5.2 库存管理 + 盘存
- 所有在库物料数量总览（按基准单位）。
- 行操作：**手动出入库**（生成台账）、**盘存**（按实际盘点数量留痕，`POST /stock/ioRecord/takeStock`）。
- 盘存记录页：固定按 `sourceType=stocktake` 过滤台账，差异=盘点后−盘点前（正盘盈绿/负盘亏红）。

#### 5.5.3 出入库申请（领料 / 还料 / 采购）— 核心审批流程

**申请入口**：领料申请（出库 OUT）、还料申请（入库 IN）、物料申请（兼容旧入口）。
- 选择**分期项目**（服务端模糊搜索 `/project/period/searchByName`，打开即预载首页 10 条），自动带出主项目名称。
- **还料人 = 当前登录用户**（自动填充）。
- 明细：物料（看库存）/数量/单位/备注。

**整单审批流程（状态机）**：

```
PENDING 待审批
  ├─ 审批通过 → APPROVED 已通过 → 执行出库/入库（整单或批量）
  ├─ 部分通过 → PARTIAL_APPROVED 部分通过 → 执行已通过明细 / 继续审批剩余
  ├─ 审批驳回 → REJECTED 已驳回 → 申请人「修改」后重新提交（驳回必填原因）
  └─ 申请人撤回 → WITHDRAWN 已撤回 → 可修改重提 / 可删除
```

**关键规则**：
1. **只有「待审批 PENDING」显示「审批」按钮**，审批为**整单审批**（明细只读展示，结果单选 整单通过 / 整单驳回，驳回必填审批备注）。
2. 审批通过后，`APPROVED/PARTIAL_APPROVED` 显示「出库/入库」按钮（`executeStatus` 待执行/部分执行时）。
3. **执行出入库统一调 `POST /stock/apply/execute`**（`{applyId, itemIds?, items:[{itemId, executeQty}]}`），方向由申请自身决定；**执行人由后端从登录 token 取**，明细记录 `executeUserId/executeUserName/executeTime`。
4. 申请人动作：待审批/已撤回/已驳回 → 可「修改」重提；待审批可「撤回」；删除仅限 待审批/已撤回（**已驳回不可删**）。
5. **出入库台账 `stock_io_record`**：每次出入库留痕（类型/来源/来源单号/数量/单价/金额/变动前后库存/备注），来源走字典 `stock_io_source_type`（apply=申请 / manual=手动 / stocktake=盘存 / purchase=采购入库）。

#### 5.5.4 采购入库（独立采购订单模块）

**状态机**（状态值 = **数字码**）：

```
1 待采购 ──确认采购──> 2 采购中 ──采购完成──> 3 已到货 ──开始入库──> 4 入库中
4 入库中 ──逐物料实际入库 + 入库完成──> 5 已完成
1/2/3 ──关闭（必填原因）──> 0 已关闭
```

- 采购订单：供应商 / 分期项目 / 下单日期 / 明细（物料、数量、单价）。
- 状态切换走 `POST /project/purchaseOrder/status`（`{orderId, status}`）；**入库**走 `POST /project/purchaseOrder/inbound`（`{orderId, items:[{itemId, inboundQty}]}`），库存/台账按实际入库数量计算；差异必填说明，逐条写台账留痕。
- ⚠️ 后端限制：采购单**不允许删除**（前端无删除按钮）。

#### 5.5.5 批次 / 库位 / SN（规划中，未上线）

后续规划：**仓库→库区→层**三级位置维护；**批次 = 入库单 × 物料 × 单价**（一个批次一个价）；SN 扫码/系统生成、打标签；出库 **FIFO（先入先出）** 推荐批次、可换批留痕。详见 `docs/后端开发需求-批次-库位-SN.md`。**小程序端暂不做**，但设计时预留「批次/SN」扩展位。

### 5.6 客户 / 供应商

- **客户**：名称/联系人/电话/三个负责人（销售/维保/客户经理，用户选择器）/开票信息（抬头/税号/银行/账号/地址/电话）；**客户编号后端生成**。
- **供应商**：编号后端生成 / 名称 / 对接人（用户选择器）/联系人/电话/地址/银行账户；采购入库页供应商下拉同源。

### 5.7 车辆管理（后端未实现）

PC 端页面已做（车牌/负责人/状态/使用·加油·保养记录 3 tab），**后端接口未开发**。小程序端如涉及车辆排班/使用登记需后端先补接口。

## 六、通用业务规则（全系统统一，小程序务必遵守）

1. **状态/枚举/下拉标签一律走后端数据字典 `sys_dict`**，前端不写死。字典编码见 §8。
2. **编号一律后端生成**（物料编码、客户编号、供应商编号、申请单号、采购单号、盘存单号等）：新增时前端不填编号，保存后后端生成带出。
3. **当前操作人身份**：登录后存用户信息；凡审批/操作类提交，必须传当前操作人 id（审批人 `approvalUserId`）；执行人由后端从 token 取。
4. **单位**统一走 `inv_unit` 字典，物料单位名即字典文本。
5. **主项目名称** = `projectName`（主项目名），分期名 `periodName` 仅作下拉 label。
6. **驳回必填原因**（审批备注），前端拦截未填不可提交。
7. 所有页面字段/接口以 apifox 接口文档为准；文档没有的接口视为后端未实现。

## 七、接口规范（小程序接入必需）

### 7.1 基本信息

| 项 | 值 |
| --- | --- |
| 后端地址（示例，正式按环境） | `http://10.10.10.11:8080/shouhuiApi`（前缀 `/shouhuiApi`） |
| 登录接口 | `POST /sys/login`（账号密码，密码 AES 加密；密钥见 `src/utils/cipher.ts`） |
| 响应格式 | `{ code, result, message, success }`，**`code === 200` 为成功** |
| 分页返回 | `{ records, total, size, current, pages }`（MyBatis-Plus 风格，列表取 `records`） |
| 文件上传 | `POST /sys/common/upload`（返回文件路径/ID） |
| 鉴权 | 登录后携带 token（header `X-Access-Token`），后端权限模式 BACK：菜单/路由/按钮权限码由后端返回 |

> **请求签名（重要，小程序必须复刻）**：PC 端所有请求带 3 个 header——
> - `X-TIMESTAMP`：`new Date().getTime()`
> - `X-Sign`：签名
> - 签名算法（`src/utils/encryption/signMd5Utils.js`）：
>   1. 合并 ① URL 上的 query 参数 ② GET 的 params ③ POST 的 body（若有），数字/布尔转字符串；
>   2. 按键名**升序排序**，剔除 `_t`；
>   3. `md5(JSON.stringify(排序后对象) + 密钥)` 后 **转大写**。
>   4. 密钥 `signatureSecret = 'dd05f1c54d63749eda95f9fa6d49v442a'`（前后端一致）。
>
> 小程序端在 `utils/request.js` 里**照抄这套算法**（WeChat 无 crypto 需引入 md5 库），否则所有请求会被后端签名校验拒绝。登录密码为 AES 加密（`AES_KEY=1234567890adbcde`、`AES_IV=1234567890hjlkew`，见 `src/utils/cipher.ts`）。

## 九、小程序前端开发要点（本人开发用）

1. **接口契约直接抄 PC 端**：字段名、状态码、分页结构都以 PC 端 `src/views/<模块>/*.api.ts` 为准（配合 `docs/接口对照文档.md`、`docs/项目/项目模块接口对照.md`），不要自造字段。
2. **请求层**：先搭好 `utils/request.js`（baseURL=`/shouhuiApi` + MD5 签名 + token 携带 + `{code,result,message,success}` 统一拦截，`code!==200` 弹错），后续所有页面只写业务请求。
3. **移动端一期高频场景**：
   - 项目：列表 / 详情（基本信息 + 状态 + 动态时间线）/ 状态推进按钮。
   - 实施：工序列表、实施日志提交（含**拍照**）、施工打卡（**经纬度定位**）、工期延期申请。
   - 物料：领料 / 还料申请（选项目→选物料→填数量→提交）、出入库**审批**、库存查看、**盘存**。
4. **图片上传**：拍照/相册 → `POST /sys/common/upload`，返回路径存字段（验收报告、实施照片、打卡照片、项目文件）。
5. **定位**：施工打卡 / 实施位置需要经纬度 + 位置名称。
6. **状态字段不要硬编码**：所有状态/下拉从字典接口拉取（PC 端读取方式见 `material.util.ts` 的 `loadDictMap` / `JDictSelectTag`），小程序端封装一个 `dict.js` 拉字典 + 缓存即可。
7. **编号字段**：所有新增表单的编号留空、只读展示，保存后由后端返回。
8. 小程序登录方式（账号密码 / 微信授权换 token）需与后端确认；PC 端登录是 `POST /sys/login`（密码 AES 加密）。
