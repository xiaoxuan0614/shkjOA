## 一、模块定位

项目模块覆盖：**项目管理**（主项目+分期）、**计划方案**、**实施管理**（工序/实施记录/参与人员/施工打卡/工期延期）、**项目成员/实施位置/项目文件/项目动态/用料计划**、**验收管理**（内部验收 + 外部验收并行）、**返工申请/审批/执行**、**合同管理/回款**。

计划方案、合同、项目用料申请、项目延期以及出入库申请/明细的审批状态统一使用 `approval_status`：`-1=待提交`、`0=驳回`、`1=审核通过`、`2=待审批`、`3=已撤回`，由 `src/utils/approvalStatus.ts` 负责页面判断和缓存失败兜底。项目生命周期、工序状态、出入库执行状态和 `AGREE/REJECT` 审批动作参数不属于该字段。

后端以「**项目(project) — 分期(period)**」两级结构组织：主项目下挂多个分期，**所有子表（计划/成员/位置/实施/验收/文件/用料/动态）都挂在分期(periodId)上**。

新增/编辑项目的地址使用按需选点弹窗：默认展示地址，点击「选择位置」或在输入框按回车后加载地图；确定回填地址和经纬度，取消不更改表单，关闭后卸载地图。

## 三、项目生命周期（状态流转）

```
未开始 ──合同提交──> 合同待审批（2） ──审批通过（1）+指定项目经理──> 筹备中 ──计划提交审批──> 待审批
待审批 ──审批通过──> 实施中 ──全部工序完成──> 验收中（自动生成验收记录）
验收中：运维部门经理办理内部验收，项目经理办理外部验收；两项都通过后端自动进入质保
任一验收不通过 ──返工申请/审批──> 返工中 ──统一返工工序完成──> 验收中
质保中 ──质保结束──> 完结
任意允许关闭的状态 ──关闭审批──> 关闭（例外终态）
```

- 合同提交后，项目列表的同一“合同信息”入口进入只读详情：审批权限人可通过/驳回，原提交人可撤回；驳回详情展示原因，驳回或撤回后由原提交人修改并重新提交；通过时指定项目经理，项目进入筹备中，列表入口随即隐藏，后续从项目详情查看。
- 合同待审批只读详情将合同类型和回款项编码转换为字典名称；销售负责人优先显示合同姓名快照，快照为空时按负责人 ID 从系统用户补齐，并兼容历史姓名字段、嵌套用户对象和创建账号；项目经理姓名同样支持按用户 ID 补齐。已上传的合同附件与合同货物清单可在站内弹窗查看文件内容。
- 合同信息页将 `contractAmount` 以“项目金额”展示，计划交付日期、项目金额和质保期均为必填；质保期使用月数并只允许填写大于等于 0 的整数。历史待审批合同缺少计划交付日期时不能直接通过，应驳回补充后重新提交。
- 已有合同修改并重新提交时调用 `editWithPaymentRecords`，项目分期 ID 必传；合同字段仅提交变化项，回款计划全量同步，修改成功后转为待审批。合同审批通过前写入项目经理也使用该组合接口并携带当前完整回款计划，再调用合同状态接口审批通过；前端不再调用已停用的 `/project/contract/edit`。回款管理列表的“编辑”统一进入正式合同编辑页。
- 合同回款计划增加“回款周期”，表头提示其含义为“阶段任务完成后回款的周期”；回款项、比例和周期均为必填，新行不预填比例，回款周期默认 7 天。比例和周期使用数字输入；其他行已选择的回款项不会再出现在当前下拉中，全部节点使用后禁用“添加款项”，提交前再次校验重复；比例必须大于 0、不超过 100% 且合计为 100%，`rollbackTime` 必须是大于等于 0 的整数并随合同组合接口保存，旧记录没有该字段时仍按 7 天显示。
- 仅项目处于筹备中（`PREPARING`）时，项目列表显示“编辑计划方案”；提交计划审批后立即隐藏，审批通过进入实施中后也不再显示。
- 计划审批通过后至完成实施之前（`IMPLEMENTING/DEBUGGING`，兼容历史 `DEBUG_COMPLETED`），仅项目列表显示受 `project:implement` 控制的“实施完成”，项目详情不再提供该按钮。列表点击后打开“确认工序实施进度”抽屉并通过 `GET /project/process/detail?periodId=...` 展示全部工序；未开始、进行中的工序均可单选完成，已完成工序禁选但可查看。确认前二次提示，提交 `POST /project/process/status` 的 `{ processId, status: 'COMPLETED' }`；最后一道工序完成时项目状态由后端自动推进，前端不再直接提交调试完成或实施完成状态。
- 工序抽屉展示工序名称、状态、计划周期（计划结束日减开始日加一）、实际开始时间、已进行自然日、现场负责人；“详情”进入当前项目分期的实施日志页并自动展开所选工序。接口 `processName` 按 `work_type` 转换名称，抽屉选择提示、二次确认和工序日志分组使用同一中文名称，未命中才回退原值。工序状态统一使用 `project_process_status`：`NOT_STARTED/IN_PROGRESS/COMPLETED`。
- PC 新增项目先选择“新建主项目”或“已有主项目下新增分期”；分期模式先锁定所属主项目，再填写分期信息，提交继续以 `parentProjectId` 区分两种模式。
- 项目列表增加“到货状态”，按 `arrivalStatus=0/1` 显示未到货/已到货。仅实施中/调试中（`IMPLEMENTING/DEBUGGING`，兼容历史 `DEBUG_COMPLETED`）且未到货的项目可由拥有 `project:arrival:confirm` 权限的人员确认到货；实施完成及后续状态隐藏。PC 列表和 App 项目详情共用规则，弹窗展示到货款回款周期、预计回款日期和合同货物清单预览，确认只更新分期到货状态，计划回款日期由后端生成。
- 项目列表的对接人姓名优先使用列表姓名快照或用户 ID 反查；仍缺失时按当前分期补查项目详情，避免列表留空。
- 新增项目、已有主项目新增分期及编辑项目的附件改为随项目保存接口组合提交：multipart 的 `data` 为业务 JSON 字符串，`attachment` 为单个可选文件，不预调用公共上传接口，也不在 JSON 中传 `attachmentFileId`。编辑不选新附件时保留旧文件，选择后由后端替换；允许 Word、PPT、Excel、PDF 和图片，页面移除表单上方重复的“基本信息”标题。
- “编辑/查看计划方案”页面标题旁显示“详情”，在当前计划页打开项目基本信息抽屉；抽屉展示主项目、分期与对接、实施信息。
- 计划页标签由“方案文件管理”改为“方案文件”，按项目分期 ID 读取 `/project/plan/list`，仅展示计划方案记录，不显示合同附件或 `CONTRACT_MATERIAL_DRAFT` 合同用料草稿。序号按当前表格行位置从 1 连续显示，新增、删除和重载不会显示内部行键。顶部“保存本页”统一保存本页方案：新增记录及附件通过 multipart `/project/plan/addBatch` 提交，已有修改调用 `/project/plan/edit`，移除记录在最后调用 `/project/plan/deleteBatch`。每个新增记录用 `attachmentIndex` 对应附件数组；先校验全部必填项，全部成功并回查后整页锁定，点击“修改”解锁。不同请求并非整页事务，中途失败停止后续操作并保留未完成草稿。

## 五、验收阶段（核心概念）

内部验收与外部验收**同时进行、不分先后**，均为同一轮验收的一部分，统一记录在 `project_acceptance`，分别上传验收报告：

| 维度      | 内部验收 `acceptType=INTERNAL`  | 外部验收 `acceptType=CUSTOMER`                                        |
| --------- | -------------------------------- | --------------------------------------------------------------------- |
| 办理责任  | 运维部门经理                     | 本项目经理                                                            |
| 负责人    | `acceptLeaderId/acceptLeaderName` | `acceptLeaderId/acceptLeaderName`、`acceptUnitLeader/acceptUnitPhone` |
| 验收报告  | `completionReportFileId`（必传）  | `completionReportFileId`（必传）、`acceptanceFormFileId`（验收单）    |
